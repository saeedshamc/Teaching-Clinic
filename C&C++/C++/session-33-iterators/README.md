# جلسهٔ ۳۳ — تکرارگرها (Iterators)

> تکرارگر یک اشاره‌گر نیست، ولی مثل اشاره‌گر رفتار می‌کند؛ و همین «مثل» بودن، پل بین کانتینر و الگوریتم است.

---

## اهداف این جلسه

1. `begin`/`end` و بازهٔ نیمه‌باز را بفهمید.
2. با `*`، `++`، `!=`، `next`/`prev`/`advance`/`distance` کار کنید.
3. `const_iterator` و `cbegin`/`cend` را بشناسید.
4. پیمایش معکوس با `rbegin`/`rend` و نقش `base()` را یاد بگیرید.
5. بدانید کدام عملیات تکرارگر را نامعتبر می‌کند.

---

## ۱. تکرارگر چیست

تکرارگر یک شیء است که «به یک عنصر اشاره می‌کند» و می‌داند چطور به بعدی برود. الگوریتم‌ها فقط از این رابط استفاده می‌کنند، پس روی `vector`، `list`، `map` و حتی آرایهٔ خام کار می‌کنند.

```cpp
std::vector<int> values{10, 20, 30, 40};
for (auto it = values.begin(); it != values.end(); ++it) {
    std::cout << *it;   // 10 20 30 40
}
```

بازهٔ `[begin, end)` **نیمه‌باز** است: `begin` به اولین عنصر اشاره می‌کند، `end` به «یکی بعد از آخر». چرا؟ چون حلقهٔ `it != end` بدون استثنا برای مجموعهٔ خالی هم کار می‌کند.

```cpp
std::vector<int> empty;
std::cout << std::distance(empty.begin(), empty.end());   // 0
```

---

## ۲. عملیات پایه

| عملیات | معنی |
|---|---|
| `*it` | عنصر جاری |
| `++it` / `it++` | رفتن به بعدی |
| `--it` | رفتن به قبلی (فقط تکرارگر دوسویه) |
| `it == other` / `it != other` | مقایسه |
| `it->member` | دسترسی به عضو (برای `map` و اشیاء) |
| `it + n` | پرش (فقط تکرارگر تصادفی) |

### `next`، `prev`، `advance`، `distance`

```cpp
std::next(it, 2);      // تکرارگر جدید، it تغییر نمی‌کند
std::prev(it);
std::advance(it, 3);   // it را جلو می‌برد (بدون مقدار بازگشتی)
std::distance(a, b);   // تعداد گام از a تا b
```

`std::advance` روی `vector` و `deque` در زمان ثابت انجام می‌شود، ولی روی `list` گام‌به‌گام است: `O(n)`. همین تفاوت، دلیل وجود «دسته‌بندی تکرارگر» است.

خروجی واقعی `01_iterator_basics.cpp`:

```
--- پیمایش دستی با تکرارگر ---
  *it = 10
  *it = 20
  *it = 30
  *it = 40
--- end یک عنصر بعد از آخر است ---
  distance = 4، size = 4
--- next و prev ---
  *begin = 10
  *next(begin, 2) = 30
  *prev = 20
--- تغییر مقدار از طریق تکرارگر ---
  values[2] = 99
--- const_iterator: فقط خواندن ---
  10  20  99  40
--- پیمایش معکوس ---
  40  99  20  10
--- تکرارگر روی string ---
  S
  T
  L
```

## ۳. `const_iterator`

اگر تکرارگر از شیء `const` گرفته شود یا از `cbegin()`/`cend()` استفاده کنید، نوع آن `const_iterator` است و نمی‌توانید `*it` را بنویسید:

```cpp
for (std::vector<int>::const_iterator cit = values.cbegin(); cit != values.cend(); ++cit) {
    // *cit = 0;   ❌ خطای کامپایل — و همین خوب است
}
```

در توابعی که کانتینر را فقط می‌خوانند، `const&` بگیرید تا خودکار `const_iterator` به دست آید:

```cpp
void print(const std::vector<int>& data) {
    for (const auto& value : data) { ... }
}
```

## ۴. پیمایش معکوس

```cpp
for (auto rit = values.rbegin(); rit != values.rend(); ++rit) {
    std::cout << *rit;
}
```

`rbegin()` به آخرین عنصر اشاره می‌کند و `++` آن به عقب می‌رود. اگر لازم شد تکرارگر معکوس را به رو به جلو تبدیل کنید:

```cpp
auto rit = values.rbegin();
auto forward = rit.base();   // forward به عنصری بعد از *rit اشاره می‌کند
```

این «یکی جلوتر» بودن، منبع خطای کلاسیک است:

```cpp
// اندیس واقعی عنصری که *rit به آن اشاره می‌کند:
const int index = static_cast<int>(std::distance(values.begin(), rit.base())) - 1;
```

در تمرین همین جلسه دقیقاً به همین نیاز داریم.

## ۵. دسته‌بندی تکرارگرها

| دسته | عملیات مجاز | کانتینرها |
|---|---|---|
| Input/Output | `*`، `++`، یک‌بار مصرف | جریان‌ها (`istream_iterator`) |
| Forward | `*`، `++`، چندبار پیمایش | `forward_list`، `unordered_*` |
| Bidirectional | + `--` | `list`، `set`، `map` |
| Random access | + `it + n`، `it[n]`، `<`، `distance` در `O(1)` | `vector`، `deque`، `array` |

اینکه یک الگوریتم چه تکرارگری می‌خواهد، در مستنداتش نوشته شده: `std::sort` تکرارگر تصادفی می‌خواهد (پس روی `list` کار نمی‌کند)، `std::find` فقط ورودی لازم دارد.

خروجی واقعی `02_iterator_categories.cpp`:

```
--- تابعی که فقط ++ می‌خواهد ---
  vector: 5
  list: 5
  forward_list: 5
--- تابعی که پرش (it += 2) می‌خواهد ---
  1
  3
  5
  (روی list کامپایل نمی‌شود: تکرارگر آن تصادفی نیست)
--- دسته‌ها با iterator_traits ---
  vector: random_access
  list: bidirectional
  forward_list: forward
  map: bidirectional
--- عقب‌گرد فقط روی دوسویه ---
  *--list.end() = 5
  بعد از advance(3) و --: 3
--- map: تکرارگر به pair<const Key, Value> ---
  Ali = 18
  Sara = 20
```

نکته: تکرارگر `map` به `pair<const Key, Value>` اشاره می‌کند؛ کلید `const` است چون تغییرش ساختار درخت را می‌شکند.

## ۶. نامعتبر شدن تکرارگر

| عملیات | اثر |
|---|---|
| `push_back` با رشد `vector` | همهٔ تکرارگرها باطل |
| `push_back` بدون رشد | معتبر می‌مانند |
| `insert`/`erase` در `vector` | از نقطهٔ تغییر به بعد |
| `erase` در `list`/`map`/`set` | فقط همان عنصر |
| `clear` | همه باطل |

خروجی واقعی `03_invalidation.cpp`:

```
--- vector: رشد حافظه را عوض می‌کند ---
  آدرس حافظه عوض شد (size = 4، capacity = 6)
--- با reserve از قبل ---
  آدرس حافظه ثابت ماند (capacity = 4)
--- list: درج در جای دیگر تکرارگر را باطل نمی‌کند ---
  مقدار قبلی: 20، مقدار فعلی از همان تکرارگر: 20
--- erase در حلقه: تکرارگر بعدی را از erase بگیرید ---
  بعد از حذف زوج‌ها: 1 3 5 
قاعده: هر عملیاتی که capacity را عوض کند، همهٔ تکرارگرهای vector را باطل می‌کند.
```

برنامه آدرس‌ها را چاپ نمی‌کند، فقط **مقایسه** می‌کند؛ چون آدرس‌ها بین اجراها تغییر می‌کنند. الگوی `before == after` یک تست قطعی است.

## ۸. اشتباهات رایج

1. **`it <= end`** → برای تکرارگرهای غیرتصادفی حتی کامپایل نمی‌شود، و در تصادفی هم `end` قابل‌خواندن نیست.
2. **`*end` یا `++` روی `end`** → رفتار تعریف‌نشده.
3. **استفاده از تکرارگر بعد از `erase`** → مگر مقدار بازگشتی `erase` را بگیرید.
4. **نگه داشتن `end()` قبل از `push_back`** → اگر رشد رخ دهد، `end` قدیمی باطل است.
5. **`std::distance` در حلقه روی `list`** → هر بار `O(n)`؛ یک بار حساب کنید.
6. **`rit.base()` به‌عنوان همان عنصر** → یک خانه جلوتر است.
7. **پیمایش `unordered_*` با فرض ترتیب** → ترتیب وجود ندارد.
8. **`it += 2` روی `list`** → خطای کامپایل؛ `std::advance` یا `std::next` لازم است.

## ۹. بهترین شیوه‌ها

- در حلقه‌های ساده از range-based `for` استفاده کنید؛ تکرارگر صریح فقط وقتی لازم است که به موقعیت نیاز دارید.
- برای خواندن، `const auto&` و برای شمارش، `const_iterator`.
- `erase` در حلقه: `it = container.erase(it)`.
- اگر مکرراً `end()` را مقایسه می‌کنید و کانتینر تغییر نمی‌کند، مشکلی نیست؛ ولی پس از تغییر، دوباره بگیرید.
- تکرارگر را با نوع دقیق (`std::vector<int>::iterator`) فقط وقتی بنویسید که لازم است؛ `auto` کوتاه‌تر و امن‌تر است.

---

## ۱۰. خلاصه

- تکرارگر پل بین کانتینر و الگوریتم است.
- بازه نیمه‌باز `[begin, end)` است و همین باعث می‌شود مجموعهٔ خالی هم درست کار کند.
- `next`/`prev` مقدار جدید می‌دهند، `advance` درجا تغییر می‌دهد.
- دسته‌بندی تکرارگر تعیین می‌کند چه الگوریتمی روی چه کانتینری کار کند.
- هر عملیاتی که ساختار یا حافظه را عوض کند، ممکن است تکرارگر را باطل کند.

```
معکوس: 5 4 3 2 1 
آخرین بزرگ‌تر از 3 → اندیس 4 (مقدار 5)
آخرین بزرگ‌تر از 10 → پیدا نشد (-1)
distance(rbegin, rend) = 5
```

سه نکته:

1. جستجو از انتها با `rbegin` ارزان‌تر از پیمایش کامل رو به جلو و ذخیرهٔ آخرین نتیجه است.
2. برای تبدیل به اندیس واقعی: `distance(begin, rit.base()) - 1`.
3. اگر `std::distance(begin, rend())` بنویسید، کامپایلر خطای «نوع‌های ناسازگار» می‌دهد — تکرارگر معکوس و مستقیم قابل جمع نیستند.
