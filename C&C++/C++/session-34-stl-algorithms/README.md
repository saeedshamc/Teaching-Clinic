# جلسهٔ ۳۴ — الگوریتم‌های STL

> اگر حلقه‌ای می‌نویسید که «همه را می‌گردد تا چیزی پیدا کند»، احتمالاً الگوریتم آماده‌اش وجود دارد.

---

## اهداف این جلسه

1. `sort` را با کامپارator سفارشی به کار ببرید و بدانید چرا `<=` در آن اشتباه است.
2. `find`، `find_if`، `count`، `count_if` و `binary_search` را بشناسید.
3. `transform` و `accumulate` را برای پردازش دسته‌ای استفاده کنید.
4. الگوی `remove_if` + `erase` را درست بنویسید.
5. `all_of`/`any_of`/`none_of` را جای حلقه‌های شمارشی به کار ببرید.

---

## ۱. چرا الگوریتم

```cpp
// دستی
int count = 0;
for (int value : values) {
    if (value % 2 == 0) ++count;
}

// STL
const auto count = std::count_if(values.begin(), values.end(), isEven);
```

نسخهٔ دوم:

- نیت را در یک خط می‌گوید (شمارش زوج‌ها).
- باگ اندیس و شرط پایان ندارد.
- با کامپایلر و کتابخانه بهینه می‌شود و در نسخه‌های جدید موازی‌سازی هم ممکن است.

---

## ۲. `sort`

```cpp
std::sort(values.begin(), values.end());                        // صعودی
std::sort(values.begin(), values.end(), std::greater<int>());   // نزولی
std::sort(values.begin(), values.end(), byGradeDesc);           // کامپارator سفارشی
```

خروجی واقعی `01_sort_find.cpp`:

```
  قبل: 42 7 19 8 23 4 16 
  صعودی: 4 7 8 16 19 23 42 
  نزولی: 42 23 19 16 8 7 4 
```

### قاعدهٔ طلایی کامپارator

کامپارator باید **ترتیب ضعیف اکید** (strict weak ordering) بسازد. به زبان ساده: باید مثل `<` رفتار کند، نه `<=`.

```cpp
std::sort(v.begin(), v.end(), [](int a, int b) { return a <= b; });   // ❌
std::sort(v.begin(), v.end(), [](int a, int b) { return a < b; });    // ✅
```

اگر کامپارator برای `a == b` هم `true` برگرداند، `std::sort` می‌تواند حافظه را زیر پا بگذارد یا کرش کند — رفتار تعریف‌نشده، نه خطای کامپایل.

`sort` تکرارگر تصادفی می‌خواهد، پس روی `list` استفاده نمی‌شود؛ `list` عضو `sort()` دارد.

`std::stable_sort` ترتیب عناصر مساوی را حفظ می‌کند (به قیمت حافظهٔ بیشتر).

## ۳. جستجو

```cpp
std::find(v.begin(), v.end(), 19);          // اولین برابر
std::find_if(v.begin(), v.end(), isEven);   // اولین شرط‌دار
std::binary_search(v.begin(), v.end(), 23); // فقط بله/خیر، روی دادهٔ مرتب
std::equal_range(v.begin(), v.end(), 16);   // بازهٔ همهٔ عناصر برابر
```

خروجی واقعی:

```
--- find ---
  19 در اندیس 4
  100 پیدا نشد
--- find_if ---
  اولین زوج: 4 در اندیس 0
--- count و count_if ---
  count(8) = 1
  count_if(isEven) = 4
--- binary_search روی دادهٔ مرتب ---
  binary_search(23): هست
  binary_search(50): نیست
  equal_range(16): از اندیس 3 تا 4
--- min و max ---
  min = 4، max = 42
```

نکته‌ها:

- `find` خطی است (`O(n)`). اگر داده مرتب است، `binary_search` با `O(log n)` بسیار سریع‌تر است — ولی روی دادهٔ نامرتب، خروجی **بی‌معنی** است، نه فقط کند.
- `equal_range` برای مجموعه‌های چندعضوی برابر (مثلاً `multiset`) بازهٔ کامل را می‌دهد.
- برای پیداکردن اندیس از `std::distance(begin, it)` استفاده کنید.

## ۴. `transform` و `accumulate`

```cpp
std::transform(src.begin(), src.end(), dst.begin(), doubled);
const int sum = std::accumulate(v.begin(), v.end(), 0);
```

خروجی واقعی `02_transform_accumulate.cpp`:

```
--- transform ---
  2 4 6 8 10 
--- accumulate ---
  مجموع = 15، حاصل‌ضرب = 120
  میانگین = 3
--- transform روی رشته ---
  HELLO STL
--- transform درجا ---
  2 -4 6 -8 
--- count_if ---
  مثبت‌ها: 2
--- دقت accumulate ---
  با شروع int: 0، با شروع double: 0.6
```

سه دام مهم:

1. **مقصد باید جا داشته باشد.** `dst` باید از قبل `size` درست داشته باشد (`std::vector<int> dst(src.size())`)، وگرنه `transform` روی حافظهٔ ناموجود می‌نویسد. راه دیگر: `std::back_inserter(dst)`.
2. **نوع مقدار شروع `accumulate` نوع نتیجه را تعیین می‌کند.** با `0` همه‌چیز `int` می‌شود و `0.1 + 0.2 + 0.3` به `0` تبدیل می‌شود؛ با `0.0` جواب `0.6` است. این خروجی واقعی، بهترین درس این بخش است.
3. **`transform` درجا** (`src.begin()` به‌عنوان مقصد) مجاز است و حافظهٔ اضافه نمی‌خواهد.

`accumulate` در `<numeric>` است، نه `<algorithm>`.

---

## ۵. الگوی `erase-remove_if`

این مهم‌ترین نکتهٔ عملی جلسه است. `std::remove_if` **حذف نمی‌کند**؛ فقط عناصر باقی‌مانده را به ابتدا می‌آورد و تکرارگر «پایان منطقی» را برمی‌گرداند.

خروجی واقعی `03_erase_remove_if.cpp`:

```
  قبل: [5, -3, 8, -1, 0, 12, -7]  size = 7
--- بعد از remove_if، قبل از erase ---
  داده: [5, 8, 0, 12, 0, 12, -7]  size = 7
  عناصر منطقی: 4
--- بعد از erase ---
  داده: [5, 8, 0, 12]  size = 4
```

اندازه بعد از `remove_if` هنوز ۷ است! فقط ترتیب عوض شد و آخرین خانه‌ها «آشغال» شدند. حذف واقعی کار `erase` است:

```cpp
values.erase(std::remove_if(values.begin(), values.end(), isNegative), values.end());
```

چرا دو مرحله؟ چون `remove_if` فقط با تکرارگر کار می‌کند و نمی‌داند کانتینر چه نوعی است؛ تغییر اندازه وظیفهٔ کانتینر است. این جدایی، همان فلسفهٔ سه‌ستونی STL است.

## ۶. `all_of` / `any_of` / `none_of`

```
--- all_of / any_of / none_of ---
  all_of(>0): خیر
  any_of(>0): بله
  none_of(>0): خیر
```

هر سه از اولین نتیجهٔ قطعی برمی‌گردند (`short-circuit`)، پس روی مجموعهٔ بزرگ سریع‌تر از حلقهٔ کامل‌شمارشگر هستند. نامشان نیت را بهتر از `count_if(...) == size` می‌رساند.

## ۸. اشتباهات رایج

1. **کامپارator با `<=`** → رفتار تعریف‌نشده در `sort`.
2. **`binary_search` روی دادهٔ نامرتب** → نتیجهٔ تصادفی.
3. **`remove_if` بدون `erase`** → اندازه تغییر نمی‌کند و دادهٔ آشغال در انتها می‌ماند.
4. **`transform` بدون فضای مقصد** → نوشتن بیرون از محدوده.
5. **`accumulate` با `0` برای `double`** → برش به `int`.
6. **`sort` روی `list`** → خطای کامپایل.
7. **کامپارator غیر-const یا با side effect** → نتیجهٔ نامعین و خطاهای سخت‌یاب.
8. **`find` در حلقه برای هر عنصر** → `O(n²)`؛ اگر زیاد جستجو می‌کنید `set`/`map`.

---

## ۹. بهترین شیوه‌ها

- نام تابع کامپارator را گویا بگذارید: `byGradeDesc`، `byName`.
- برای مرتب‌سازی پایدار `stable_sort`.
- کامپارator را کوچک و بدون side effect بنویسید.
- `remove_if` را همیشه با `erase` ترکیب کنید.
- `accumulate` را با مقدار شروع هم‌نوع با نتیجه صدا بزنید (`0.0` برای `double`).
- پیش از نوشتن حلقه، فهرست الگوریتم‌ها را یک بار مرور کنید.

---

## ۱۰. خلاصه

- الگوریتم‌ها روی محدودهٔ تکرارگر کار می‌کنند و نیت را واضح می‌کنند.
- `sort` با کامپارator اکید؛ `stable_sort` برای حفظ ترتیب مساوی‌ها.
- `find`/`count` خطی‌اند؛ `binary_search` روی دادهٔ مرتب لگاریتمی.
- `add`-style: `transform` مقصد لازم دارد؛ `accumulate` نوع شروع مهم است.
- `remove_if` فقط جابه‌جا می‌کند؛ `erase` حذف می‌کند.
