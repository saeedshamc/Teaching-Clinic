# جلسهٔ ۲۹ — `list` و `deque`

> `vector` همیشه جواب نیست: وقتی درج و حذف در میانه زیاد است، `list` برنده می‌شود؛ وقتی دو سر مهم است، `deque`.

---

## اهداف این جلسه

1. ساختار `std::list` و دلیل ارزان بودن درج/حذف در آن را بفهمید.
2. با `splice` گره‌ها را بین لیست‌ها بدون کپی منتقل کنید.
3. `std::deque` و تفاوتش با `vector` را بشناسید.
4. بدانید چرا `std::sort` روی `list` کار نمی‌کند.
5. برای هر سناریو بین `vector`، `list` و `deque` تصمیم بگیرید.

---

## ۱. `list` چیست

`std::list` یک فهرست **پیوندی دوطرفه** است: هر عنصر در گرهٔ جداگانه‌ای با اشاره‌گر به قبلی و بعدی.

```
head → [5] ⇄ [10] ⇄ [15] ⇄ [20] → null
```

پیامدها:

| ویژگی | نتیجه |
|---|---|
| گره‌ها پراکنده در حافظه | پیمایش کندتر از `vector` (کش CPU پراکنده) |
| هر گره دو اشاره‌گر اضافه دارد | سربار حافظهٔ بیشتر |
| درج/حذف با تکرارگر آماده | `O(1)` و **هیچ** عنصر دیگری جابه‌جا نمی‌شود |
| دسترسی با اندیس | ندارد؛ فقط پیمایش `O(n)` |
| تکرارگر | فقط در صورت حذف همان گره باطل می‌شود |

```cpp
std::list<int> values{30, 10, 20};
auto it = values.begin();
std::advance(it, 2);          // پیمایش تا عنصر سوم
values.insert(it, 15);        // O(1) — بقیه تکان نمی‌خورند
```

برای رسیدن به تکرارگر اما `O(n)` پیمایش کردیم؛ پس صرفه‌جویی وقتی معنا دارد که تکرارگر را از قبل داشته باشید (یا از `splice`/`remove` استفاده کنید).

---

## ۲. عملیات مخصوص `list`

چون تکرارگر تصادفی ندارد، `std::sort` روی آن کامپایل نمی‌شود. `list` نسخهٔ خودش را دارد:

```cpp
values.sort();      // مرتب‌سازی درجا، بدون تخصیص حافظهٔ اضافه
values.unique();     // حذف تکراری‌های **همسایه**
values.remove(40);   // حذف همهٔ عناصر با مقدار ۴۰
values.reverse();
values.merge(other); // ادغام دو لیست مرتب
```

### تلهٔ `unique`

`unique` فقط تکراری‌های **پشت سر هم** را حذف می‌کند. در خروجی واقعی این جلسه دیدیم:

```
--- push_back(20) دو بار ---
  [5, 10, 15, 20, 40, 20, 20]  size = 7
--- unique (فقط همسایه‌های تکراری) ---
  [5, 10, 15, 20, 40, 20]  size = 6
```

سه تا `20` داشتیم ولی چون `40` بین دو‌تا از آن‌ها بود، فقط دو‌تای آخر ادغام شدند. اگر یکتایی کامل می‌خواهید: `sort()` بعد `unique()`.

---

## ۳. `splice` — انتقال بدون کپی

`splice` گره‌ها را از یک لیست جدا و به لیست دیگر وصل می‌کند؛ نه کپی، نه تخصیص حافظه.

```cpp
urgent.splice(urgent.end(), normal);          // کل normal به انتهای urgent
normal.splice(normal.begin(), urgent, it);    // فقط گرهٔ it
```

خروجی واقعی `02_list_splice.cpp`:

```
--- شروع ---
  urgent: [سرور, پرداخت]  size = 2
  normal: [مستندات, ایمیل, گزارش]  size = 3
--- splice کل لیست ---
  urgent: [سرور, پرداخت, مستندات, ایمیل, گزارش]  size = 5
  normal: []  size = 0
--- انتقال یک گره («مستندات») ---
  urgent: [سرور, پرداخت, ایمیل, گزارش]  size = 4
  normal: [مستندات]  size = 1
```

`normal` بعد از اولین `splice` خالی شد — گره‌ها منتقل شدند، کپی نشدند. این کار با `vector` فقط با کپی/انتقال همهٔ عناصر ممکن است.

---

## ۴. `deque` — صف دوطرفه

`std::deque` مخفف double-ended queue است: چند بلوک پیوسته که در دو سر رشد می‌کنند.

| عملیات | `vector` | `deque` |
|---|---|---|
| `push_back` | `O(1)` سرشکن | `O(1)` سرشکن |
| `push_front` | `O(n)` ❌ | `O(1)` ✅ |
| دسترسی `[i]` | `O(1)` | `O(1)` |
| حافظهٔ پیوسته | بله | نه (بلوکی) |
| درج در میانه | `O(n)` | `O(n)` |

پس اگر برنامه‌تان «از دو سر اضافه/حذف می‌کند و گاهی اندیس می‌خواهد»، `deque` انتخاب درست است.

خروجی واقعی `03_deque.cpp`:

```
--- تاریخچه ---
  [نوشتن, ویرایش, اجرا]  size = 3
  history[1] = ویرایش  (دسترسی تصادفی)
--- بعد از افزودن «ذخیره» و کوتاه کردن ---
  [ویرایش, اجرا, ذخیره]  size = 3
--- push_front("بازگشت") ---
  [بازگشت, ویرایش, اجرا, ذخیره]  size = 4
  جلو: بازگشت، عقب: ذخیره
--- pop_back ---
  [بازگشت, ویرایش, اجرا]  size = 3
```

الگوی «فقط سه عمل آخر» با `while (history.size() > 3) history.pop_front();` کار می‌کند — در `vector` حذف از ابتدا هر بار `O(n)` بود.

---

## ۵. جدول تصمیم

| نیاز | انتخاب |
|---|---|
| پیمایش کامل و دسترسی با اندیس | `vector` |
| افزودن/حذف در دو سر با دسترسی تصادفی | `deque` |
| درج/حذف زیاد در میانه با تکرارگر آماده | `list` |
| انتقال دسته‌ای عناصر بین مجموعه‌ها | `list` + `splice` |
| ادغام دو مجموعهٔ مرتب | `list::merge` |
| صرفاً پیمایش رو به جلو با کمترین حافظه | `forward_list` |

قاعدهٔ عملی: **`list` را فراموش کنید مگر اینکه پروفایل نشان دهد گلوگاه جابه‌جایی است.** بیشتر مواقع `vector` حتی از `list` سریع‌تر است، چون کش CPU را بهتر استفاده می‌کند.

## ۷. اشتباهات رایج

1. **`std::sort(list.begin(), list.end())`** → خطای کامپایل، چون تکرارگر تصادفی لازم است. از `values.sort()` استفاده کنید.
2. **`list[i]`** → وجود ندارد؛ `std::advance` یا `std::next` لازم است.
3. **انتظار یکتایی کامل از `unique`** → فقط همسایه‌ها را حذف می‌کند.
4. **استفاده از `list` برای دادهٔ کوچک** → سربار حافظه و پیمایش کندتر، بدون سود.
5. **`erase` در حلقه بدون استفاده از مقدار بازگشتی** → همان تلهٔ `vector`.
6. **نگه داشتن تکرارگر بعد از `splice`** → تکرارگر به همان گره اشاره می‌کند ولی لیست مالک عوض شده است؛ برای جلوگیری از سردرگمی دوباره بگیرید.
7. **`deque` و انتظار حافظهٔ پیوسته** → `&d[0] + i` معتبر نیست؛ `deque` بلوکی است.

## ۸. بهترین شیوه‌ها

- برای `list`، تکرارگر را یک بار پیدا کنید و بارها استفاده کنید؛ وگرنه هزینهٔ پیمایش، سود درج ارزان را می‌خورد.
- `splice` را برای انتقال دسته‌ای به‌جای حلقهٔ کپی/حذف استفاده کنید.
- برای صف کارها `deque` یا `queue`؛ برای پشته `vector`/`deque` با آداپتور `stack`.
- قبل از انتخاب `list`، پروفایل بگیرید.

---

## ۹. خلاصه

- `list` پیوندی است: درج/حذف `O(1)` با تکرارگر، ولی دسترسی `O(n)` و پیمایش کندتر.
- `sort`، `unique`، `remove`، `merge` و `splice` اعضای خود `list` هستند.
- `unique` فقط تکراری‌های همسایه را حذف می‌کند.
- `deque` درج/حذف `O(1)` در دو سر و دسترسی تصادفی `O(1)` می‌دهد.
