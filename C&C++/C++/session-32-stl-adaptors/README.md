# جلسهٔ ۳۲ — `stack`، `queue` و `priority_queue`

> آداپتور کانتینر، کانتینر نیست: یک رابط محدود است که روی کانتینر دیگری می‌نشیند تا فقط عملیات مجاز را نشان دهد.

---

## اهداف این جلسه

1. `stack` و منطق LIFO را در عمل ببینید.
2. `queue` و منطق FIFO را با یک صف کار به کار ببرید.
3. `priority_queue` و کامپارator سفارشی را بشناسید.
4. بدانید کانتینر زیرین چیست و چرا مهم است.
5. با `stack` یک مسئلهٔ واقعی (بررسی توازن پرانتزها) حل کنید.

---

## ۱. آداپتور چیست

`stack`، `queue` و `priority_queue` داده را خودشان نگه نمی‌دارند؛ **کانتینر زیرین** را می‌گیرند و فقط بخشی از عملیاتش را نشان می‌دهند:

| آداپتور | کانتینر پیش‌فرض | عملیات |
|---|---|---|
| `stack` | `deque` | `push`، `pop`، `top`، `empty`، `size` |
| `queue` | `deque` | `push`، `pop`، `front`، `back`، `empty`، `size` |
| `priority_queue` | `vector` | `push`، `pop`، `top`، `empty`، `size` |

هیچ‌کدام تکرارگر ندارند: نمی‌توانید پشته را پیمایش کنید. همین محدودیت، هدف است — رابط اجازه نمی‌دهد قانون LIFO یا FIFO را بشکنید.

```cpp
std::stack<int, std::vector<int>> onVector;   // کانتینر زیرین را خودتان انتخاب کنید
```

---

## ۲. `stack` — آخرین ورودی، اولین خروجی

```cpp
std::stack<std::string> history;
history.push("نوشتن");
history.push("ویرایش");
history.push("حذف");
std::cout << history.top();   // "حذف"
history.pop();                // حذف شد
```

خروجی واقعی `01_stack.cpp`:

```
--- پشته (LIFO) ---
  top = حذف، size = 3
  pop → حذف
  pop → ویرایش
  pop → نوشتن
  size بعد از خالی شدن = 0
--- معکوس کردن "C++" ---
  ++C
  هیچ تکرارگری ندارد: نمی‌توان پشته را پیمایش کرد، فقط top.
```

نکتهٔ مهم: `pop()` **مقدار برنمی‌گرداند**. باید اول `top()` بگیرید و بعد `pop()` کنید. اگر پشته خالی باشد، `top()` رفتار تعریف‌نشده دارد؛ همیشه `empty()` را بررسی کنید.

کاربردهای `stack`: Undo/Redo، ارزیابی عبارت، پیمایش عمق‌اول (DFS) بدون بازگشت، بررسی توازن نمادها.

---

## ۳. `queue` — اولین ورودی، اولین خروجی

```cpp
std::queue<std::string> jobs;
jobs.push("کامپایل");
jobs.push("تست");
jobs.push("بسته‌بندی");
std::cout << jobs.front();   // "کامپایل"
```

خروجی واقعی `02_queue.cpp`:

```
--- صف (FIFO) ---
  front = کامپایل، back = بسته‌بندی، size = 3
  1) کامپایل
  2) تست
  3) بسته‌بندی
  صف خالی است: بله
queue هم تکرارگر ندارد؛ فقط front/back و pop.
```

کاربردهای `queue`: صف کار (job queue)، پیمایش سطح‌اول (BFS)، بافر پیام، زمان‌بندی درخواست‌ها.

تفاوت کلیدی با `stack`: `stack` فقط یک سر دارد (`top`)، `queue` دو سر دارد (`front` برای خروج، `back` برای ورود) ولی فقط از `front` حذف می‌شود.

---

## ۴. `priority_queue` — همیشه بهترین اول

`priority_queue` یک heap روی `vector` نگه می‌دارد، پس `top()` همیشه بزرگ‌ترین عنصر است.

```cpp
std::priority_queue<int> maxHeap;                                     // بزرگ‌ترین اول
std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap; // کوچک‌ترین اول
```

خروجی واقعی `03_priority_queue.cpp`:

```
--- max-heap (پیش‌فرض) ---
  5 3 2 1 
--- min-heap با greater<int> ---
  1 2 3 5 
--- صف اولویت‌دار کارها ---
  5 → رفع باگ
  3 → جلسه
  1 → مستندات
```

ورودی هر دو heap یکسان بود: `{3, 1, 5, 2}`. فقط کامپارator عوض شد.

### کامپارator سفارشی

برای `struct Task`، یک functor تعریف می‌کنیم که بگوید کدام «کوچک‌تر» است — چون heap بزرگ‌ترین را اول می‌دهد، `TaskCompare` باید برای اولویت کمتر `true` برگرداند:

```cpp
struct TaskCompare {
    bool operator()(const Task& left, const Task& right) const {
        return left.priority < right.priority;
    }
};

std::priority_queue<Task, std::vector<Task>, TaskCompare> tasks;
```

این کامپارator «کمتر از» است، نه «بزرگ‌تر از». اگر برعکسش کنید، کم‌اولویت‌ترین کار اول اجرا می‌شود — اشتباه رایج و بی‌صدایی که فقط با تست کردن خروجی معلوم می‌شود.

کاربردها: زمان‌بند وظایف، الگوریتم دایکسترا، ادغام k فهرست مرتب، انتخاب k عنصر بزرگ‌تر.

## ۵. جدول انتخاب

| نیاز | آداپتور |
|---|---|
| آخرین اول (Undo، DFS، توازن پرانتز) | `stack` |
| اولین اول (صف کار، BFS) | `queue` |
| همیشه بزرگ‌ترین/کوچک‌ترین | `priority_queue` |
| دسترسی به همهٔ عناصر | آداپتور نه — `vector`/`deque`/`list` |

## ۷. اشتباهات رایج

1. **`int x = s.pop();`** → `pop()` مقدار برنمی‌گرداند؛ `top()` بعد `pop()`.
2. **`top()`/`front()` روی آداپتور خالی** → رفتار تعریف‌نشده. اول `empty()`.
3. **پیمایش `stack` با `for`** → تکرارگر ندارد؛ اگر پیمایش لازم است، کانتینر اشتباه است.
4. **کامپارator معکوس در `priority_queue`** → کم‌اولویت اول درمی‌آید.
5. **انتظار پایداری (stability) از `priority_queue`** → برای عناصر با اولویت برابر ترتیب تضمینی نیست.
6. **`priority_queue` با کامپارator غیر-const** → امضا باید `bool operator()(...) const` باشد، وگرنه خطای کامپایل.
7. **آداپتور به‌جای `vector` برای دادهٔ عمومی** → اگر به همهٔ عناصر نیاز دارید، آداپتور مانع شماست.

---

## ۸. بهترین شیوه‌ها

- آداپتور را وقتی انتخاب کنید که **قانون دسترسی** بخشی از طراحی است.
- قبل از هر `top`/`front`/`pop`، `empty()` را بررسی کنید.
- کامپارator را «کمتر از» بنویسید و با یک مثال کوچک تست کنید.
- برای صف با حذف از دو سر، `deque` مستقیم بهتر از `queue` است.

---

## ۹. خلاصه

- آداپتورها رابط محدود روی کانتینر زیرین‌اند و تکرارگر ندارند.
- `stack` = LIFO، `queue` = FIFO، `priority_queue` = heap با `top` همیشه بهترین.
- `pop()` چیزی برنمی‌گرداند.
- `priority_queue` با `std::greater<T>` به min-heap تبدیل می‌شود و با functor سفارشی هر ترتیبی می‌گیرد.

## ۱۰. تمرین‌ها

### تمرین ۱ — بررسی توازن پرانتزها (متوسط)

`exercises/exercise_01.cpp`: با `stack<char>` بررسی کنید که پرانتزها، کروشه‌ها و آکولادها درست بسته شده‌اند.

```
"(a[b]{c})" → متوازن
"([)]"      → نامتوازن
"((("       → نامتوازن
""          → متوازن
```

سه حالت شکست که باید پوشش دهید:

1. **بسته بدون باز** → پشته خالی است و نماد بسته می‌آید.
2. **نوع یا ترتیب غلط** → `([)]` : بالای پشته `[` است ولی `)` می‌آید.
3. **بازِ باقی‌مانده** → بعد از پایان متن، پشته خالی نیست.

این تمرین الگوی کلاسیک «پشته به‌عنوان حافظهٔ تودرتویی» را نشان می‌دهد؛ همان ایده در تجزیه‌گر عبارت و پارسر JSON هم استفاده می‌شود.
