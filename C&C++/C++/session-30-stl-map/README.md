# جلسهٔ ۳۰ — `map` و `unordered_map`

> `map` کلید را به مقدار نگاشت می‌کند و کلیدها را مرتب نگه می‌دارد. `unordered_map` همین کار را با هش و سریع‌تر، ولی بی‌ترتیب انجام می‌دهد.

---

## اهداف این جلسه

1. `map` را بسازید، درج/به‌روزرسانی/حذف کنید و پیمایش کنید.
2. تفاوت خطرناک `operator[]` و `at` را بشناسید.
3. از `insert`/`emplace` و نتیجهٔ `pair<iterator, bool>` استفاده کنید.
4. الگوی شمارش `++counts[word]` را به کار ببرید.
5. `unordered_map` و نیاز به هش و `operator==` سفارشی را بفهمید.

---

## ۱. `map` چیست

`std::map<Key, Value>` یک درخت متوازن (معمولاً red-black) از جفت‌های کلید→مقدار است:

- هر کلید **یکتا** است.
- کلیدها همیشه **مرتب** هستند (بر اساس `operator<`).
- جستجو، درج و حذف `O(log n)`.

```cpp
std::map<std::string, int> ages;
ages["Saeed"] = 30;      // درج
ages["Saeed"] = 31;      // به‌روزرسانی
```

---

## ۲. `operator[]` در برابر `at`

این مهم‌ترین بخش جلسه است.

```cpp
int a = ages["Unknown"];    // ⚠️ کلید را با مقدار ۰ درج می‌کند!
int b = ages.at("Unknown"); // ✅ std::out_of_range پرتاب می‌کند
```

`operator[]` برای **نوشتن** طراحی شده است، پس اگر کلید نبود باید چیزی بسازد. خروجی واقعی:

```
--- operator[] روی کلید ناموجود ---
  ages["Reza"] = 0 (کلید ناخواسته درج شد)
  size = 4
```

یک خواندن ساده، اندازهٔ `map` را از ۳ به ۴ برد. برای خواندن بدون تغییر:

```cpp
const auto it = ages.find("Reza");
if (it != ages.end()) {
    std::cout << it->second;
}
```

قاعده: **`[]` برای نوشتن، `at` یا `find` برای خواندن.**

---

## ۳. `insert` و `emplace`

`insert` روی کلید تکراری **بازنویسی نمی‌کند**، فقط اعلام می‌کند که درج نشد:

```cpp
const auto [it, inserted] = ages.insert({"Mina", 28});
```

نتیجه یک `pair<iterator, bool>` است؛ با structured binding (جلسهٔ ۴۸) به‌سادگی از هم باز می‌شود. خروجی واقعی:

```
  insert("Mina", 28) → inserted = بله
  insert تکراری → inserted = خیر، مقدار فعلی: 28
```

`emplace` همان کار را با ساخت درجا انجام می‌دهد:

```cpp
ages.emplace("Omid", 35);
```

| عملیات | کلید موجود |
|---|---|
| `insert` / `emplace` | رد می‌شود، مقدار قبلی می‌ماند |
| `insert_or_assign` | مقدار را به‌روزرسانی می‌کند |
| `operator[]` | مقدار را به‌روزرسانی می‌کند (و در نبود، می‌سازد) |

---

## ۴. الگوی شمارش

پرکاربردترین خط `map` در کد واقعی:

```cpp
++counts[word];
```

اگر کلید نبود `operator[]` آن را با `0` می‌سازد و بعد `++` یکی اضافه می‌کند. خروجی واقعی `02_word_count.cpp`:

```
شمارش کلمات (کلید مرتب):
  cpp = 3
  map = 2
  set = 1
  stl = 1
  vector = 1
تعداد کلمات یکتا: 5
تعداد کل کلمات: 8
پرتکرارترین: cpp (3)
stl = 1
```

دو نکته:

1. `counts.size()` تعداد کلمات **یکتا** است، نه تعداد کل کلمات؛ برای دومی شمارندهٔ جدا لازم است.
2. ترتیب چاپ، ترتیب حروف الفبا است، نه ترتیب ورود متن — چون `map` مرتب است.

---

## ۵. `unordered_map`

`std::unordered_map` از **جدول هش** استفاده می‌کند:

| ویژگی | `map` | `unordered_map` |
|---|---|---|
| جستجو | `O(log n)` | میانگین `O(1)` |
| ترتیب پیمایش | مرتب بر اساس کلید | **نامشخص** |
| نیاز کلید | `operator<` | `operator==` + تابع هش |
| حافظه | متوسط | بیشتر (سبدها) |
| بدترین حالت | `O(log n)` | `O(n)` (اگر هش بد باشد) |

### کلید سفارشی

برای `struct Point` باید دو چیز بدهید: `operator==` و تابع هش.

```cpp
struct PointHash {
    std::size_t operator()(const Point& point) const {
        const std::size_t hx = std::hash<int>{}(point.x);
        const std::size_t hy = std::hash<int>{}(point.y);
        return hx ^ (hy + 0x9e3779b9u + (hx << 6) + (hx >> 2));
    }
};

std::unordered_map<Point, std::string, PointHash> labels;
```

`0x9e3779b9` عدد طلایی ۳۲ بیتی است؛ ترکیب `xor` با شیفت آن را به standard trick تبدیل می‌کند. خروجی واقعی `03_unordered_map.cpp`:

```
--- برچسب نقطه‌ها (ترتیب تضمین‌شده نیست) ---
  (3, 4) → نقطهٔ C
  (2, 1) → نقطهٔ B
  (1, 2) → نقطهٔ A (به‌روز)
  (0, 0) → مبدأ
  size = 4
```

ترتیب نه بر اساس درج است و نه بر اساس مقدار؛ **هیچ تضمینی** وجود ندارد. اگر خروجی برنامه‌تان باید قطعی باشد (مثل تست)، روی ترتیب `unordered_map` حساب نکنید — به `map` کپی کنید یا مرتب کنید. این خروجی روی `libstdc++`/GCC گرفته شده و با کامپایلر دیگر ممکن است متفاوت باشد.

### ۶.۱ خروجی واقعی `01_map_basics.cpp`

```
--- بعد از درج و به‌روزرسانی ---
  {Ali: 20, Saeed: 30, Sara: 26}  size = 3
--- operator[] روی کلید ناموجود ---
  ages["Reza"] = 0 (کلید ناخواسته درج شد)
  size = 4
--- at با کلید ناموجود ---
    out_of_range: map::at
--- insert و emplace ---
  insert("Mina", 28) → inserted = بله
  insert تکراری → inserted = خیر، مقدار فعلی: 28
  {Ali: 20, Mina: 28, Omid: 35, Reza: 0, Saeed: 30, Sara: 26}  size = 6
--- find و count ---
  پیدا شد: Sara = 26
  "Nobody" وجود ندارد (count = 0)
--- erase ---
  {Ali: 20, Mina: 28, Omid: 35, Saeed: 30, Sara: 26}  size = 5
```

کلیدها همیشه مرتب‌اند: `Ali`، `Mina`، `Omid`، ... حتی وقتی `Sara` اول درج شد. پیام `map::at` پیاده‌سازی‌محور است؛ روی متن آن تست ننویسید، روی `std::out_of_range` تکیه کنید.

## ۷. اشتباهات رایج

1. **خواندن با `operator[]`** → کلید ناخواسته درج می‌شود و `size` عوض می‌شود.
2. **انتظار بازنویسی از `insert`** → کلید موجود دست‌نخورده می‌ماند؛ `insert_or_assign` یا `[]` لازم است.
3. **انتظار ترتیب درج از `map`** → ترتیب همیشه بر اساس کلید است.
4. **انتظار ترتیب از `unordered_map`** → وجود ندارد.
5. **کلید غیرقابل‌مقایسه در `map`** → باید `operator<` داشته باشد، وگرنه خطای کامپایل.
6. **کلید بدون هش در `unordered_map`** → خطای کامپایل طولانی؛ `operator==` و تابع هش لازم است.
7. **تغییر کلید داخل پیمایش** → `map` ساختار درخت را عوض می‌کند و تکرارگر نامعتبر می‌شود.
8. **تکیه بر `count` برای وجود** → در `map` مقدار ۰ و ۱ دارد؛ `find` مستقیم‌تر است و در صورت نیاز به مقدار، یک جستجو کمتر می‌خواهد.
9. **هش ضعیف** → همهٔ کلیدها در یک سبد می‌افتند و `O(1)` به `O(n)` تبدیل می‌شود.

---

## ۸. بهترین شیوه‌ها

- `[]` فقط برای نوشتن؛ `at`/`find` برای خواندن.
- برای شمارش `++counts[key]` بنویسید.
- برای خروجی قطعی و تست‌پذیر، `map` یا مرتب‌سازی صریح.
- وقتی تعداد کلیدها کم است (چند ده تا)، تفاوت `map` و `unordered_map` عملاً دیده نمی‌شود؛ خوانایی `map` را انتخاب کنید.
- تابع هش سفارشی را ساده و یکنواخت نگه دارید و یادتان باشد دو شیء برابر باید هش برابر بدهند.

---

## ۹. خلاصه

- `map` درخت متوازن است: کلید یکتا، مرتب، `O(log n)`.
- `operator[]` کلید ناموجود را درج می‌کند؛ `at` استثنا می‌دهد.
- `insert`/`emplace` روی کلید تکراری چیزی را عوض نمی‌کنند و نتیجهٔ `pair<iterator, bool>` می‌دهند.
- `++counts[word]` الگوی استاندارد شمارش است.
- `unordered_map` سریع‌تر ولی بی‌ترتیب است و برای کلید سفارشی به هش و `operator==` نیاز دارد.
