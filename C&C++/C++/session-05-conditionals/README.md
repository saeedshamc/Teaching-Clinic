# جلسهٔ ۵ — شرط‌ها: `if`، `switch` و عملگر سه‌گانه

> برنامه‌ای که همیشه یک مسیر را می‌رود، تصمیم نمی‌گیرد. این جلسه دربارهٔ تصمیم‌گیری است.

---

## اهداف این جلسه

1. با `if`، `else if` و `else` منطق چندشاخه بنویسید.
2. بدانید ترتیب شرط‌ها چرا مهم است.
3. از `switch` و `case` به‌درستی استفاده کنید و نقش `break` و `default` را بفهمید.
4. عملگر سه‌گانهٔ `?:` را بشناسید و بدانید کجا استفاده **نکنید**.
5. خطای کلاسیک `=` به‌جای `==` را تشخیص دهید.

---

## ۱. `if` ساده

```cpp
int age = 20;
if (age >= 18) {
    std::cout << "بزرگسال\n";
}
```

- شرط داخل پرانتز به `bool` تبدیل می‌شود: صفر یعنی غلط، هر چیز دیگر درست.
- آکولاد برای یک دستور اختیاری است، اما **همیشه بنویسید**؛ باگ‌های `if` بدون آکولاد بسیار رایج‌اند.

```cpp
if (score >= 10)
    std::cout << "قبول\n";
    std::cout << "تبریک\n";   // ⚠️ این خط همیشه اجرا می‌شود!
```

---

## ۲. `else` و `else if`

```cpp
int score = 0;
std::cin >> score;

if (score < 0 || score > 100) {
    std::cerr << "نمرهٔ نامعتبر\n";
} else if (score >= 90) {
    std::cout << "عالی\n";
} else if (score >= 75) {
    std::cout << "خوب\n";
} else if (score >= 50) {
    std::cout << "قبول\n";
} else {
    std::cout << "مردود\n";
}
```

نکتهٔ کلیدی: شرط‌ها **به ترتیب** بررسی می‌شوند و اولین شرط درست برنده است. اگر اول `score >= 50` را بنویسید، نمرهٔ ۹۵ هم «قبول» می‌شود و هرگز به «عالی» نمی‌رسد. پس همیشه از **سخت‌ترین/بزرگ‌ترین** شرط شروع کنید.

بررسی نامعتبر بودن را **اول** می‌گذاریم تا بقیهٔ منطق روی دادهٔ سالم کار کند؛ این الگوی «guard clause» است.

---

## ۳. شرط‌های تودرتو و ترکیب

```cpp
if (isLoggedIn) {
    if (isAdmin) {
        std::cout << "دسترسی کامل\n";
    } else {
        std::cout << "دسترسی محدود\n";
    }
}
```

می‌توان ساده‌تر نوشت:

```cpp
if (isLoggedIn && isAdmin) { ... }
```

هر جا ترکیب منطقی خوانایی را بهتر می‌کند، تودرتو نکنید. اما اگر منطق واقعاً دو مرحله‌ای است (اول ورود، بعد سطح دسترسی)، تودرتو طبیعی است.

---

## ۴. `switch`

برای انتخاب از بین چند **مقدار مشخص** (نه بازه)، `switch` خواناتر از زنجیرهٔ `if` است:

```cpp
char choice = ' ';
std::cin >> choice;

switch (choice) {
    case 'a':
    case 'A':
        std::cout << "افزودن\n";
        break;
    case 'd':
        std::cout << "حذف\n";
        break;
    case 'q':
        std::cout << "خروج\n";
        break;
    default:
        std::cout << "گزینهٔ نامعتبر\n";
        break;
}
```

قواعد:

- `case`ها باید **مقدار ثابت** باشند (عدد، کاراکتر، `constexpr`، عضو `enum`).
- بدون `break`، اجرا به `case` بعدی **می‌ریزد** (fallthrough) — گاهی عمدی است (مثل `'a'` و `'A'` بالا)، ولی معمولاً باگ است.
- `default` برای حالت‌های دیگر است؛ نوشتنش عادت خوبی است.
- `switch` روی `std::string` کار نمی‌کند.

### `switch` با `enum`

```cpp
enum class Direction { Up, Down, Left, Right };

switch (dir) {
    case Direction::Up:    std::cout << "بالا\n"; break;
    case Direction::Down:  std::cout << "پایین\n"; break;
    // ...
}
```

`enum class` نوع را جدا و امن می‌کند و کامپایلر می‌تواند هشدار بدهد اگر یک حالت را جا انداخته باشید (با `-Wswitch` که در `-Wall` هست).

---

## ۵. عملگر سه‌گانه `?:`

```cpp
const int a = 7, b = 12;
const int max = (a > b) ? a : b;                 // 12
std::string status = (score >= 10) ? "قبول" : "مردود";
```

عملگر سه‌گانه یک **عبارت** است (مقدار دارد) نه دستور؛ به همین دلیل می‌توان آن را داخل `cout` یا مقداردهی نوشت.

کجا **نه**:

```cpp
// بد: خواندنش سخت است
std::string g = (s > 90) ? "A" : (s > 75) ? "B" : (s > 50) ? "C" : "F";
```

برای بیش از یک شرط، `if`/`else if` بنویسید. قاعدهٔ ساده: `?:` فقط برای انتخاب بین **دو** مقدار ساده.

---

## ۶. تلهٔ `=` در برابر `==`

```cpp
int x = 0;
if (x = 5) {              // مقدار ۵ در x گذاشته می‌شود و شرط همیشه درست است
    std::cout << "همیشه اجرا می‌شود\n";
}
```

کامپایلر با `-Wall` معمولاً هشدار می‌دهد (`suggest parentheses around assignment used as truth value`)، اما همیشه نه. راه‌های پیشگیری:

1. `const` را جدی بگیرید: `const int x = 0;` باعث می‌شود `x = 5` خطای کامپایل بدهد.
2. مقایسه با ثابت را برعکس بنویسید: `if (5 == x)`؛ اشتباه `if (5 = x)` خطای کامپایل است.
3. هشدارهای کامپایلر را نادیده نگیرید.

## ۸. اشتباهات رایج

1. `if (x = 5)` به‌جای `==`.
2. گذاشتن `;` بعد از شرط: `if (x > 0);` بدنهٔ خالی می‌سازد.
3. فراموش کردن `break` در `switch` و ریزش ناخواسته.
4. نبودن `default` و عبور بی‌صدا از مقدار نامعتبر.
5. ترتیب غلط شرط‌ها در رتبه‌بندی (شرط عمومی قبل از خاص).
6. استفاده از `switch` روی `double` یا `std::string` (خطای کامپایل).
7. تودرتوی زیاد؛ اگر سه سطح شد، منطق را به تابع بشکنید (جلسهٔ ۷).

---

## ۹. بهترین شیوه‌ها

- شرط‌های نامعتبر را اول بررسی کنید (guard clause) و زود `return` کنید.
- بازه‌ها را با `&&` بنویسید: `score >= 0 && score <= 100`.
- برای انتخاب بین مقادیر ثابت از `switch` و `enum class` استفاده کنید.
- همیشه آکولاد بگذارید.
- `?:` را فقط برای انتخاب دو مقدار ساده به کار ببرید.

---

## ۱۰. خلاصه

- `if`/`else if`/`else` به ترتیب بررسی می‌شوند؛ اولین شرط درست اجرا می‌شود.
- `switch` برای مقادیر ثابت است و `break` ریزش را متوقف می‌کند.
- `default` و `enum class` کد را ایمن‌تر می‌کنند.
- `?:` یک عبارت است، نه دستور.
- `=` انتساب است و `==` مقایسه؛ `const` و ترتیب معکوس مقایسه از این باگ جلوگیری می‌کنند.
