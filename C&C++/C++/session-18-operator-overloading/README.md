# جلسهٔ ۱۸ — سربارگذاری عملگرها

> عملگرها فقط نحو نیستند؛ اگر `a + b` معنی روشنی داشته باشد، کد بدون توضیح خوانده می‌شود.

---

## اهداف این جلسه

1. عملگرهای حسابی (`+`، `-`، `*`) و مرکب (`+=`) را سربارگذاری کنید.
2. عملگرهای مقایسه (`==`، `!=`، `<`) را درست و سازگار پیاده کنید.
3. `operator<<` را به‌صورت **تابع آزاد** بنویسید تا `std::cout << obj` کار کند.
4. `operator[]` را در دو نسخهٔ `const` و غیر `const` بنویسید.
5. بدانید چه زمانی عملگر **عضو** است و چه زمانی **آزاد**، و کدام عملگرها را نباید سربارگذاری کرد.

---

## ۱. چرا سربارگذاری؟

بدون آن:

```cpp
Complex sum = add(multiply(a, 2.0), b);
```

با آن:

```cpp
Complex sum = a * 2.0 + b;
```

هر دو یک کار می‌کنند، ولی دومی نیاز به توضیح ندارد. سربارگذاری وقتی خوب است که عملگر **معنی طبیعی** داشته باشد: جمع برای بردار و پول و کسر، `<` برای مقایسه، `<<` برای چاپ.

قاعدهٔ اصلی: **اگر مجبورید برای فهم کد، مستندات بخوانید، عملگر را سربارگذاری نکنید.** `matrix / string` یا `person + person` تقریباً همیشه ایدهٔ بدی است.

---

## ۲. عملگر عضو در برابر عملگر آزاد

| عملگر | عضو یا آزاد؟ | دلیل |
|---|---|---|
| `+=`، `-=`، `*=` | عضو | شیء چپ را تغییر می‌دهد و به اعضا نیاز دارد |
| `+`، `-`، `*` | عضو یا آزاد | هر دو درست‌اند؛ عضو ساده‌تر است |
| `==`، `!=`، `<` | عضو یا آزاد | اگر به اعضای خصوصی نیاز دارد و getter ندارید → آزاد + friend |
| `<<`، `>>` | **فقط آزاد** | شیء چپ `std::ostream` است، نه کلاس شما |
| `[]`، `()`، `->` | **فقط عضو** | زبان اجازهٔ آزاد بودن نمی‌دهد |
| `=`، `+=` | عضو | آزاد بودن معنی ندارد |

قاعدهٔ سریع: اگر **شیء سمت چپ** متعلق به کلاس شما نیست، عملگر باید آزاد باشد.

```cpp
std::cout << money;      // شیء چپ std::ostream است → آزاد
money + other;           // شیء چپ Money است → می‌تواند عضو باشد
```

## ۳. عملگرهای حسابی

```cpp
Complex& operator+=(const Complex& other) {   // تغییر می‌دهد → reference
    real_ += other.real_;
    imaginary_ += other.imaginary_;
    return *this;
}

Complex operator+(const Complex& other) const {   // شیء تازه → با ارزش
    return Complex(real_ + other.real_, imaginary_ + other.imaginary_);
}
```

سه نکته:

1. `+=` شیء را تغییر می‌دهد، پس `const` نمی‌گیرد و `*this` برمی‌گرداند (زنجیره‌سازی، جلسهٔ ۱۷).
2. `+` شیء تازه می‌سازد، پس `const` می‌گیرد و **با ارزش** برمی‌گرداند.
3. اگر `+=` دارید، `+` را از روی آن بسازید تا منطق تکرار نشود:
   ```cpp
   Complex operator+(Complex other) const {   // کپی، سپس +=
       other += *this;
       return other;
   }
   ```

### عملگر دوطرفه

```cpp
Complex operator*(double factor) const;              // a * 2
Complex operator*(double factor, const Complex&);    // 2 * a  ← آزاد
```

برای `2 * a`، شیء چپ `double` است، پس نسخهٔ آزاد لازم است. اگر `double` را به `Complex` تبدیل‌پذیر کنید (سازندهٔ غیر `explicit`)، نسخهٔ عضو هم کار می‌کند — ولی به قیمت تبدیل‌های ضمنی غیرمنتظره. در این جلسه صریح، نسخهٔ آزاد نوشته‌ایم.

## ۴. `operator<<` — چرا آزاد و چه زمانی friend

```cpp
std::ostream& operator<<(std::ostream& out, const Money& money) {
    return out << money.toString();
}
```

- خروجی `std::ostream&` است تا زنجیرهٔ `<< a << b` کار کند.
- پارامتر `std::ostream&` **با ارزش** است: جریان کپی نمی‌شود.
- `const Money&`: چاپ، شیء را تغییر نمی‌دهد.
- `std::cerr` و `std::ostringstream` هم به‌طور خودکار کار می‌کنند، چون همه از `std::ostream` مشتق شده‌اند.

اگر کلاس getter عمومی دارد (`toString`، `cents`)، `friend` لازم نیست. اگر نه، جلسهٔ ۱۹ نشان می‌دهد `friend` چطور این دسترسی را می‌دهد — **بدون** عمومی کردن داده.

> چرا نمی‌توان `operator<<` را عضو کرد؟ چون عضو می‌شود `Money::operator<<(std::ostream&)` و باید `money << cout` بنویسید. زبان این را نمی‌پذیرد که شیء چپ، استریم باشد.

---

## ۵. `operator[]` در دو نسخه

```cpp
std::string& operator[](std::size_t index) {             // نوشتن
    return titles_.at(index);
}

const std::string& operator[](std::size_t index) const { // خواندن
    return titles_.at(index);
}
```

- نسخهٔ غیر `const` روی شیء غیر `const` انتخاب می‌شود و اجازهٔ انتساب می‌دهد.
- نسخهٔ `const` روی شیء `const` (یا `const&`) انتخاب می‌شود.
- اگر فقط نسخهٔ `const` را بنویسید، `shelf[1] = "x"` خطا می‌دهد؛ اگر فقط غیر `const` را بنویسید، روی شیء `const` نمی‌شود ایندکس گرفت.

در پیاده‌سازی از `.at()` استفاده کرده‌ایم تا اندیس نامعتبر استثنا بدهد (جلسهٔ ۱۹ به بعد دربارهٔ استثنا). `operator[]` در `std::vector` بررسی نمی‌کند؛ `at` می‌کند.

### ۶.۱ `01_complex_number.cpp`

```
a = 3 + 4i ، |a| = 5
b = 1 - 2i ، |b| = 2.23607

a + b = 4 + 2i
a - b = 2 + 6i
a * 2 = 6 + 8i
2 * b = 2 - 4i

c = a; c += b → 4 + 2i
a == c ؟ خیر
a != b ؟ بله
|a| < |b| ؟ خیر
```

دو نکته که تازه‌کارها اشتباه می‌کنند:

1. `c += b` نتیجه‌اش `4 + 2i` است، پس `a == c` نادرست است — `c` تغییر کرده، `a` نه.
2. `|a| = 5` و `|b| ≈ 2.24`، پس `a < b` نادرست است. عملگر `<` بر اساس **اندازه** تعریف شده، نه مؤلفه‌ها؛ همین تصمیم طراحی است که باید مستند شود.

## ۷. اشتباهات رایج

1. **سربارگذاری `+` به‌عنوان تغییردهنده**: `a + b` نباید `a` را عوض کند. جمع، مقدار تازه می‌سازد.
2. **برگرداندن `void` از `+=`** → زنجیره‌سازی و استفاده در عبارت ممکن نیست.
3. **`operator<<` به‌صورت عضو** → `money << cout` لازم می‌شود.
4. **فراموش کردن `return out;`** در `operator<<` → زنجیرهٔ `<<` می‌شکند (و کامپایلر خطای عجیب می‌دهد).
5. **پیاده کردن `==` بدون `!=`** یا تعریف ناسازگار (مثلاً `==` بر اساس مؤلفه و `<` بر اساس اندازه، بدون اینکه بدانید).
6. **`operator[]` بدون نسخهٔ `const`** → شیء `const` قابل ایندکس نیست.
7. **سربارگذاری `&&`، `||`، `,`** → ترتیب ارزیابی و short-circuit از بین می‌رود.
8. **سربارگذاری `new`/`delete` یا `&`** بدون دلیل جدی.
9. **تبدیل ضمنی ناخواسته** با سازندهٔ تک‌پارامتری غیر `explicit` → `Complex c = 5;` ممکن می‌شود و باگ می‌سازد.
10. **عملگرهایی با معنی غافلگیرکننده** مثل `+` برای «ادغام دو فایل»؛ به‌جایش تابع با نام `merge` بنویسید.

## ۸. بهترین شیوه‌ها

- عملگرها را **سازگار** تعریف کنید: اگر `+=` دارید، `+` هم داشته باشید؛ اگر `==` دارید، `!=` هم.
- `==` باید بازتابی (`a == a`)، متقارن و سازگار با `!=` باشد.
- عملگرهای تغییردهنده (`+=`، `++`) عضو؛ عملگرهای مقدارساز (`+`، `==`) می‌توانند عضو یا آزاد باشند.
- `<<` و `>>` همیشه آزاد و همیشه `std::ostream&`/`std::istream&` برمی‌گردانند.
- `operator[]` را دو نسخه بنویسید و در نسخهٔ خواندن `const&` برگردانید.
- عملگر را فقط وقتی اضافه کنید که معنی‌اش برای خواننده **بدیهی** باشد.
- در C++20 می‌توانید `<=>` بنویسید و بقیه را از آن بسازید؛ در این دوره با C++17 همان شش عملگر را جدا می‌نویسیم.

---

## ۹. خلاصه

- عملگر عضو وقتی که شیء چپ از کلاس شماست؛ آزاد وقتی که نیست (`<<`، `>>`).
- `+=` → `T&` و تغییردهنده؛ `+` → `T` و `const`.
- `operator<<` آزاد، با `std::ostream&` و `return out;`.
- `operator[]` دو نسخه: `T&` و `const T&`.
- عملگر بدون معنی طبیعی، کد را بدتر می‌کند.

### تمرین ۱ — کلاس `Fraction` (متوسط)

`exercises/exercise_01.cpp`: کسری که همیشه ساده است و علامت منفی‌اش روی صورت می‌نشیند.

```cpp
Fraction(int numerator, int denominator);   // 6/8 → 3/4 ، 1/-2 → -1/2
Fraction operator+(const Fraction& other) const;
Fraction operator*(const Fraction& other) const;
bool operator==(const Fraction& other) const;
bool operator<(const Fraction& other) const;
friend std::ostream& operator<<(std::ostream& out, const Fraction& f);
```

```
6/8 ساده‌شده → 3/4
1/-2 → -1/2

1/2 + 1/3 = 5/6
1/2 * 2/3 = 1/3

1/2 == 1/2 ؟ بله
1/3 < 1/2 ؟ بله
```

سه نکته:

1. **`normalize()` در سازنده**: هر کسر، بعد از ساخت، در شکل استاندارد است. به همین دلیل `2/4 == 1/2` بدون مقایسهٔ ضرب‌درضرب درست کار می‌کند.
2. **علامت**: اگر مخرج منفی باشد، هر دو را در `-1` ضرب کنید؛ هیچ‌وقت `-1/-2` را با مخرج منفی نگه ندارید.
3. **مخرج صفر**: در این جلسه با جایگزین امن (`1`) مدیریت شده؛ در جلسهٔ ۲۶ همین حالت به استثنا تبدیل می‌شود.
