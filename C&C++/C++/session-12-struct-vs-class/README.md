# جلسهٔ ۱۲ — `struct` در برابر `class`

> تا حالا داده و تابع از هم جدا بودند. شیءگرایی می‌گوید: داده و رفتارِ متعلق به آن داده باید در یک واحد زندگی کنند.

---

## اهداف این جلسه

1. `struct` را در C++ (نه C) بشناسید: داده + تابع عضو.
2. کلاس ساده با بخش عمومی و خصوصی بنویسید.
3. بدانید تنها تفاوت واقعی `struct` و `class` **دسترسی پیش‌فرض** است.
4. عرف طراحی را یاد بگیرید: کِی `struct` و کِی `class`.
5. بفهمید هر شیء حافظهٔ مستقل خودش را دارد.

---

## ۱. چرا شیء؟

فرض کنید می‌خواهید یک نقطه را نگه دارید:

```cpp
double x = 3.0;
double y = 4.0;
```

و ۱۰۰ نقطه؟ ده آرایهٔ موازی؟ و تابع فاصله؟ `distance(x1, y1, x2, y2)` با چهار پارامتر و احتمال جابه‌جا شدن آرگومان‌ها.

با `struct`:

```cpp
Point a{3.0, 4.0};
double d = a.distanceTo(b);    // نقطه و رفتارش کنار هم
```

این همان **کپسوله‌سازی** است: «چه داده‌ای» و «چه کارهایی روی آن» یک واحد منسجم.

---

## ۲. `struct` در C++

`struct` در C++ چیزی بیش از C است: می‌تواند **تابع عضو** داشته باشد، عضو با مقدار پیش‌فرض، و بعداً سازنده و وراثت هم (جلسه‌های بعد).

```cpp
struct Point {
    double x = 0.0;
    double y = 0.0;

    void print() const {                       // متد const
        std::cout << "(" << x << ", " << y << ")\n";
    }

    double distanceTo(const Point& other) const {
        const double dx = x - other.x;
        const double dy = y - other.y;
        return std::sqrt(dx * dx + dy * dy);
    }
};
```

نکات مهم:

- داخل متد، به اعضا **بدون** `a.x` دسترسی دارید؛ نام عضو مستقیم در دسترس است.
- `const` بعد از فهرست پارامتر یعنی «این متد شیء را تغییر نمی‌دهد». روی شیء `const` فقط متد `const` قابل فراخوانی است (جلسهٔ ۴۱ کامل).
- مترجم برای پارامترهای بزرگ `const Point&` داده‌ایم تا کپی نشود.

### ساخت و مقداردهی

```cpp
Point origin{};          // x = 0, y = 0
Point a{3.0, 4.0};       // x = 3, y = 4
Point b{1.0};            // y مقدار پیش‌فرض 0.0 را می‌گیرد
Point c = a;             // کپی مستقل
```

این شکل `{}` **مقداردهی آگریگیت** نام دارد و برای `struct`های بدون سازندهٔ نوشته‌شده کار می‌کند.

### کپی، کپی مستقل است

```cpp
Point copy = a;
copy.x = 100.0;    // a تغییر نمی‌کند
```

`struct` نوع **مقداری** است: انتساب، همهٔ اعضا را کپی می‌کند.

## ۳. کلاس ساده

```cpp
class Counter {
public:
    void increment() { ++count_; }
    int value() const { return count_; }
    void reset() { count_ = 0; }

private:
    int count_ = 0;
};
```

`public` یعنی «از بیرون قابل استفاده»، `private` یعنی «فقط اعضای همین کلاس». استفاده:

```cpp
Counter counter;
counter.increment();
std::cout << counter.value();   // 1

counter.count_ = 100;           // ❌ خطای کامپایل
```

### چرا `private`؟

چون می‌خواهید **قاعده‌های داخلی** را حفظ کنید. اگر `count_` عمومی بود، کسی می‌توانست آن را منفی کند و بعد `value()` عدد بی‌معنی بدهد. با `private`، تنها راه تغییر از مسیر متدهای شماست، پس هر تغییری از فیلتر شما می‌گذرد.

این موضوع در جلسهٔ ۱۳ (کپسوله‌سازی) محور اصلی است.

### پسوند `_` برای اعضای خصوصی

عرف رایج: اعضای دادهٔ خصوصی با `count_` (زیرخط انتهایی) یا `m_count` نام‌گذاری شوند تا از متغیرهای محلی و پارامترها قابل تشخیص باشند:

```cpp
void setValue(int value) {
    value_ = value;      // بدون _، این خط خودش را به خودش انتساب می‌داد!
}
```

## ۴. تفاوت واقعی: دسترسی پیش‌فرض

```cpp
struct PublicByDefault {
    int value = 0;      // public
};

class PrivateByDefault {
    int value = 0;      // private
};
```

همین. تمام تفاوت زبان همین است:

| | `struct` | `class` |
|---|---|---|
| دسترسی پیش‌فرض اعضا | `public` | `private` |
| دسترسی پیش‌فرض وراثت | `public` | `private` |
| سازنده/مخرب | ✅ | ✅ |
| متد و `static` | ✅ | ✅ |
| می‌تواند `private` داشته باشد | ✅ | ✅ |

و برعکسش هم کاملاً قانونی است:

```cpp
struct WithPrivate {
public:
    int id = 1;
private:
    int secret = 42;
};

class AllPublic {
public:
    int value = 0;
};
```

پس `struct` و `class` **دو نوع متفاوت نیستند**؛ دو پیش‌فرض متفاوت برای یک چیز.

---

## ۵. عرف طراحی: کدام را انتخاب کنم؟

| انتخاب | چه وقت | نمونه |
|---|---|---|
| `struct` | فقط داده، بدون قاعده؛ مثل «رکورد» | `Point`، `Size`، `Config`، پارامترهای چندگانه |
| `class` | داده + قاعده (invariant) + رابط کنترل‌شده | `BankAccount`، `Counter`، `Student` با اعتبارسنجی |

قاعدهٔ ساده:

- اگر همهٔ اعضا می‌توانند هر مقداری داشته باشند و هیچ ترکیبی «نامعتبر» نیست → `struct`.
- اگر بین اعضا رابطه‌ای وجود دارد که باید همیشه برقرار بماند (مثلاً `balance >= 0`) → `class` با اعضای خصوصی.

`std::string` و `std::vector` کلاس‌اند (invariant دارند). `std::pair` و `std::tuple` struct-مانند هستند.

## ۶. هر شیء، حافظهٔ خودش

```cpp
std::vector<Counter> counters(3);
counters[0].add(10);
counters[1].add(20);
// counters[2] هنوز صفر است
```

کلاس مثل **قالب** است و هر شیء یک نمونهٔ مستقل با حافظهٔ خودش. `sizeof(Counter)` اندازهٔ یک نمونه است، نه تعداد نمونه‌ها.

## ۸. اشتباهات رایج

1. **فراموش کردن `;` بعد از `}` تعریف کلاس/ساختار** → خطاهای عجیب در خط بعد.
2. **تصور اینکه `struct` فقط داده دارد** — در C++ می‌تواند متد، سازنده و وراثت داشته باشد.
3. **عمومی گذاشتن همه‌چیز** در کلاسی که قاعده دارد؛ بعداً نمی‌توانید مطمئن باشید وضعیت معتبر است.
4. **هم‌نام بودن عضو و متد** → خطای کامپایل.
5. **`const` نگذاشتن روی متدهای فقط‌خواندنی** → روی شیء `const` قابل فراخوانی نیستند.
6. **کپی کردن شیءهای بزرگ به‌جای `const&`** در پارامترها.
7. **مقایسهٔ دو `struct` با `==`** بدون تعریف عملگر؛ برای `struct`های ساده `==` وجود ندارد (جلسهٔ ۱۸).

---

## ۹. بهترین شیوه‌ها

- داده بدون قاعده → `struct`؛ داده با قاعده → `class`.
- اعضا را `private` بگذارید و فقط لازم‌ترین‌ها را `public` کنید.
- متدهای فقط‌خواندنی را `const` کنید — از ابتدا، نه بعداً.
- اعضای خصوصی را با `_` پایانی نام‌گذاری کنید.
- یک کلاس = یک مسئولیت.
- تعریف کلاس کوچک را همان‌جا بنویسید؛ کلاس بزرگ را در هدر جدا ببرید (جلسهٔ ۴۳).

---

## ۱۰. خلاصه

- `struct` و `class` یک چیزند با دو دسترسی پیش‌فرض متفاوت.
- تفاوت واقعی: `public` در `struct`، `private` در `class`.
- `struct` = رکورد داده؛ `class` = داده + قاعده.
- متد `const` وضعیت را تغییر نمی‌دهد و روی شیء `const` قابل فراخوانی است.
- هر شیء حافظهٔ مستقل دارد؛ کلاس قالب است.
