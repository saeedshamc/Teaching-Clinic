# جلسهٔ ۲۰ — مبانی وراثت

> وراثت رابطهٔ «is-a» است، نه راهی برای کم کردن تایپ.

---

## اهداف این جلسه

1. وراثت عمومی را بنویسید: `class Dog : public Animal`.
2. بفهمید چه چیزی ارث می‌رسد، چه چیزی نه، و `protected` دقیقاً کجا به کار می‌آید.
3. سازندهٔ پایه را در لیست مقداردهی صدا بزنید و ترتیب ساخت/تخریب را ببینید.
4. انواع وراثت (`public`/`protected`/`private`) را بشناسید.
5. بدانید چه زمانی وراثت **غلط** است و ترکیب (composition) بهتر است.

---

## ۱. وراثت چیست؟

```cpp
class Animal {
public:
    Animal(const std::string& name, int age);
    const std::string& name() const;
    int age() const;
protected:
    void setAge(int age);
private:
    std::string name_;
    int age_;
};

class Dog : public Animal {
public:
    Dog(const std::string& name, int age, const std::string& breed)
        : Animal(name, age), breed_(breed) { }
private:
    std::string breed_;
};
```

`Dog` **همهٔ** اعضای `Animal` را دارد — از نظر حافظه، یک `Dog` شامل یک `Animal` است به‌علاوهٔ `breed_`. به همین دلیل:

```cpp
Dog dog("رکس", 3, "ژرمن شپرد");
dog.name();     // عضو پایه، از طریق مشتق
```

`Animal` را **کلاس پایه** (base) و `Dog` را **کلاس مشتق** (derived) می‌نامیم.

---

## ۲. چه چیزی ارث می‌رسد؟

| عضو پایه | در مشتق | از بیرون |
|---|---|---|
| `public` | در دسترس | در دسترس |
| `protected` | در دسترس | ❌ ممنوع |
| `private` | ❌ ممنوع | ❌ ممنوع |
| سازنده/مخرب | ساخته می‌شوند، ولی **ارث نمی‌رسند** | — |
| `friend` | ❌ ارث نمی‌رسد | — |
| عملگر `=` | خودکار تولید می‌شود | — |

دو نکته که تازه‌کارها اشتباه می‌کنند:

1. **`private` پایه، حتی برای مشتق هم ممنوع است.** اگر `Dog` لازم دارد `age_` را تغییر دهد، یا باید `protected` باشد یا از setter عمومی/محافظت‌شده استفاده کند.
2. **سازنده‌ها ارث نمی‌رسند**، ولی در C++11 می‌شود با `using Base::Base;` آن‌ها را «وارد کرد» — موضوع پیشرفته‌تر.

در کد این جلسه، `setAge` را `protected` گذاشته‌ایم تا `Dog` بتواند در `celebrateBirthday()` سن را زیاد کند، بدون اینکه `main` بتواند مستقیم سن را دستکاری کند.

---

## ۳. سازندهٔ پایه — اجباری و صریح

```cpp
Dog(const std::string& name, int age, const std::string& breed)
    : Animal(name, age),       // ← همیشه اول
      breed_(breed) {
}
```

- اگر سازندهٔ پایه پارامتری است و در لیست ننویسید، خطای کامپایل می‌گیرید: «no matching function for call to Animal()».
- اگر سازندهٔ پایه پیش‌فرض داشته باشد و ننویسید، **سازندهٔ پیش‌فرض پایه** صدا زده می‌شود — که گاهی همان چیزی نیست که می‌خواهید.
- ترتیب ساخت: **پایه → اعضای مشتق (به ترتیب اعلان) → بدنهٔ سازندهٔ مشتق**.
- ترتیب تخریب: **بدنهٔ مشتق → اعضای مشتق (معکوس) → پایه**.

خروجی واقعی `02_base_constructor.cpp`:

```
  ساخت Base(پایه:abc)
  ساخت بدنهٔ Derived(abc)
  دسترسی به tag_ از protected: پایه:abc

tag از بیرون: پایه:abc ، payload: 3

--- پایان بلوک ---
  تخریب بدنهٔ Derived
  تخریب Base(پایه:abc)
```

این ترتیب را در جلسهٔ ۱۴ برای اعضا دیدید؛ حالا پایه هم به آن اضافه شده است.

---

## ۴. سه نوع وراثت

```cpp
class A : public Base { };      // رایج‌ترین: is-a واقعی
class B : protected Base { };   // Base برای B نقش private دارد
class C : private Base { };     // «implemented in terms of»
```

| نوع | `public` پایه در مشتق می‌شود | کاربرد |
|---|---|---|
| `public` | `public` | رابطهٔ is-a؛ تبدیل `Dog*` به `Animal*` مجاز |
| `protected` | `protected` | نادر |
| `private` | `private` | نادر؛ معمولاً ترکیب بهتر است |

**همیشه `public` بنویسید، مگر دلیل روشنی داشته باشید.** اگر `class Dog : Animal` بنویسید (بدون کلمهٔ `public`)، وراثت **private** است — یکی از رایج‌ترین اشتباهات، مخصوصاً برای کسانی که از `struct` استفاده می‌کنند (که پیش‌فرضش `public` است).

---

## ۵. `is-a` در برابر `has-a`

وراثت فقط وقتی درست است که جملهٔ «B یک A است» واقعاً برقرار باشد:

| رابطه | درست؟ | جایگزین |
|---|---|---|
| `Dog` یک `Animal` است | ✅ | وراثت |
| `Car` یک `Vehicle` است | ✅ | وراثت |
| `Car` یک `Engine` است | ❌ | عضو `Engine engine_;` |
| `Stack` یک `vector` است | ❌ (پیاده‌سازی با آن) | عضو `std::vector<T> data_;` |
| `Employee` یک `Person` است | ✅ | وراثت |
| `Person` یک `Date` است | ❌ | عضو `Date birthDate_;` |

اگر وراثت را برای «استفادهٔ دوبارهٔ کد» انتخاب کنید، به دام می‌افتید: هر تغییری در پایه، همهٔ مشتق‌ها را تحت تأثیر می‌گذارد و رابط پایه پر از چیزهایی می‌شود که بعضی مشتق‌ها نمی‌خواهند. ترکیب، مرز روشن‌تری دارد.

### ۶.۱ `01_animal_dog.cpp`

```
رکس (3 ساله) — صدا: واق واق
ملوس (2 ساله) — صدا: میو

نژاد سگ: ژرمن شپرد

قبل از تولد: 1
بعد از تولد: 2

--- از طریق Animal& ---
رکس صدا: ...
  (توجه: sound() اینجا هنوز نسخهٔ Animal است — جلسهٔ ۲۲)
```

خط آخر مهم‌ترین خط این جلسه است:

```cpp
const Animal& asAnimal = dog;
asAnimal.sound();        // "..." نه "واق واق"
```

`sound()` در `Animal` `virtual` نیست، پس انتخاب تابع در **زمان کامپایل** بر اساس **نوع اعلان‌شده** (`Animal&`) انجام می‌شود، نه نوع واقعی شیء (`Dog`). این «binding ایستا» است و جلسهٔ ۲۲ با `virtual` آن را به binding پویا تبدیل می‌کند.

### ۶.۲ `02_base_constructor.cpp`

```
--- شروع ---
  ساخت Base(پایه:abc)
  ساخت بدنهٔ Derived(abc)
  دسترسی به tag_ از protected: پایه:abc

tag از بیرون: پایه:abc ، payload: 3

--- پایان بلوک ---
  تخریب بدنهٔ Derived
  تخریب Base(پایه:abc)
--- بعد از بلوک ---
```

- `payload_(tag.size())` مقدار `3` داد، چون `"abc"` سه کاراکتر است.
- `tag_` را از `protected` در بدنهٔ `Derived` خواندیم، ولی `main` نمی‌تواند (`object.tag_ = ...` خطای کامپایل).
- مخرب `Derived` **قبل از** مخرب `Base` اجرا شد. اگر مخرب پایه `virtual` نباشد و شیء با `Base*` حذف شود، مخرب مشتق اجرا نمی‌شود — جلسهٔ ۲۲.

---

## ۷. اشتباهات رایج

1. **فراموش کردن `public`** در `class Dog : Animal` → وراثت private و خطاهای عجیب در تبدیل نوع.
2. **صدا زدن سازندهٔ پایه در بدنه** به‌جای لیست مقداردهی — ممکن نیست؛ سازنده، تابع معمولی نیست.
3. **دسترسی به `private` پایه از مشتق** → خطای کامپایل. راه درست: `protected` یا متد عمومی.
4. **انتظار ارث‌بری سازنده‌ها/`friend`ها**.
5. **وراثت برای استفادهٔ دوبارهٔ کد** بدون رابطهٔ is-a → رابط پایه شلوغ و شکننده.
6. **مخرب غیر virtual در پایه** و حذف از طریق `Base*` → نشت منابع (جلسهٔ ۲۲).
7. **نگه‌داشتن `std::vector<Animal>` برای `Dog` و `Cat`** → برش شیء (object slicing، جلسهٔ ۲۲).
8. **وراثت چندسطحی عمیق** برای «کمی کد مشترک» → سلسله‌مراتب شکننده.
9. **`protected` کردن داده به‌جای متد** → زیرکلاس‌ها به internals وابسته می‌شوند؛ همان مشکل `public`، کمی پنهان‌تر.

---

## ۸. بهترین شیوه‌ها

- وراثت را فقط برای رابطهٔ **is-a** به کار ببرید؛ در شک، ترکیب را انتخاب کنید.
- همیشه `public` بنویسید (صریح).
- اعضای داده را `private` نگه دارید؛ اگر زیرکلاس لازم دارد، متد `protected` بدهید، نه داده.
- سازندهٔ پایه را همیشه در لیست مقداردهی صدا بزنید.
- مخرب پایه را وقتی از طریق اشاره‌گر پایه حذف می‌کنید `virtual` کنید (جلسهٔ ۲۲).
- کلاس پایه را کوچک و با invariant روشن نگه دارید.
- اگر کلاس پایه فقط برای «کد مشترک» است و شیء مستقیم از آن ساخته نمی‌شود، احتمالاً کلاس انتزاعی می‌خواهید (جلسهٔ ۲۳).

---

## ۹. خلاصه

- `class Derived : public Base` رابطهٔ is-a می‌سازد.
- `public` ارث می‌رسد و از بیرون دیده می‌شود؛ `protected` فقط برای مشتق؛ `private` هیچ‌کس.
- سازندهٔ پایه اول اجرا می‌شود؛ مخرب پایه آخر.
- سازنده‌ها و `friend`ها ارث نمی‌رسند.
- وراثت برای is-a، ترکیب برای has-a.

## ۱۰. تمرین‌ها

### تمرین ۱ — `Vehicle` و `Car` (متوسط)

`exercises/exercise_01.cpp`: پایه‌ای با برند و تعداد چرخ، مشتقی با تعداد در.

```cpp
class Vehicle {
public:
    Vehicle(const std::string& brand, int wheels);
    std::string type() const;      // "وسیلهٔ نقلیه"
    void print() const;            // برند، چرخ، نوع
protected:
    void setWheels(int count);     // فقط > 0
};

class Car : public Vehicle {
public:
    Car(const std::string& brand, int doors);   // پایه با 4 چرخ
    std::string type() const;                   // "خودرو"
};
```

```
وسیلهٔ نقلیه: دوچرخ ، چرخ = 2 ، نوع = وسیلهٔ نقلیه
وسیلهٔ نقلیه: پژو ، چرخ = 4 ، نوع = وسیلهٔ نقلیه
تعداد درها: 4
چرخ‌های خودرو بعد از تغییر: 5
از طریق Vehicle& : نوع = وسیلهٔ نقلیه
```

خط دوم را با دقت ببینید: با اینکه `car.type()` از بیرون `"خودرو"` می‌دهد، `print()` که در پایه نوشته شده، نسخهٔ **پایه** را صدا می‌زند. این دقیقاً همان محدودیت binding ایستاست. اگر بخواهید `print()` نسخهٔ درست را نشان دهد، `type()` باید `virtual` شود — جلسهٔ ۲۲.
