# جلسهٔ ۷ — توابع، پارامتر پیش‌فرض و overloading

> هر برنامهٔ بزرگ از تابع‌های کوچک ساخته می‌شود. این جلسه مرز بین «کد اسکریپتی» و «کد قابل نگهداری» است.

---

## اهداف این جلسه

1. تابع را اعلان و تعریف کنید و تفاوت این دو را بدانید.
2. تابع `void` و تابع با مقدار بازگشتی بنویسید.
3. پارامتر پیش‌فرض تعریف کنید و محدودیت‌هایش را بشناسید.
4. با overloading چند نسخه از یک نام بسازید و بدانید کامپایلر چطور انتخاب می‌کند.
5. دامنهٔ متغیرها (local در برابر global) را درک کنید.
6. دلیل وجود توابع در C++ نسبت به C را بفهمید.

---

## ۱. چرا تابع؟

تا جلسهٔ ۶ همهٔ کد در `main` بود. مشکل:

- کد تکراری (همان محاسبه را ده بار می‌نویسید).
- `main` صدها خط می‌شود و خواندنش سخت است.
- تست کردن یک بخش خاص ممکن نیست.

تابع این‌ها را حل می‌کند: یک قطعهٔ منطقی را **یک‌بار** می‌نویسید، **نام** می‌گذارید و هر جا لازم شد صدایش می‌زنید.

```cpp
int square(int value) {     // تعریف
    return value * value;
}
```

اجزای تابع:

| جزء | در مثال | نقش |
|---|---|---|
| نوع بازگشتی | `int` | نوع مقداری که برمی‌گردد |
| نام | `square` | شناسه‌ای که با آن صدا می‌زنیم |
| فهرست پارامتر | `(int value)` | ورودی‌های تابع |
| بدنه | `{ ... }` | کاری که انجام می‌شود |
| `return` | `return value * value;` | مقدار خروجی |

---

## ۲. اعلان (prototype) در برابر تعریف

کامپایلر فایل را از بالا به پایین می‌خواند. اگر تابع را **قبل** از تعریفش صدا بزنید، باید از قبل بداند چه شکلی دارد:

```cpp
double average(double a, double b);   // اعلان: فقط امضا، بدون بدنه

int main() {
    std::cout << average(12.5, 17.5);  // حالا مجاز است
}

double average(double a, double b) {   // تعریف: بدنه
    return (a + b) / 2.0;
}
```

- **اعلان** = «چنین تابعی وجود دارد با این امضا».
- **تعریف** = اعلان + بدنه.

در فایل‌های چندبخشی (جلسهٔ ۴۳) اعلان‌ها در هدر و تعریف‌ها در `.cpp` می‌روند.

> **نکته:** اگر امضای اعلان و تعریف یکی نباشد (مثلاً `int` در برابر `double`)، لینکر خطای `undefined reference` می‌دهد. همیشه هدر را یک منبع حقیقت نگه دارید.

## ۳. تابع `void`

تابعی که چیزی برنمی‌گرداند `void` است:

```cpp
void printLine(int count, char fill) {
    for (int i = 0; i < count; ++i) {
        std::cout << fill;
    }
    std::cout << "\n";
}
```

`return` در تابع `void` فقط اجرا را قطع می‌کند و مقدار ندارد:

```cpp
void printSign(int value) {
    if (value > 0) {
        std::cout << value << " مثبت است.\n";
        return;                  // خروج زودهنگام، بدون مقدار
    }
    ...
}
```

## ۴. دامنهٔ متغیر

هر متغیری که داخل تابع تعریف شود **محلی** است: فقط داخل همان تابع دیده می‌شود و با پایان فراخوانی از بین می‌رود.

```cpp
int nextId() {
    int id = 0;   // هر فراخوانی این متغیر را از نو می‌سازد
    ++id;
    return id;
}
```

دو بار `nextId()` همیشه `1` می‌دهد، چون متغیر بین فراخوانی‌ها زنده نمی‌ماند. برای حفظ وضعیت بین فراخوانی‌ها بعداً `static` (جلسهٔ ۱۶) و کلاس (فاز ۳) می‌آید.

**متغیر global** (خارج از همهٔ توابع) از همه‌جا دیده می‌شود، اما استفاده از آن تقریباً همیشه اشتباه طراحی است: وابستگی پنهان می‌سازد و تست را سخت می‌کند. پیش‌فرض درست: **همه‌چیز محلی**.

---

## ۵. پارامتر پیش‌فرض

می‌توانید برای پارامترها مقدار پیش‌فرض بگذارید تا فراخوانی ساده‌تر شود:

```cpp
std::string makeGreeting(const std::string& name,
                         const std::string& greeting = "سلام",
                         const std::string& suffix = "!");
```

سه شکل فراخوانی، همه معتبر:

```cpp
makeGreeting("Saeed");                  // سلام Saeed!
makeGreeting("Saeed", "درود");          // درود Saeed!
makeGreeting("Saeed", "درود", ".");     // درود Saeed.
```

قواعد مهم:

1. پارامترهای پیش‌فرض باید **از راست به چپ** باشند. این غلط است:
   ```cpp
   void f(int a = 1, int b);   // خطا
   ```
2. نمی‌توانید پارامتر وسطی را رد کنید:
   ```cpp
   makeGreeting("Saeed", , "?");   // خطا
   ```
3. مقدار پیش‌فرض فقط **یک‌بار** نوشته می‌شود؛ اگر اعلان دارید، در اعلان بنویسید و در تعریف تکرار نکنید:
   ```cpp
   void f(int a = 5);      // اعلان
   void f(int a) { }       // تعریف، بدون ۵
   ```

> لازم نیست مقدار پیش‌فرض حتماً «صفر» یا «کوچک‌ترین» باشد؛ آن را طوری انتخاب کنید که **رایج‌ترین حالت** را پوشش دهد.

## ۶. Overloading (چندنسخه‌ای کردن)

در C++ می‌توانید چند تابع **هم‌نام** داشته باشید، به شرطی که **امضا** متفاوت باشد:

```cpp
int    maxOf(int a, int b);
double maxOf(double a, double b);
int    maxOf(int a, int b, int c);
```

این سه تابع مستقل‌اند؛ کامپایلر از روی نوع و تعداد آرگومان‌ها نسخهٔ درست را انتخاب می‌کند:

```cpp
maxOf(3, 9);        // نسخهٔ int دوتایی
maxOf(3.5, 9.25);   // نسخهٔ double دوتایی
maxOf(4, 11, 7);    // نسخهٔ int سه‌تایی
```

### چه چیزی امضا را متفاوت می‌کند؟

| تفاوت | معتبر است؟ |
|---|---|
| تعداد پارامترها | ✅ |
| نوع پارامترها | ✅ |
| `const` روی پارامتر مرجع (`T&` در برابر `const T&`) | ✅ |
| **فقط** نوع بازگشتی | ❌ |

```cpp
int    f(int x);
double f(int x);   // خطا: فقط نوع بازگشتی فرق دارد
```

دلیل: در فراخوانی `f(3)` معلوم نیست کدام را می‌خواهید.

### کامپایلر چطور انتخاب می‌کند؟

به ترتیب اولویت:

1. **تطابق دقیق** (exact match)
2. **ارتقا** (promotion: `char` → `int`، `float` → `double`)
3. **تبدیل استاندارد** (conversion: `int` → `double`)
4. اگر دو نسخه در یک سطح باشند → **مبهم (ambiguous)** و خطای کامپایل.

```cpp
void show(int value);
void show(double value);
void show(const std::string& value);

show('A');     // char با promotion به int می‌رود → "int: 65"
show(3.14);    // تطابق دقیق با double
```

اما این فراخوانی مبهم است، چون `long` هم به `int` و هم به `double` تبدیل استاندارد دارد:

```cpp
// maxOf(2, 3L);   → خطای کامپایل: ambiguous call
```

### overloading در برابر C

در C فقط یک تابع با یک نام می‌تواند وجود داشته باشد، چون نام‌ها در سطح لینکر بدون اطلاعات نوع mangling نمی‌شوند. C++ **name mangling** انجام می‌دهد و امضا را داخل نام نماد کد می‌کند؛ به همین دلیل `maxOf(int,int)` و `maxOf(double,double)` می‌توانند کنار هم باشند.

همین موضوع یک نکتهٔ عملی دارد: برای صدا زدن تابع C از C++ باید `extern "C"` بگذارید تا mangling نشود.

### ۷.۳ `03_overloading.cpp`

```cpp
int maxOf(int a, int b, int c) {

}
```

این الگو (پیاده‌سازی نسخهٔ سه‌تایی روی دوتایی) هم کد را کم می‌کند و هم یک تمرین خوب برای فهم overloading است.

## ۸. اشتباهات رایج

1. **فراموش کردن `return`** در تابعی که نوع بازگشتی‌اش `void` نیست → رفتار تعریف‌نشده (بیشتر کامپایلرها هشدار `control reaches end of non-void function` می‌دهند).
2. **`;` بعد از امضای تابع**: `int f(int x) { return x; };` — این یک تعریف معتبر است ولی `;` اضافه، عادت بدی است که در هدرها خطای عجیب می‌سازد.
3. **پیش‌فرض در تعریف و اعلان هر دو** → خطای `redefinition of default argument`.
4. **پارامتر پیش‌فرض در میانهٔ فهرست** بدون پیش‌فرض برای بقیه → خطا.
5. **overloading فقط با نوع بازگشتی** → خطا.
6. **فراخوانی مبهم** با تبدیل‌های ضمنی (`0` می‌تواند به pointer تبدیل شود و ابهام بسازد).
7. **کپی کردن آرگومان‌های بزرگ**: `std::string` را با `const&` بگیرید، نه با مقدار.
8. **استفاده از متغیر global** به‌جای پارامتر؛ تابع را غیرقابل‌تست می‌کند.

## ۹. بهترین شیوه‌ها

- یک تابع = یک کار. اگر نام تابع «و» دارد (`readAndValidateAndSave`)، آن را بشکنید.
- نام تابع **فعل** باشد: `calculateAverage`، `printReport`، `isValid`.
- ورودی‌های تغییرنکردنی را `const&` بگیرید (جلسهٔ ۸ کامل توضیح می‌دهد).
- بدنه را کوتاه نگه دارید؛ بیشتر از ۲۰ تا ۳۰ خط یعنی احتمالاً دو تابع است.
- پیش‌فرض‌ها را برای «رایج‌ترین حالت» بگذارید، نه برای پنهان کردن پیچیدگی.
- overloading را وقتی به کار ببرید که **معنی** یکی است (`maxOf`)، نه وقتی رفتار متفاوت است (`save` برای فایل و شبکه) — آنجا نام متفاوت بگذارید.

## ۱۰. خلاصه

- تابع: امضا + بدنه؛ اعلان قبل از استفاده لازم است.
- `void` یعنی بدون مقدار بازگشتی؛ `return;` اجرا را قطع می‌کند.
- پارامتر پیش‌فرض از راست به چپ، فقط یک‌بار در اعلان.
- overloading با تعداد/نوع پارامتر ممکن است، نه با نوع بازگشتی.
- انتخاب نسخه: تطابق دقیق > ارتقا > تبدیل؛ دو گزینهٔ هم‌سطح = ابهام.
- متغیر محلی بین فراخوانی‌ها زنده نمی‌ماند.
