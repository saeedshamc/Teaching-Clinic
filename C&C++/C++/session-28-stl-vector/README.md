# جلسهٔ ۲۸ — بررسی عمیق `std::vector`

> `size` چیزی است که دارید؛ `capacity` چیزی است که برایش جا گرفته‌اید. تفاوتشان همهٔ کارایی `vector` است.

---

## اهداف این جلسه

1. تفاوت `size` و `capacity` را بفهمید و با `reserve` کنترلش کنید.
2. بدانید رشد `vector` چطور و با چه هزینه‌ای انجام می‌شود.
3. `insert`/`erase` در میانه و هزینهٔ جابه‌جایی را اندازه بگیرید.
4. `emplace_back` را در برابر `push_back` بگذارید.
5. بدانید کدام عملیات تکرارگر را نامعتبر می‌کند.

---

## ۱. `size` در برابر `capacity`

`vector` دو عدد دارد:

- `size()`: تعداد عناصری که **واقعاً** دارد.
- `capacity()`: تعداد عناصری که **بدون تخصیص دوباره** جا می‌شود.

```cpp
std::vector<int> v;
v.push_back(10);   // size = 1، capacity = 1
v.push_back(20);   // size = 2، capacity = 2
v.push_back(30);   // size = 3، capacity = 4  ← رشد!
```

وقتی `size` به `capacity` برسد، `vector`:

1. حافظهٔ جدید بزرگ‌تر می‌گیرد (در `libstdc++` معمولاً دو برابر).
2. همهٔ عناصر را به حافظهٔ جدید **منتقل/کپی** می‌کند.
3. حافظهٔ قبلی را آزاد می‌کند.

پس `push_back` **معمولاً** `O(1)` است، ولی وقتی رشد رخ دهد `O(n)`. چون رشد دوباره‌دوباره بزرگ‌تر می‌شود، هزینهٔ سرشکن (amortized) همان `O(1)` می‌ماند.

---

## ۲. `reserve` — حذف رشدهای میانی

اگر تعداد تقریبی عناصر را می‌دانید، یک بار جا بگیرید:

```cpp
std::vector<int> v;
v.reserve(1000);          // یک تخصیص، صفر کپی
for (int i = 0; i < 1000; ++i) {
    v.push_back(i);
}
```

نکات:

- `reserve` **اندازه را تغییر نمی‌دهد**؛ `size` صفر می‌ماند. تنها `capacity` بالا می‌رود.
- `reserve` کوچک‌تر از `capacity` فعلی هیچ کاری نمی‌کند (استاندارد اجازهٔ کم کردن نمی‌دهد).
- `resize(n)` فرق دارد: عناصر جدید **واقعاً ساخته می‌شوند** و `size` برابر `n` می‌شود.

```cpp
std::vector<int> a;
a.reserve(10);   // size = 0، capacity = 10
a.resize(10);    // size = 10، capacity = 10، ده صفر
```

---

## ۳. `shrink_to_fit`

اگر کلی عنصر حذف کردید و حافظهٔ اضافه را نمی‌خواهید:

```cpp
v.shrink_to_fit();   // درخواست، نه تضمین
```

استاندارد اجرای آن را تضمین نمی‌کند؛ در `libstdc++` معمولاً `capacity` را به `size` می‌رساند. اگر می‌خواهید قطعی باشد، الگوی مطمئن:

```cpp
std::vector<int>(v).swap(v);   // کپی دقیق + جابه‌جایی
```

---

## ۴. درج و حذف در میانه

`vector` پیوسته است. `insert` در اندیس `i` باید همهٔ عناصر بعد از `i` را یک خانه جلو ببرد؛ `erase` برعکس. پس هر دو `O(n)` هستند.

```cpp
std::vector<int> values{10, 20, 30, 40, 50};
values.insert(values.begin() + 1, 15);   // [10, 15, 20, 30, 40, 50]
values.erase(values.begin() + 3);        // [10, 15, 20, 40, 50]
```

### حذف در حلقه — تلهٔ کلاسیک

```cpp
for (auto it = values.begin(); it != values.end(); ++it) {
    if (*it > 30) {
        values.erase(it);      // ❌ it نامعتبر شد، بعد ++it روی آن → رفتار تعریف‌نشده
    }
}
```

درست:

```cpp
for (auto it = values.begin(); it != values.end();) {
    if (*it > 30) {
        it = values.erase(it);   // ✅ erase تکرارگر بعدی را برمی‌گرداند
    } else {
        ++it;
    }
}
```

`erase` تکرارگر عنصر بعدی را برمی‌گرداند؛ بعد از حذف **نباید** `++` بزنید.

## ۵. `emplace_back` در برابر `push_back`

- `push_back(x)`: `x` را می‌گیرد (کپی یا انتقال) و در انتها می‌گذارد.
- `emplace_back(args...)`: شیء را **درجا** با آرگومان‌ها می‌سازد؛ نه شیء موقت، نه کپی.

در `examples/03_emplace.cpp` یک `struct Item` داریم که سازنده و سازندهٔ کپی‌اش چاپ می‌کنند:

```
--- push_back ---
  ساخت: خودکار
  کپی: خودکار
--- emplace_back ---
  ساخت: دفتر
--- push_back با شیء موجود (کپی) ---
  ساخت: پاک‌کن
  کپی: پاک‌کن
```

`push_back(Item("خودکار", 10))` اول یک موقت ساخت و بعد کپی کرد؛ `emplace_back("دفتر", 5)` فقط ساخت. برای `std::string` و اشیای سنگین این تفاوت واقعی است.

`push_back(pen)` با شیء موجود همچنان کپی می‌کند — و این درست است؛ `pen` باید بعد از فراخوانی سالم بماند. اگر دیگر به `pen` نیاز ندارید، `std::move(pen)` کپی را به انتقال تبدیل می‌کند (جلسهٔ ۳۷).

---

## ۶. نامعتبر شدن تکرارگر

| عملیات | تکرارگرها |
|---|---|
| `push_back` بدون رشد | معتبر می‌مانند |
| `push_back` با رشد | همه نامعتبر (حافظه عوض شد) |
| `insert`/`erase` در میانه | از محل تغییر به بعد نامعتبر |
| `reserve` بزرگ‌تر از ظرفیت | همه نامعتبر |
| `clear` | همه نامعتبر |

قاعده: **هر عملیاتی که `capacity` را تغییر دهد، همهٔ تکرارگرها را باطل می‌کند.** اگر با `reserve` از قبل جا گرفته باشید، `push_back`های بعدی تکرارگرها را باطل نمی‌کنند — دلیل دیگری برای `reserve`.

## ۷. `at` در برابر `operator[]`

```cpp
values[99]      // ❌ رفتار تعریف‌نشده؛ ممکن است بخواند، ممکن است explode کند
values.at(99)   // ✅ std::out_of_range پرتاب می‌کند
```

خروجی واقعی `02_erase_insert.cpp`:

```
--- دسترسی با at و بررسی محدوده ---
  at(1) = 15
  at(99) =   out_of_range: vector::_M_range_check: __n (which is 99) >= this->size() (which is 3)
```

دقت کنید `at(99) = ` **قبل** از پرتاب استثنا چاپ شد: `std::cout << "..." << values.at(99)` اول سمت چپ را ارسال می‌کند، بعد `at` پرتاب می‌کند. به همین دلیل خروجی وسط خط قطع شده است — نمونهٔ خوبی از اینکه چاپ و محاسبه در یک عبارت می‌توانند نیمه‌کاره بمانند.

`[]` سریع‌تر است چون بررسی نمی‌کند؛ در حلقه‌ای که اندیس قطعاً معتبر است از `[]`، در ورودی نامطمئن از `at` استفاده کنید.

### ۸.۱ خروجی واقعی `01_vector_grow.cpp`

```
--- رشد خودکار بدون reserve ---
push_back(10)
  size = 1، capacity = 1
push_back(20)
  size = 2، capacity = 2
push_back(30)
  size = 3، capacity = 4
push_back(40)
  size = 4، capacity = 4
push_back(50)
  size = 5، capacity = 8
--- با reserve از قبل ---
  size = 0، capacity = 5
  size = 1، capacity = 5
  size = 2، capacity = 5
  size = 3، capacity = 5
  size = 4، capacity = 5
  size = 5، capacity = 5
--- shrink_to_fit یک درخواست است، نه تضمین ---
  size = 1، capacity = 100
  size = 1، capacity = 1
--- آزمایش reserve بیشتر از نیاز ---
  size = 1، capacity = 16
```

دو نکته:

- اعداد `1, 2, 4, 8` رفتار `libstdc++` (دو برابر کردن) است. استاندارد فقط می‌گوید رشد باید **هندسی** باشد، نه خطی؛ با `MSVC` ممکن است `1.5` برابر ببینید. روی عدد دقیق تکیه نکنید، روی الگو تکیه کنید.
- در بخش `reserve`، `capacity` همیشه `5` ماند و هیچ کپی رخ نداد.

### ۸.۲ خروجی واقعی `02_erase_insert.cpp`

```
--- شروع ---
  [10, 20, 30, 40, 50]  size = 5
--- insert در اندیس ۱ ---
  [10, 15, 20, 30, 40, 50]  size = 6
--- erase اندیس ۳ ---
  [10, 15, 20, 40, 50]  size = 5
--- حذف همهٔ اعداد بزرگ‌تر از ۳۰ ---
  [10, 15, 20]  size = 3
--- دسترسی با at و بررسی محدوده ---
  at(1) = 15
  at(99) =   out_of_range: vector::_M_range_check: __n (which is 99) >= this->size() (which is 3)
```

`insert` عنصر ۱۵ را در اندیس ۱ گذاشت و ۲۰ به بعد یک خانه جابه‌جا شدند. `erase` اندیس ۳ (که بعد از درج، عدد ۳۰ است) را حذف کرد.

## ۹. اشتباهات رایج

1. **`++it` بعد از `erase(it)`** → تکرارگر نامعتبر و رفتار تعریف‌نشده. از مقدار بازگشتی استفاده کنید.
2. **`resize` به‌جای `reserve`** → `resize` عناصر واقعی می‌سازد؛ اگر فقط جا می‌خواهید، `reserve`.
3. **نگه داشتن `data()` یا تکرارگر بعد از `push_back` رشدکننده** → آدرس حافظه عوض شده است.
4. **`shrink_to_fit` به‌عنوان تضمین** → درخواست است، نه قرارداد.
5. **درج مکرر در ابتدای `vector`** → هر بار `O(n)`؛ برای این کار `deque` یا `list`.
6. **`at` در حلقهٔ داغ** → بررسی محدوده هزینه دارد؛ اگر اندیس قطعاً معتبر است `[]`.
7. **انتظار `capacity == size` بعد از حذف** → حذف ظرفیت را کم نمی‌کند.
8. **`vector<bool>` به‌عنوان `vector` معمولی** → تخصص‌یافته است و `&v[0]` معنا ندارد.

## ۱۰. بهترین شیوه‌ها

- اگر تعداد عناصر را می‌دانید، `reserve` بزنید.
- `emplace_back` را برای ساخت درجا ترجیح دهید.
- هرگز بعد از `erase` روی تکرارگر `++` نزنید.
- `reserve` را قبل از حلقه بزنید، نه داخل آن.
- برای پیمایش فقط‌خواندنی از `const auto&` استفاده کنید تا کپی ساخته نشود:

```cpp
for (const auto& item : items) {
    std::cout << item.name << "\n";
}
```

---

## ۱۱. خلاصه

- `size` تعداد عناصر است، `capacity` ظرفیت فعلی حافظه.
- رشد هندسی است؛ `reserve` رشدهای میانی و کپی‌ها را حذف می‌کند.
- `insert`/`erase` در میانه `O(n)` است.
- `erase` تکرارگر بعدی را برمی‌گرداند؛ در حلقه از آن استفاده کنید.
- `emplace_back` شیء را درجا می‌سازد و کپی موقت را حذف می‌کند.
