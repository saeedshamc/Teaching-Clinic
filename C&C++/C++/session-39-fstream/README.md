# جلسهٔ ۳۹ — کار با فایل (`fstream`)

> داده‌ای که در فایل نیست، با بسته شدن برنامه می‌میرد.

---

## اهداف این جلسه

1. `ofstream`، `ifstream` و `fstream` را به کار ببرید.
2. حالت‌های باز کردن فایل و تفاوت `trunc` با `app` را بدانید.
3. خط‌به‌خط و کلمه‌به‌کلمه بخوانید و وضعیت جریان را بررسی کنید.
4. فایل باینری بنویسید و بخوانید.
5. یک `vector` از اشیاء را در هر دو قالب ذخیره و بازیابی کنید.

---

## ۱. سه کلاس، سه نقش

| کلاس | نقش |
|---|---|
| `std::ofstream` | فقط نوشتن (output) |
| `std::ifstream` | فقط خواندن (input) |
| `std::fstream` | هر دو |

همه از `std::ostream`/`std::istream` مشتق شده‌اند، پس همان `<<` و `>>` و `getline` که با `cin`/`cout` استفاده کردید، اینجا هم کار می‌کند. و چون RAII هستند، بستن فایل خودکار است.

```cpp
{
    std::ofstream output("data.txt");
    output << "سلام\n";
}   // فایل اینجا بسته و flush شد
```

---

## ۲. حالت‌های باز کردن

```cpp
std::ofstream a("f.txt");                       // = out | trunc (بازنویسی)
std::ofstream b("f.txt", std::ios::app);        // افزودن به انتها
std::ofstream c("f.dat", std::ios::binary);     // باینری
std::fstream  d("f.txt", std::ios::in | std::ios::out);
```

| پرچم | معنی |
|---|---|
| `ios::in` | خواندن |
| `ios::out` | نوشتن (پیش‌فرض `ofstream`) |
| `ios::trunc` | پاک کردن محتوای قبلی (همراه `out`) |
| `ios::app` | نوشتن در انتها، بدون پاک کردن |
| `ios::ate` | باز کردن و رفتن به انتها (بدون پاک کردن) |
| `ios::binary` | بدون تبدیل کاراکتر پایان خط |

**دام**: `ofstream` به‌طور پیش‌فرض `trunc` دارد. اگر دو بار فایل را باز کنید، محتوای قبلی می‌رود — همان چیزی که در جلسهٔ ۳۸ دیدیم.

---

## ۳. نوشتن و بررسی موفقیت

خروجی واقعی `01_write_file.cpp`:

```
  is_open قبل از close: بله
  is_open بعد از close: خیر
  فایل ساخته شد: بله
  اندازه: 36 بایت
--- افزودن به فایل با ios::app ---
  اندازه بعد از افزودن: 52 بایت
--- تلاش برای نوشتن در مسیر نامعتبر ---
  is_open: خیر، operator bool: غلط
فایل موقت پاک شد.
```

سه نکته:

1. سه خط فارسی، هر کدام ۱۲ بایت (هر حرف فارسی ۲ بایت در UTF-8) → ۳۶ بایت.
2. `ios::app` خط چهارم را اضافه کرد: ۵۲ بایت شد، چون «خط چهارم» (۷ حرف فارسی + یک فاصله = ۷ × ۲ + ۱) به‌همراه `\n` دقیقاً ۱۶ بایت است.
3. **همیشه بعد از باز کردن بررسی کنید**:

```cpp
std::ofstream output(path);
if (!output) { /* خطا */ }
```

`operator bool` همان `!fail()` است. باز کردن مسیر نامعتبر، استثنا نمی‌دهد؛ فقط جریان را در وضعیت `fail` می‌گذارد.

## ۴. خواندن

### خط‌به‌خط با `getline`

```cpp
std::string line;
while (std::getline(input, line)) {
    // هر خط، بدون \n
}
```

### کلمه‌به‌کلمه با `>>`

```cpp
std::string word;
while (input >> word) { }     // فاصله‌ها و خطوط را رد می‌کند
```

خروجی واقعی `02_read_lines.cpp`:

```
--- خواندن خط‌به‌خط ---
  1: cpp is fast (3 کلمه)
  2: stl gives tools (3 کلمه)
  3: practice every day (3 کلمه)
  خطوط: 3، کلمات: 9
  eof: بله، fail: بله
--- خواندن کلمه‌به‌کلمه با >> ---
  1: cpp
  2: is
  3: fast
--- فایل ناموجود ---
  باز شد: خیر، fail: بله
```

### وضعیت‌های جریان

| تابع | معنی |
|---|---|
| `good()` | همه‌چیز مرتب |
| `eof()` | به انتها رسیدیم |
| `fail()` | عملیات شکست خورد (شامل eof) |
| `bad()` | خطای جدی (مثلاً خطای I/O) |

نکته: بعد از پایان `while (getline)`، هم `eof` و هم `fail` درست‌اند؛ چون `getline` در آخرین تلاش شکست خورد. برای خواندن دوباره باید `clear()` بزنید و با `seekg(0)` به ابتدا برگردید — همان کاری که در خروجی دیدید.

## ۵. فایل باینری

```cpp
std::ofstream output(path, std::ios::binary);
output.write(reinterpret_cast<const char*>(&record), sizeof(Record));

std::ifstream input(path, std::ios::binary);
input.read(reinterpret_cast<char*>(&record), sizeof(Record));
```

خروجی واقعی `03_binary_file.cpp`:

```
  sizeof(Record) = 24
  اندازهٔ فایل = 24 بایت
  خوانده شد: 24 بایت
--- مقایسه ---
  id: 7 (قبلی 7)
  value: 3.5 (قبلی 3.5)
  tag: abc
  یکسان است؟ بله
```

`sizeof(Record)` = ۲۴ شد، نه ۱۶ (`4 + 8 + 8 = 20`) — چون کامپایلر برای هم‌ترازی، فاصله (padding) می‌گذارد. `int` چهار بایت، بعد چهار بایت فاصله تا `double` هشت‌بایتی در آدرس مضرب ۸ قرار بگیرد، و `char[8]` هشت بایت → `4 + 4 + 8 + 8 = 24`.

**هشدار مهم**: نوشتن ساختار خام برای فایل قابل‌انتقال بین سیستم‌ها مناسب نیست — اندازهٔ انواع، padding و ترتیب بایت‌ها (endianness) تضمین‌شده نیست.

## ۶. پروژهٔ پایان فاز ۶ — `04_phase_project.cpp`

**«ذخیره و بازخوانی `vector` اشیاء در فایل متنی و باینری با RAII»**

```cpp
struct Book { int id; std::string title; int year; };
```

### قالب متنی

هر کتاب یک خط با جداکنندهٔ `|`:

```
1|C++ Primer|2013
```

خواندن با `getline` + `istringstream` و جداکنندهٔ `'|'`.

### قالب باینری

چون `std::string` اندازهٔ ثابت ندارد، باید **طول را قبل از محتوا** بنویسید:

```
[int id][uint32 length][bytes عنوان][int year]
```

خروجی واقعی:

```
--- اصلی (3 کتاب):
  1 — C++ Primer — 2013
  2 — Effective Modern C++ — 2014
  3 — The C++ Programming Language — 2013
--- فایل‌ها ---
  متن: 82 بایت
  باینری: 94 بایت
--- بازخوانی متنی (3 کتاب):
  1 — C++ Primer — 2013
  2 — Effective Modern C++ — 2014
  3 — The C++ Programming Language — 2013
--- بازخوانی باینری (3 کتاب):
  1 — C++ Primer — 2013
  2 — Effective Modern C++ — 2014
  3 — The C++ Programming Language — 2013
--- بازخوانی از فایل ناموجود ---
  کتاب‌ها: 0 (بدون خطا، vector خالی)
فایل‌های موقت پاک شدند.
```

تصمیم‌های طراحی که باید بتوانید توضیح دهید:

1. **متن بزرگ‌تر از باینری است** (۸۲ در برابر ۹۴)؟ چون در باینری هر عدد ۴ بایت است (`id` و `year` و `length`) و عنوان‌ها هم یک بار آمده‌اند؛ در متن `id` و `year` به شکل کم‌حجم‌تر نوشته شدند ولی `|` و `\n` اضافه شد.
2. **تابع بازخوانی از فایل ناموجود استثنا نمی‌دهد**، `vector` خالی برمی‌گرداند. تفکیک «نبود فایل» از «فایل خراب» تصمیم طراحی است؛ در پروژهٔ نهایی (جلسهٔ ۵۰) بهتر است با `optional` یا استثنا صریح شود.
3. **همه‌چیز RAII است**: `ofstream`/`ifstream` در دامنه، بدون `close()` دستی.
4. **هیچ `new`/`delete` خامی نیست** — شرط پذیرش فاز ۶.

## ۸. اشتباهات رایج

1. **`ofstream` بدون `app` روی فایل موجود** → محتوا پاک می‌شود.
2. **بررسی نکردن `if (!stream)`** → ادامه دادن با جریان نامعتبر و نتیجهٔ خالی.
3. **استفاده از `while (!input.eof())`** → آخرین خط دو بار پردازش می‌شود یا خط خالی جا می‌افتد. `while (getline(...))` درست است.
4. **فراموش کردن `clear()` قبل از `seekg`** → جستجو در جریان `fail` کاری نمی‌کند.
5. **خواندن باینری با `>>`** → دادهٔ دودویی را نمی‌شناسد.
6. **نوشتن `std::string` با `write(&s, sizeof(s))`** → فقط شیءِ مدیریت حافظه نوشته می‌شود، نه محتوا.
7. **خواندن رشته بدون طول** → نمی‌دانید چند بایت بخوانید.
8. **تکیه به padding برای سازگاری** → بین کامپایلرها و معماری‌ها متفاوت است.
9. **مسیر نسبی در برنامهٔ واقعی** → وابسته به پوشهٔ اجرا؛ از مسیر صریح یا `filesystem` استفاده کنید.

---

## ۹. بهترین شیوه‌ها

- همیشه بعد از باز کردن، جریان را بررسی کنید.
- برای فایل متنی، قالب خطی ساده و قابل‌خواندن انتخاب کنید؛ جداکننده‌ای که در داده نمی‌آید.
- برای فایل باینری، طول رشته‌ها را صریح بنویسید.
- از `std::filesystem` برای وجود فایل، اندازه و پاک‌سازی استفاده کنید.
- بستن دستی ننویسید؛ RAII کافی است. اگر لازم شد، `flush()` بزنید نه `close()`.
- فایل‌های موقت تست را در `temp_directory_path()` بسازید و در پایان پاک کنید.

---

## ۱۰. خلاصه

- `ofstream`/`ifstream`/`fstream` با همان `<<`/`>>`/`getline` کار می‌کنند.
- `ofstream` پیش‌فرض فایل را بازنویسی می‌کند؛ برای افزودن `ios::app`.
- `getline` برای خط، `>>` برای کلمه؛ وضعیت جریان را بررسی کنید.
- فایل باینری با `read`/`write` و `ios::binary`؛ طول رشته‌ها باید صریح نوشته شود.
- ذخیره و بازیابی `vector` اشیاء با RAII و بدون `new`/`delete` ممکن و ساده است.
