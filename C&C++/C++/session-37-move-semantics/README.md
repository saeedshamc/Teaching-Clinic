# جلسهٔ ۳۷ — Move Semantics

> کپی یعنی «یکی دیگر مثل این بساز»؛ move یعنی «این را بردار، من دیگر لازمش ندارم».

---

## اهداف این جلسه

1. تفاوت lvalue و rvalue را بفهمید.
2. بدانید `std::move` فقط یک cast است، نه انتقال.
3. سازندهٔ انتقال و عملگر انتساب انتقال بنویسید.
4. نقش `noexcept` را در کارایی `vector` ببینید.
5. قانون پنج و قانون صفر را بشناسید.

---

## ۱. lvalue و rvalue

- **lvalue**: عبارتی که نام دارد و آدرس دارد (`x`، `v[0]`، `*p`).
- **rvalue**: مقدار موقت که نام ندارد (`42`، `x + 1`، `std::string("موقت")`).

```cpp
int x = 5;        // x: lvalue، 5: rvalue
int y = x + 1;    // x + 1: rvalue
```

کپی از lvalue منطقی است (منبع باید سالم بماند)، ولی از rvalue می‌توان دزدی کرد (منبع قرار است بمیرد). move semantics همین اجازه را می‌دهد.

---

## ۲. `std::move` چیست

`std::move(x)` **هیچ چیزی را جابه‌جا نمی‌کند**. فقط نوع را به `T&&` (rvalue reference) تبدیل می‌کند تا سازنده یا انتساب انتقال انتخاب شود:

```cpp
std::string source = "متن";
std::string moved = std::move(source);   // الان سازندهٔ انتقال صدا زده می‌شود
```

خروجی واقعی `01_move_basics.cpp`:

```
--- کپی ---
  منبع: متن، کپی: متن
--- move ---
  مقصد: متن
  طول منبع بعد از move: 0 (وضعیت معتبر ولی نامشخص)
--- move روی int اثری ندارد ---
  number = 42، other = 42
--- vector با move ---
  names.size() = 0، movedNames.size() = 3
--- push_back با انتقال ---
  list[0] = موقت، طول temporary = 0
--- rvalue مرجع ---
  reference = موقت
```

سه درس:

1. **منبع بعد از move «معتبر ولی نامشخص» است.** در `libstdc++` خالی می‌شود، ولی استاندارد فقط می‌گوید «می‌توانی به آن مقدار بدهی یا آزادش کنی»، نه «بخوانی».
2. **`std::move` روی `int` اثری ندارد**، چون انتقال برای انواع ساده معنا ندارد؛ فقط کپی می‌شود.
3. **`std::move` روی یک شیء، خود شیء را جابه‌جا نمی‌کند** — فقط اجازهٔ انتقال می‌دهد.

---

## ۳. سازندهٔ انتقال

```cpp
class Buffer {
public:
    Buffer(Buffer&& other) noexcept
        : data_(std::move(other.data_)) { }   // حافظه دزدیده می‌شود، نه کپی
};
```

قواعد:

- امضا: `T(T&& other) noexcept` — بدون `const`، چون می‌خواهیم از منبع بدزدیم.
- `noexcept` **بسیار مهم** است (بخش ۴).
- منبع را در وضعیت معتبر بگذارید (مثلاً `nullptr` یا خالی).
- اگر عضوها خودشان move بلدند (`std::vector`، `std::string`، `unique_ptr`)، فقط `std::move` بزنید و کار تمام است.

### کپی در برابر انتقال — خروجی واقعی `02_move_ctor.cpp`

```
--- ساخت ---
  ساخت: 5 عنصر
--- کپی صریح ---
  کپی: 5 عنصر
--- انتقال از شیء غیر const ---
  انتقال: 5 عنصر
  size بعد از انتقال: 5
--- انتقال از شیء const: move به کپی تبدیل می‌شود ---
  کپی: 5 عنصر
  forcedCopy.size() = 5
--- مقدار برگشتی ---
  makeBuffer(4) صدا زده می‌شود
  ساخت: 4 عنصر
  returned.size() = 4
--- ارسال با ارزش به تابع ---
  ساخت: 3 عنصر
  انتقال: 3 عنصر
  داخل consume: 3 عنصر
  تخریب: 3 عنصر
--- vector و انتقال ---
  push_back(Buffer(2)):
  ساخت: 2 عنصر
  انتقال: 2 عنصر
  تخریب: 0 عنصر
  emplace_back(3):
  ساخت: 3 عنصر
  push_back(std::move(local)):
  انتقال: 0 عنصر
  تعداد: 3
--- پایان ---
  تخریب: 2 عنصر
  ...
```

چهار نکتهٔ کلیدی:

1. **`std::move` روی شیء `const` کپی می‌سازد.** چون `const Buffer&&` به `Buffer&&` بسته نمی‌شود و کپی انتخاب می‌شود. اگر نمی‌خواهید منبع تغییر کند، move معنا ندارد.
2. **مقدار برگشتی کپی/انتقال نداشت** — elision (RVO) شیء را مستقیم در محل مقصد ساخت.
3. **`push_back(Buffer(2))` یک ساخت + یک انتقال دارد**، ولی `emplace_back(3)` فقط یک ساخت. همان درسی که در جلسهٔ ۲۸ دیدیم، این بار با شمارش واقعی.
4. **`push_back(std::move(local))` انتقال با اندازهٔ صفر** — منبع خالی شد و انتقال چیزی نداشت که ببرد.

## ۴. `noexcept` و `vector`

`std::vector` هنگام رشد باید عناصر را به حافظهٔ جدید منتقل کند. اگر انتقال **استثنا** بدهد در میانهٔ کار، `vector` نمی‌تواند وضعیت قبلی را تضمین کند. پس:

- اگر سازندهٔ انتقال `noexcept` باشد → **move** می‌کند (سریع).
- اگر نباشد → برای امنیت **کپی** می‌کند (کند، و اگر کپی نباشد کامپایل نمی‌شود).

به همین دلیل همیشه `noexcept` بگذارید، حتی اگر بدنتان هیچ‌وقت استثنا نمی‌دهد. `std::move_if_noexcept` هم همین منطق را برای کد شما فراهم می‌کند.

---

## ۵. قانون پنج و قانون صفر

**قانون پنج**: اگر یکی از این پنج را دستی تعریف کردید، احتمالاً باید همه را تعریف کنید:

1. مخرب
2. سازندهٔ کپی
3. انتساب کپی
4. سازندهٔ انتقال
5. انتساب انتقال

**دام مهم**: اگر فقط مخرب (یا فقط کپی) تعریف کنید، کامپایلر سازندهٔ انتقال خودکار **تولید نمی‌کند** و `std::move` شما بی‌صدا به کپی تبدیل می‌شود.

خروجی واقعی `03_rule_of_five.cpp`:

```
--- CopyOnly و std::move ---
  CopyOnly: کپی
--- Movable و std::move ---
  Movable: انتقال
  بعد از انتقال ساخته شد
--- انتساب ---
  Movable: کپی=
  Movable: انتقال=
--- noexcept و vector ---
  push_back(Movable()):
  Movable: انتقال
  تعداد: 1
--- پایان ---
```

**قانون صفر** (بهتر): هیچ‌کدام را ننویسید و کار را به اعضای استاندارد بسپارید.

```cpp
class Buffer {
    std::vector<int> data_;   // خودش پنج عضو را درست مدیریت می‌کند
};
```

کامپایلر برای `Buffer` همهٔ پنج عضو را خودکار و درست می‌سازد. `= default` هم همین کار را صریح می‌کند.

---

## ۶. `std::forward` (اشاره)

`std::move` همیشه rvalue می‌سازد؛ `std::forward<T>` نوع اصلی را حفظ می‌کند. برای توابع قالبی که آرگومان را پاس می‌دهند:

```cpp
template <typename T>
void wrapper(T&& value) {
    target(std::forward<T>(value));   // lvalue اگر lvalue بود، rvalue اگر rvalue بود
}
```

این همان «forwarding reference» است؛ در جلسه‌های بعدی (قالب‌های پیشرفته و `make_unique`) دوباره می‌بینیدش.

## ۸. اشتباهات رایج

1. **`std::move` روی `const`** → کپی بی‌صدا.
2. **استفاده از منبع بعد از move** → مقدار نامشخص.
3. **`std::move` در `return`** → معمولاً جلوی elision را می‌گیرد؛ `return value;` بنویسید.
4. **فراموش کردن `noexcept`** → `vector` کپی می‌کند.
5. **پارامتر `const T&&`** → عملاً بی‌فایده؛ انتقال نمی‌تواند از آن بدزدد.
6. **تعریف مخرب بدون move** → move بی‌صدا به کپی تبدیل می‌شود.
7. **move از عضوی که بعداً لازم است** → منطق خراب می‌شود.
8. **`std::move` روی نوع ساده (`int`)** → هیچ سودی ندارد و خواننده را گمراه می‌کند.

## ۹. بهترین شیوه‌ها

- قانون صفر را پیش‌فرض بگیرید؛ فقط وقتی منبع خام دارید پنج عضو بنویسید.
- سازنده و انتساب انتقال را `noexcept` بنویسید.
- در سازندهٔ انتقال، اعضا را با `std::move` به لیست مقداردهی بدهید.
- بعد از move، منبع را در وضعیت «خالی معتبر» بگذارید.
- `std::move` را فقط جایی بزنید که واقعاً می‌خواهید مالکیت را واگذار کنید — نه برای «بهینه‌سازی».

---

## ۱۰. خلاصه

- lvalue نام دارد؛ rvalue موقت است و می‌شود از آن دزدید.
- `std::move` فقط cast به `T&&` است.
- سازندهٔ انتقال حافظه را می‌دزدد و منبع را خالی می‌گذارد.
- `noexcept` تعیین می‌کند `vector` move کند یا کپی.
- قانون پنج برای منابع خام؛ قانون صفر برای بقیه.
