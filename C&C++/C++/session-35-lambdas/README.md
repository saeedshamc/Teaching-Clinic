# جلسهٔ ۳۵ — عبارات لامبدا

> لامبدا تابعی است که نام ندارد، چون فقط همین‌جا لازم است.

---

## اهداف این جلسه

1. ساختار لامبدا را بشناسید و بتوانید آن را تجزیه کنید.
2. تفاوت capture با مقدار و با مرجع را در عمل ببینید.
3. نقش `mutable` را بفهمید.
4. لامبدای جنریک و ذخیره در `std::function` را به کار ببرید.
5. از خطر dangling در capture مرجع دوری کنید.

---

## ۱. لامبدا چیست

لامبدا یک **شیء تابع** (functor) است که کامپایلر برایتان می‌سازد:

```cpp
std::sort(values.begin(), values.end(), [](int left, int right) {
    return left > right;
});
```

بدون لامبدا باید یک تابع جدا یا یک `struct` با `operator()` می‌نوشتید — دور از محل استفاده. لامبدا تعریف را همان‌جا می‌آورد که استفاده می‌شود.

---

## ۲. تجزیهٔ ساختار

```cpp
[ capture ] ( parameters ) -> return_type { body }
```

| بخش | لازم است؟ | توضیح |
|---|---|---|
| `[ ]` | ✅ | لیست capture، حتی اگر خالی باشد |
| `( )` | اختیاری | پارامترها؛ در C++11 اگر خالی باشد می‌توان حذف کرد |
| `-> type` | اختیاری | نوع بازگشتی؛ معمولاً استنتاج می‌شود |
| `{ }` | ✅ | بدنه |

```cpp
auto add = [](int a, int b) { return a + b; };
```

کامپایلر چیزی شبیه این می‌سازد:

```cpp
struct __Lambda {
    int operator()(int a, int b) const { return a + b; }
};
```

همین `const` بودن توضیح می‌دهد چرا تغییر متغیر capture‌شده به `mutable` نیاز دارد.

---

## ۳. capture — چه چیزی از بیرون دیده شود

| شکل | معنی |
|---|---|
| `[]` | هیچ چیزی |
| `[x]` | کپی `x` در زمان **ساخت** لامبدا |
| `[&x]` | مرجع به `x` |
| `[=]` | همه با کپی |
| `[&]` | همه با مرجع |
| `[x, &y]` | ترکیبی |
| `[x = expr]` | capture با مقدار اولیه (C++14) |

خروجی واقعی `02_capture.cpp`:

```
--- capture by value ---
  threshold در زمان ساخت: 5، حالا: 100
  تعداد بزرگ‌ترها: 3
  تعداد با capture مرجع: 0
--- mutable ---
  کپی داخلی: 1، 2
  counter اصلی: 0
--- capture همه ---
  a بعد از bump: 11، sumAll() (کپی زمان ساخت): 3
```

سه درس مستقیم از این خروجی:

1. `byValue` با `threshold = 5` ساخته شد؛ بعد `threshold = 100` شد ولی لامبدا همچنان ۵ را می‌بیند → ۳ عدد بزرگ‌تر از ۵.
2. `byReference` مقدار فعلی (۱۰۰) را می‌خواند → هیچ عددی بزرگ‌تر از ۱۰۰ نیست → صفر.
3. `sumAll` با `a = 1` ساخته شد؛ `bump()` بعداً `a` را ۱۱ کرد ولی `sumAll()` هنوز ۳ برمی‌گرداند.

---

## ۴. `mutable`

به‌طور پیش‌فرض `operator()` لامبدا `const` است، پس متغیرهای capture‌شده با مقدار را نمی‌شود تغییر داد. `mutable` این محدودیت را برمی‌دارد — ولی فقط روی **کپی داخلی** اثر دارد:

```cpp
int counter = 0;
auto countCalls = [counter](int) mutable { return ++counter; };
```

```
  کپی داخلی: 1، 2
  counter اصلی: 0
```

`counter` اصلی صفر ماند. اگر می‌خواهید اصل تغییر کند، باید با مرجع capture کنید (`[&counter]`).

همچنین `mutable` باعث می‌شود لامبدا را نتوان روی شیء `const` صدا زد:

```cpp
const auto f = [counter](int) mutable { return ++counter; };
f(0);   // ❌ خطای کامپایل: operator() غیر-const روی شیء const
```

---

## ۵. لامبدای جنریک

با `auto` در پارامترها، لامبدا برای هر نوعی که صدا زده شود ساخته می‌شود (C++14):

```cpp
const auto twice = [](const auto& value) { return value + value; };
```

خروجی واقعی:

```
  twice(21) = 42، twice("ab") = abab
```

یک لامبدا، دو نوع. این همان الگوی قالب تابع جلسهٔ ۲۴ است، بدون نوشتن `template`.

---

## ۶. ذخیره در `std::function`

```cpp
std::function<bool(const Product&, const Product&)> byName =
    [](const Product& left, const Product& right) { return left.name < right.name; };
```

`std::function` یک بستهٔ نوع‌پاک‌کن است: هر چیزی که قابل صدا زدن با آن امضا باشد در آن جا می‌شود. هزینه‌اش:

- تخصیص حافظهٔ پویا برای captureهای بزرگ،
- یک لایهٔ فراخوانی غیرمستقیم (کمی کندتر از `auto`).

قاعده: **اگر می‌توانید `auto` بگذارید، `std::function` نگذارید.** `std::function` برای وقتی است که باید در امضای تابع یا عضو کلاس ذخیره شود.

---

## ۷. خطر dangling

```cpp
std::function<int()> makeCounter() {
    int local = 0;
    return [&local]() { return ++local; };   // ❌ local بعد از return می‌میرد
}
```

لامبدا مرجع به متغیری دارد که عمرش تمام شده → رفتار تعریف‌نشده. سه راه‌حل:

1. capture با مقدار (`[local]`) اگر تغییر لازم نیست.
2. `mutable` + capture با مقدار اگر تغییر داخلی لازم است و اصل مهم نیست.
3. `std::shared_ptr` اگر اشتراک واقعی لازم است (جلسهٔ ۳۶).

قاعدهٔ عملی: **capture مرجع فقط وقتی که لامبدا حتماً قبل از پایان عمر متغیر صدا زده می‌شود** — مثل الگوریتم‌های فوری (`sort`، `for_each`).

## ۹. اشتباهات رایج

1. **capture مرجع به متغیر محلی که برمی‌گردد** → dangling.
2. **فراموش کردن `mutable`** → خطای کامپایل هنگام تغییر مقدار capture‌شده.
3. **تصور اینکه `mutable` اصل متغیر را تغییر می‌دهد** → فقط کپی داخلی.
4. **`[=]` برای اشیای سنگین** → کپی پرهزینه در هر ساخت؛ `[&]` یا capture انتخابی.
5. **`[&]` در لامبدای ذخیره‌شده** → احتمال زیاد dangling.
6. **`std::function` در حلقهٔ داغ** → سربار تخصیص؛ `auto` بهتر است.
7. **فراموش کردن `()` در `[]() { }`** → خطای نحوی گیج‌کننده.
8. **لامبدای بیش‌ازحد بلند** → اگر از ده خط گذشت، تابع نام‌دار بهتر است.
9. **گرفتن `this` به‌صورت `[=]` در کلاس** → در C++17 `[=]` خود `this` را می‌گیرد (نه کپی شیء)؛ آگاه باشید.

## ۱۰. بهترین شیوه‌ها

- capture را **حداقلی و صریح** بنویسید (`[&book]`، نه `[&]`).
- لامبدای کوتاه و تک‌منظوره؛ منطق پیچیده را تابع نام‌دار کنید.
- برای کامپارatorها همان قاعدهٔ ترتیب اکید جلسهٔ ۳۴ رعایت شود.
- `auto` برای نگهداری لامبدا، `std::function` فقط وقتی امضا لازم است.
- هرگاه لامبدا از تابع خارج می‌شود، capture مرجع را دوباره بررسی کنید.

---

## ۱۱. خلاصه

- لامبدا یک شیء تابع بی‌نام است که در محل استفاده تعریف می‌شود.
- `[]` برای capture، `[x]` کپی زمان ساخت، `[&x]` مرجع.
- `mutable` فقط کپی داخلی را قابل‌تغییر می‌کند.
- لامبدای جنریک با `auto` در پارامتر.
- `std::function` لامبدا را در امضا نگه می‌دارد، با هزینهٔ اجرایی.
- capture مرجع در لامبدایی که عمرش بیشتر است، خطر dangling دارد.

## ۱۳. پایان فاز ۵ — پروژهٔ ارزیابی

**«دفترچهٔ تلفن»** — `examples/04_phonebook.cpp`

خواسته‌ها:

1. داده در `std::map<std::string, std::vector<std::string>>` (نام → شماره‌ها).
2. افزودن مخاطب با چند شماره.
3. جستجوی جزئی: بخشی از نام **یا** شماره.
4. مرتب‌سازی نتایج بر اساس تعداد شماره‌ها، با حفظ ترتیب حروف برای برابرها (`stable_sort`).
5. همهٔ پردازش‌ها با لامبدا، بدون حلقهٔ دستی برای جستجو.

خروجی واقعی:

```
--- همهٔ مخاطبین ---
  Ali: 0913-444-5566 021-8877-6655 
  Omid: 0912-333-4455 
  Saeed: 0919-777-8899 
  Sara: 0912-111-2233 
--- جستجوی «0912» ---
  Omid
  Sara
--- جستجوی «Sa» ---
  Saeed
  Sara
--- مرتب بر اساس تعداد شماره ---
  Ali (2)
  Omid (1)
  Saeed (1)
  Sara (1)
--- یافتن شمارهٔ یک نفر ---
  Ali: 2 شماره
```

نکته‌های طراحی:

- `book[name].push_back(number)` هم درج و هم افزودن شماره را یک‌جا انجام می‌دهد (جلسهٔ ۳۰).
- `std::any_of` با لامبدای `[&part]` روی شماره‌ها جستجو می‌کند — capture مرجع امن است چون لامبدا همان‌جا اجرا می‌شود.
- `stable_sort` باعث شد `Omid`، `Saeed` و `Sara` با یک شماره، ترتیب حروف خود را حفظ کنند؛ با `sort` این ترتیب تضمین نبود.

| مشکل | جلسه |
|---|---|
| کانتینر درست را نمی‌شناسم | ۲۷ |
| `map` کلید ناموجود می‌سازد | ۳۰ |
| `find_if`/`any_of` را نمی‌فهمم | ۳۴ |
| کامپارator نتیجهٔ عجیب می‌دهد | ۳۴ |
| لامبدا کامپایل نمی‌شود | ۳۵ (capture و `mutable`) |
