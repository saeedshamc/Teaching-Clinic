# جلسهٔ ۴۲ — جستجوی خطی و دودویی (Linear & Binary Search)

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- جستجوی خطی را روی هر آرایه‌ای پیاده‌سازی کنید (O(n))
- جستجوی دودویی را روی آرایهٔ مرتب پیاده‌سازی کنید (O(log n))
- شرط لازم برای جستجوی دودویی (آرایهٔ مرتب) را درک کنید
- تفاوت سرعت این دو را برای دادهٔ بزرگ ببینید

---

## چرا جستجو؟

تقریباً هر برنامه‌ای نیاز به پیدا کردن داده دارد: پیدا کردن یک کاربر، یک کلمه، یک شناسه. نحوهٔ ذخیرهٔ داده تعیین می‌کند چقدر سریع می‌توانیم بگردیم.

## جستجوی خطی (Linear Search)

ساده‌ترین روش: از اول تا آخر می‌رویم و هر عنصر را مقایسه می‌کنیم.

```c
int linear_search(const int arr[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == target) {
            return i;   // ایندکس پیدا شده
        }
    }
    return -1;          // پیدا نشد
}
```

- مزیت: روی **هر** آرایه‌ای کار می‌کند (مرتب یا نامرتب).
- عیب: در بدترین حالت باید همهٔ n عنصر را ببینیم → O(n).
- برای n = 1,000,000 یعنی حداکثر ۱ میلیون مقایسه.

## جستجوی دودویی (Binary Search)

ایده: اگر آرایه **مرتب** باشد، هر بار آرایه را نصف می‌کنیم — عنصر وسط را نگاه می‌کنیم، اگر کوچک‌تر است به نیمهٔ چپ برویم، اگر بزرگ‌تر است به نیمهٔ راست.

```c
int binary_search(const int arr[], int n, int target) {
    int low = 0, high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;   // وسطِ امن

        if (arr[mid] == target) {
            return mid;
        } else if (arr[mid] < target) {
            low = mid + 1;      // برو به نیمهٔ راست
        } else {
            high = mid - 1;     // برو به نیمهٔ چپ
        }
    }
    return -1;   // پیدا نشد
}
```

نسخهٔ بازگشتی هم همین منطق را دارد:

```c
int binary_search_recursive(const int arr[], int low, int high, int target) {
    if (low > high) return -1;

    int mid = low + (high - low) / 2;
    if (arr[mid] == target)      return mid;
    if (arr[mid] < target)       return binary_search_recursive(arr, mid + 1, high, target);
    return binary_search_recursive(arr, low, mid - 1, target);
}
```

هر بار نصف می‌شویم: n → n/2 → n/4 → ... → 1. تعداد مراحل log₂(n) است → **O(log n)**.

| n | خطی (بدترین) | دودویی (بدترین) |
|---|---|---|
| 1,000 | 1,000 | ~10 |
| 1,000,000 | 1,000,000 | ~20 |
| 1,000,000,000 | 1,000,000,000 | ~30 |

## شرط‌های لازم و مرزهای دقت

1. **آرایه باید مرتب باشد** — اگر مرتب نباشد جستجوی دودویی نتیجهٔ اشتباه می‌دهد.
2. شرط حلقه `low <= high` است نه `low < high` — اشتباه رایج.
3. `mid = low + (high - low) / 2` به‌جای `(low + high) / 2` برای جلوگیری از سرریز.
4. وقتی عنصر پیدا نشد، `-1` برگردانید و حتماً در main بررسی کنید.

## اشتباهات رایج

1. **جستجوی دودویی روی آرایهٔ نامرتب** — نتیجهٔ بی‌معنی.
2. **فراموش کردن `<=` در شرط حلقه** — عنصر آخر یا اول پیدا نمی‌شود.
3. **سرریز `low + high`** برای آرایه‌های خیلی بزرگ.
4. **برنگرداندن مقدار از تابع بازگشتی** (جلسهٔ ۱۰ را یادتان باشد).
5. **اشتباه گرفتن `low = mid + 1` با `low = mid`** — اگر `low = mid` بگذارید حلقه بی‌نهایت می‌شود.

## بهترین شیوه‌ها

- اگر آرایه مرتب است همیشه از دودویی استفاده کنید.
- اگر داده یک‌بار مرتب و بارها جستجو می‌شود، هزینهٔ مرتب‌سازی توجیه‌پذیر است.
- برای کلیدهای تکراری، مشخص کنید اولین/آخرین رخداد را می‌خواهید (تغییر کوچک در شرط).
- `const` روی پارامتر آرایه بگذارید چون جستجو نباید آرایه را تغییر دهد.

## خلاصهٔ جلسه

- خطی: ساده، روی هر آرایه، O(n).
- دودویی: فقط روی آرایهٔ مرتب، O(log n) — فوق‌العاده سریع.
- دقت در مرزها (`low <= high` و `mid + 1`/`mid - 1`) حیاتی است.
