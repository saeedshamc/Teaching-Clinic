# جلسهٔ ۲۵ — کار با فایل پیشرفته: fseek و فایل باینری

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- با `fseek` و `ftell` داخل فایل حرکت کنید (دسترسی تصادفی)
- با `fread`/`fwrite` فایل باینری بنویسید و بخوانید
- struct را مستقیم در فایل باینری ذخیره کنید
- تفاوت فایل متنی و دودویی را بدانید

---

## حرکت در فایل: fseek و ftell

```c
fseek(fp, offset, origin);
ftell(fp);   // موقعیت فعلی بر حسب بایت
```

- `origin` می‌تواند `SEEK_SET` (ابتدا)، `SEEK_CUR` (فعلی)، `SEEK_END` (انتها) باشد.
- `offset` تعداد بایت جابه‌جایی (مثبت/منفی).

```c
fseek(fp, 0, SEEK_END);      // برو به انتها
long size = ftell(fp);       // اندازهٔ فایل
fseek(fp, 0, SEEK_SET);      // برگرد به ابتدا
```

## فایل باینری: fread و fwrite

```c
fwrite(&data, sizeof(data), 1, fp);   // نوشتن یک بلوک
fread(&data, sizeof(data), 1, fp);    // خواندن یک بلوک
```

معنی آرگومان‌ها: `fwrite(مبدأ, اندازهٔ هر عنصر, تعداد عناصر, فایل)`.

باز کردن با `"rb"`/`"wb"` (باینری):

```c
FILE *fp = fopen("data.bin", "wb");
```

## ذخیرهٔ struct در فایل باینری

```c
struct Student s = {"Ali", 20, 17.5};
fwrite(&s, sizeof(s), 1, fp);   // کل struct یک‌جا نوشته می‌شود
```

## نکات

- فایل باینری قابل‌خواندن با چشم نیست ولی سریع و دقیق است.
- فایل متنی قابل‌خواندن و قابل‌انتقال بین سیستم‌هاست ولی کندتر و حجیم‌تر.
- بعد از `fwrite`، `fflush(fp)` داده را به‌زور روی دیسک می‌نویسد.
- `fseek` را قبل از `fread` بعد از نوشتن به کار ببرید (rewind).

## اشتباهات رایج

1. **باز نکردن فایل با `"rb"`/`"wb"` در ویندوز** — تبدیل‌های CRLF مشکل می‌سازند.
2. **فراموش کردن چک کردن مقدار بازگشتی `fread`** (تعداد عناصر واقعاً خوانده‌شده).
3. **فایل باینری را با فایل‌بازکن متنی باز کردن.**
4. **استفاده از fseek قبل از باز شدن درست فایل.**

## بهترین شیوه‌ها

- برای داده‌های ساختاریافته (مثل struct) از باینری و برای متن از متنی استفاده کنید.
- همیشه اندازهٔ struct را با `sizeof` بدهید.
- بعد از نوشتن، فایل را ببندید تا بافر تخلیه شود.

## خلاصهٔ جلسه

- fseek/ftell برای دسترسی تصادفی.
- fread/fwrite برای باینری؛ struct یک‌جا ذخیره می‌شود.
- حالت‌های rb/wb برای باینری.
