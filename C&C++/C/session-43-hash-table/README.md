# جلسهٔ ۴۳ — جدول هش (Hash Table)

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- مفهوم تابع هش و جدول هش را درک کنید
- برخورد (collision) را با زنجیره‌سازی (chaining) حل کنید
- عملیات insert / search / delete را روی جدول هش پیاده‌سازی کنید
- بفهمید چرا جدول هش می‌تواند O(1) باشد

---

## چرا جدول هش؟

آرایه: پیدا کردن با ایندکس O(1) اما ایندکس باید عدد صحیح کوچک باشد.
جستجوی دودویی: O(log n) اما آرایه باید مرتب باشد.
**جدول هش**: می‌خواهیم کلیدهای دلخواه (مثل نام یا کد ملی) را مستقیماً به یک ایندکس تبدیل کنیم تا جستجو تقریباً O(1) شود.

## تابع هش (Hash Function)

تابعی که هر کلید را به یک عدد (ایندکس) نگاشت می‌کند:

```c
unsigned hash(const char *key, int table_size) {
    unsigned h = 0;
    for (int i = 0; key[i] != '\0'; i++) {
        h = h * 31 + key[i];   // ترکیب کاراکترها
    }
    return h % (unsigned)table_size;   // محدود به اندازهٔ جدول
}
```

خاصیت‌های یک تابع هش خوب:
- **یکسان باشد**: کلید مساوی همیشه هش مساوی بدهد (قانون طلایی).
- پخش یکنواخت: کلیدهای مختلف به ایندکس‌های مختلف بروند.
- سریع باشد.

## برخورد (Collision) و زنجیره‌سازی (Chaining)

دو کلید مختلف ممکن است ایندکس یکسانی بگیرند → **برخورد**. ساده‌ترین راه‌حل: هر خانهٔ جدول یک لیست پیوندی باشد (جلسهٔ ۳۴). همهٔ کلیدهای هم‌هش داخل همان لیست می‌مانند:

```
ایندکس 0 → ["ali" → "sara"]
ایندکس 1 → []
ایندکس 2 → ["reza"]
```

نسبت تعداد عناصر به اندازهٔ جدول را **load factor** می‌گویند؛ اگر خیلی بزرگ شود، جدول را بزرگ‌تر می‌کنیم (rehash).

## عملیات پایه

- **insert**: ایندکس = hash(key)، سپس کلید را به لیست آن خانه اضافه کن.
- **search**: ایندکس = hash(key)، سپس در لیست آن خانه بگرد.
- **delete**: از لیست آن خانه حذف کن.

اگر تابع هش خوب باشد، طول هر لیست تقریباً ۱ است → همهٔ عملیات O(1).

## اشتباهات رایج

1. **تغییر تابع هش بین insert و search** — کلید دیگر پیدا نمی‌شود!
2. **فراموش کردن آزادسازی حافظهٔ لیست‌ها** در پایان (memory leak).
3. **استفاده از کلید غیرقابل تغییر** — اگر کلیدی را که در جدول است عوض کنید، پیدا کردنش ناممکن می‌شود.
4. **اندازهٔ جدول خیلی کوچک** → برخورد زیاد → O(n) می‌شود.
5. **شمارش درست طول کلید** در حافظهٔ پویا (فراموش کردن +1 برای '\0').

## بهترین شیوه‌ها

- اندازهٔ جدول را عدد اول (prime) انتخاب کنید تا پخش بهتری داشته باشد.
- `unsigned` برای h بگیرید تا سرریز رفتار مشخصی داشته باشد.
- همیشه یک تابع `free_table` بنویسید که همهٔ لیست‌ها را آزاد کند.
- با دادهٔ واقعی (مثلاً لیست اسامی) تست کنید.

## خلاصهٔ جلسه

- تابع هش: کلید → ایندکس (یکسان برای کلید مساوی).
- برخورد طبیعی است؛ زنجیره‌سازی آن را مدیریت می‌کند.
- جدول هش خوب: insert/search/delete تقریباً O(1).
