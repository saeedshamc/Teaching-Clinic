# جلسهٔ ۵۰ — پروژهٔ نهایی: مینیشل و پایگاه‌دادهٔ فایلی

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- همهٔ مفاهیم دوره (رشته، اشاره‌گر، struct، فایل، fork/exec، مدیریت خطا) را در یک پروژهٔ واقعی ترکیب کنید
- یک **مینی‌شل** ساده بسازید که دستورها را بخواند و اجرا کند
- یک **پایگاه‌دادهٔ فایلی** کوچک بسازید که رکوردها را روی دیسک ذخیره کند
- پروژه را با Makefile بسازید و با valgrind بررسی کنید (جلسات ۴۵ و ۴۷)

## چرا پروژهٔ نهایی؟

تا اینجا همهٔ قطعات را یاد گرفته‌اید: آرایه و struct (جلسات ۱۱–۲۰)، حافظهٔ پویا (۱۸)، فایل (۲۴–۲۵)، fork و آرگومان خط فرمان (۲۷ و ۳۰)، مدیریت خطا (۳۱). این جلسه همهٔ آن‌ها را کنار هم می‌گذارد تا یک برنامهٔ واقعی و مفید بسازید.

## پروژهٔ A: مینیشل

یک شل سادهٔ Unix که این کار را می‌کند:

1. پرامپت `mini-sh>` را چاپ کند.
2. یک خط از کاربر بخواند (fgets).
3. خط را به کلمات جدا کند (strtok — جلسهٔ ۱۴).
4. اگر `exit` بود خارج شود.
5. وگرنه با `fork` + `execvp` دستور را اجرا کند (جلسات ۲۷ و ۳۰).

```c
while (1) {
    printf("mini-sh> ");
    fflush(stdout);

    if (fgets(line, sizeof(line), stdin) == NULL) break;

    /* توکن‌بندی */
    char *args[MAX_ARGS];
    int argc = 0;
    char *token = strtok(line, " \n");
    while (token != NULL && argc < MAX_ARGS - 1) {
        args[argc++] = token;
        token = strtok(NULL, " \n");
    }
    args[argc] = NULL;

    if (argc == 0) continue;
    if (strcmp(args[0], "exit") == 0) break;

    pid_t pid = fork();
    if (pid == 0) {
        execvp(args[0], args);
        perror("execvp");        /* اگر دستور ناشناخته بود */
        exit(1);
    } else {
        wait(NULL);              /* منتظر بمان (جلسهٔ ۲۷) */
    }
}
```

## پروژهٔ B: پایگاه‌دادهٔ فایلی

یک برنامهٔ سادهٔ «نوت‌برداری» که رکوردها را به‌صورت متن در فایل `notes.txt` نگه می‌دارد:

- **افزودن (add)**: یک خط به فایل اضافه می‌کند (fopen با "a").
- **نمایش (list)**: همهٔ خطوط فایل را می‌خواند و چاپ می‌کند (fgets).
- **حذف (clear)**: فایل را خالی می‌کند.

```c
void add_note(const char *text) {
    FILE *fp = fopen("notes.txt", "a");   /* حالت append */
    if (fp == NULL) {
        fprintf(stderr, "خطا در باز کردن فایل\n");
        return;
    }
    fprintf(fp, "%s\n", text);            /* جلسهٔ ۲۴ */
    fclose(fp);
}
```

## ترکیب با Makefile و valgrind

```makefile
CC     = gcc
CFLAGS = -Wall -Wextra -g
```

و برای بررسی نشت حافظه:

```bash
valgrind --leak-check=full ./mini_shell
```

## اشتباهات رایج

1. **فراموش کردن `fflush(stdout)`** بعد از پرامپت — پرامپت نمایش داده نمی‌شود.
2. **توکن‌بندی با جداکنندهٔ اشتباه** — حتماً `\n` را هم جدا کنید.
3. **بررسی نکردن `fopen`** — فایل ممکن است باز نشود.
4. **فراموش کردن `wait`** — شل دستور بعدی را قبل از پایان قبلی می‌خواند.
5. **بافر خواندن کوتاه** — `fgets(line, sizeof(line), stdin)` سایز را درست بدهید.

## بهترین شیوه‌ها

- همهٔ مقادیر بازگشتی (fopen، fork، execvp) را بررسی کنید.
- فایل‌ها را حتماً `fclose` کنید.
- پروژه را مرحله‌به‌مرحله بسازید: اول شل بدون fork، بعد با fork، بعد دیتابیس.
- در پایان با valgrind و gdb بررسی کنید.

## خلاصهٔ جلسه و دوره

- مینیشل = fgets + strtok + fork/execvp + wait.
- دیتابیس فایلی = fopen + fprintf + fgets.
- این پروژه ترکیبی از تمام مفاهیم ۵۰ جلسه است — حالا می‌توانید پروژه‌های واقعی C بسازید!
