# جلسهٔ ۴۱ — مرتب‌سازی ادغامی (Merge Sort) و سریع (Quick Sort)

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- ایدهٔ «تقسیم و غلبه» (Divide and Conquer) را درک کنید
- Merge Sort و Quick Sort را از صفر پیاده‌سازی کنید
- پیچیدگی O(n log n) را با O(n²) جلسهٔ قبل مقایسه کنید
- تفاوت حافظهٔ اضافه و پایداری (stability) این دو الگوریتم را بدانید

---

## چرا به مرتب‌سازی بهتر نیاز داریم؟

مرتب‌سازی‌های جلسهٔ ۴۰ (حبابی، انتخابی، درجی) همه O(n²) بودند. برای n = 100,000 یعنی حدود ۱۰ میلیارد عملیات — چند ثانیه تا چند دقیقه. اما Merge/Quick با O(n log n) برای همین داده فقط چند میلیون عملیات انجام می‌دهند.

ایدهٔ کلیدی هر دو: **تقسیم و غلبه** — مسئله را به دو نیمهٔ کوچک‌تر بشکن، هر نیمه را جداگانه حل کن، بعد نتایج را ترکیب کن.

## مرتب‌سازی ادغامی (Merge Sort)

### ایده

1. آرایه را از وسط به دو نیمه تقسیم کن.
2. هر نیمه را بازگشتی مرتب کن.
3. دو نیمهٔ مرتب را در یک آرایهٔ موقت «ادغام» کن.

قسمت ادغام قلب الگوریتم است؛ با دو اشاره‌گر روی دو نیمه راه می‌رویم و همیشه کوچک‌ترین عنصر فعلی را برمی‌داریم:

```c
void merge(int arr[], int l, int m, int r) {
    int n1 = m - l + 1;
    int n2 = r - m;

    int L[n1], R[n2];          // نیمه‌های موقت
    for (int i = 0; i < n1; i++) L[i] = arr[l + i];
    for (int j = 0; j < n2; j++) R[j] = arr[m + 1 + j];

    int i = 0, j = 0, k = l;
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) arr[k++] = L[i++];
        else              arr[k++] = R[j++];
    }
    while (i < n1) arr[k++] = L[i++];   // باقی‌مانده‌های نیمهٔ چپ
    while (j < n2) arr[k++] = R[j++];   // باقی‌مانده‌های نیمهٔ راست
}
```

تابع بازگشتی:

```c
void merge_sort(int arr[], int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;   // دقت: وسطِ امن (بدون سرریز)
        merge_sort(arr, l, m);
        merge_sort(arr, m + 1, r);
        merge(arr, l, m, r);
    }
}
```

نکتهٔ `l + (r - l) / 2` به‌جای `(l + r) / 2`: برای آرایه‌های خیلی بزرگ، `l + r` ممکن است از محدودهٔ `int` رد شود؛ این فرم امن است.

### تحلیل

- زمان: همیشه O(n log n) — مزیت بزرگش این است که حتی بدترین حالت هم خوب است.
- حافظهٔ اضافه: O(n) — یک آرایهٔ موقت در هر سطح ادغام.
- **پایدار است** (عناصر مساوی ترتیب قبلی‌شان را حفظ می‌کنند) — برای مرتب‌سازی struct مهم است.

## مرتب‌سازی سریع (Quick Sort)

### ایده

1. یک عنصر به‌عنوان **محور (pivot)** انتخاب کن (اینجا: عنصر آخر).
2. آرایه را طوری بازچینی کن که عناصر کوچک‌تر از محور سمت چپ و بزرگ‌تر سمت راست بیفتند → این «پارتیشن‌بندی» است.
3. روی دو سمت پارتیشن بازگشتی ادامه بده.

تابع پارتیشن (نسخهٔ Lomuto):

```c
int partition(int arr[], int low, int high) {
    int pivot = arr[high];
    int i = low - 1;                 // مرز عناصر کوچک‌تر از محور

    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }
    swap(&arr[i + 1], &arr[high]);   // محور را سر جایش بگذار
    return i + 1;                    // جای نهایی محور
}

void quick_sort(int arr[], int low, int high) {
    if (low < high) {
        int p = partition(arr, low, high);
        quick_sort(arr, low, p - 1);
        quick_sort(arr, p + 1, high);
    }
}
```

### تحلیل

- میانگین: O(n log n) — در عمل معمولاً سریع‌ترین انتخاب است.
- بدترین حالت: O(n²) — وقتی آرایه از قبل مرتب است و محور همیشه آخرین عنصر باشد.
- حافظهٔ اضافه: O(log n) فقط برای پشتهٔ بازگشت (به‌صورت میانگین).
- **پایدار نیست** — ترتیب عناصر مساوی ممکن است جابه‌جا شود.

## مقایسهٔ خلاصه

| الگوریتم | میانگین | بدترین | حافظهٔ اضافه | پایدار؟ |
|---|---|---|---|---|
| Merge Sort | O(n log n) | O(n log n) | O(n) | بله |
| Quick Sort | O(n log n) | O(n²) | O(log n) | خیر |

## اشتباهات رایج

1. **خطای مرز در merge** — فراموش کردن اینکه نیمهٔ راست از `m + 1` شروع می‌شود و با `r` تمام می‌شود.
2. **فراموش کردن کپی باقی‌مانده‌ها** بعد از حلقهٔ اصلی ادغام — باعث از دست رفتن داده می‌شود.
3. **استفاده از `(l + r) / 2`** که ممکن است سرریز کند.
4. **پارتیشن بدون عنصر پایانی** — فراموش کردن قرار دادن محور در جای نهایی (`swap` آخر).
5. **نادیده گرفتن پایداری** — اگر روی struct با کلید مساوی مرتب می‌کنید و Quick را انتخاب می‌کنید، بدانید که ترتیب را حفظ نمی‌کند.

## بهترین شیوه‌ها

- برای آرایه‌های کوچک (مثلاً < 15 عنصر) بسیاری از پیاده‌سازی‌ها به Insertion Sort سوئیچ می‌کنند — بهینه‌سازی معروف.
- در کد واقعی تقریباً همیشه از `qsort` استاندارد استفاده کنید؛ جلسهٔ ۳۲ (function pointer) آن را دیده‌اید.
- تست با آرایه‌های مرزی: آرایهٔ مرتب، معکوس، یک‌عنصری و خالی.
- برای تمرین، تعداد مقایسه‌ها را بشمارید و برای n مختلف مقایسه کنید.

## خلاصهٔ جلسه

- تقسیم و غلبه: مسئله را بشکن، حل کن، ترکیب کن.
- Merge Sort: تقسیم ساده + ادغام هوشمندانه → همیشه O(n log n)، پایدار، حافظهٔ O(n).
- Quick Sort: پارتیشن‌بندی حول محور → میانگین O(n log n)، ناپایدار، حافظهٔ کم.
