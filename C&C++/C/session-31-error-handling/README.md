# جلسهٔ ۳۱ — مدیریت خطا (errno، perror)

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- با `errno` و `perror` خطاهای سیستم را شناسایی و چاپ کنید
- الگوهای مدیریت خطا در C را بشناسید (کد بازگشتی، errno، goto cleanup)
- برنامه‌های مقاوم در برابر خطا بنویسید

---

## errno چیست؟

`errno` یک متغیر سراسری است که پس از خطای یک تابع سیستمی، **کد خطا** را نگه می‌دارد. برای استفاده باید `<errno.h>` را include کنید:

```c
#include <errno.h>
#include <stdio.h>

FILE *fp = fopen("nothing.txt", "r");
if (fp == NULL) {
    printf("errno = %d\n", errno);
    perror("خطا");        // پیام انسانی چاپ می‌کند
}
```

## perror و strerror

- `perror("پیام")` — پیام ما + توضیح خطا را روی stderr چاپ می‌کند: `پیام: No such file or directory`
- `strerror(errno)` — رشتهٔ توضیح خطا را برمی‌گرداند.

```c
perror("باز کردن فایل");              // چاپ روی stderr
printf("%s\n", strerror(errno));      // فقط متن خطا
```

## الگوهای مدیریت خطا

1. **کد بازگشتی تابع:** تابع ۰ (موفق) یا غیرصفر (خطا) برمی‌گرداند.
2. **چک کردن errno بعد از شکست:** فقط بعد از اینکه تابع نشان داد شکست خورده معتبر است.
3. **goto cleanup برای آزادسازی منابع** هنگام خطا:

```c
FILE *fp = fopen("f.txt", "r");
if (fp == NULL) {
    perror("fopen");
    return 1;
}
// ... استفاده
fclose(fp);
```

## نکات مهم errno

- قبل از صدا زدن تابع، `errno = 0;` بگذارید و بعد چک کنید (چون توابع موفق هم ممکن است errno را تغییر دهند).
- `errno` را فقط بعد از شکست واقعی بخوانید.
- هر thread (نخ) errno مستقل خودش را دارد (جلسهٔ ۴۸).

## اشتباهات رایج

1. **خواندن errno بدون چک کردن اینکه تابع شکست خورده** — مقدار قدیمی/بی‌ربط.
2. **نادیده گرفتن NULL از fopen/malloc** — کرش.
3. **چاپ خطا روی stdout به‌جای stderr** — بهتر است `perror` را روی stderr بدهیم.
4. **مدیریت نکردن نشت منابع هنگام خطا** — در C دستی است.

## بهترین شیوه‌ها

- همیشه مقدار بازگشتی توابع سیستمی را چک کنید.
- برای خطاهای سیستمی از `perror` استفاده کنید.
- در توابع بزرگ، الگوی goto cleanup را برای آزادسازی منابع به کار ببرید.

## خلاصهٔ جلسه

- errno کد خطا، perror/strerror پیام انسانی می‌دهند.
- چک کردن بازگشتی تابع‌ها اجباری است.
- هنگام خطا منابع را آزاد کنید.
