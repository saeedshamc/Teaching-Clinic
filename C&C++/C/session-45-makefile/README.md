# جلسهٔ ۴۵ — Makefile و اتوماسیون Build

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- هدف (target)، وابستگی (dependency) و recipe را در Makefile بنویسید
- متغیرها (CC، CFLAGS) و قواعد الگویی (pattern rules) را استفاده کنید
- با `make` و `make clean` و `make run` پروژه را بسازید
- پروژهٔ چندفایلی جلسهٔ ۲۷ را با Makefile خودکار کنید

---

## چرا Makefile؟

تا حالا هر فایل را جدا کامپایل می‌کردید. وقتی پروژه چند فایل دارد (جلسهٔ ۲۷)، دوباره کامپایل کردن همه چیز هر بار اتلاف وقت است. **make** فقط فایل‌هایی را دوباره می‌سازد که تغییر کرده‌اند و «قدیمی» هستند.

قانون طلایی make: اگر فایل هدف قدیمی‌تر از وابستگی‌هایش باشد، recipe اجرا می‌شود.

## ساختار یک Makefile

```makefile
CC     = gcc
CFLAGS = -Wall -Wextra -g

app: main.o utils.o
	$(CC) $(CFLAGS) -o app main.o utils.o

main.o: main.c utils.h
	$(CC) $(CFLAGS) -c main.c

utils.o: utils.c utils.h
	$(CC) $(CFLAGS) -c utils.c

clean:
	rm -f *.o app
```

- **هدف** (target): چیزی که می‌سازیم (مثل `app` یا `main.o`).
- **وابستگی** (prerequisites): فایل‌هایی که هدف به آن‌ها بستگی دارد.
- **recipe**: خطوط فرمان که با **Tab** شروع می‌شوند (نه فاصله!).
- `.PHONY`: اهدافی که فایل نیستند (`clean`) را معرفی می‌کند تا همیشه اجرا شوند.

## متغیرها

```makefile
CC     = gcc                # کامپایلر
CFLAGS = -Wall -Wextra -g   # پرچم‌های کامپایل
```

استفاده با `$(CC)` — مزیت: یک‌بار تغییر بدهید، همه‌جا اعمال می‌شود.

## هدف‌های پرکاربرد

| دستور | کار |
|---|---|
| `make` یا `make all` | ساخت خروجی اصلی |
| `make clean` | حذف فایل‌های میانی (`.o` و خروجی) |
| `make run` | اجرای برنامه |
| `make debug` | کامپایل با پرچم‌های دیباگ |

## قواعد الگویی (Pattern Rules)

به‌جای نوشتن قانون جدا برای هر `.o`:

```makefile
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```

- `$<` = اولین وابستگی (فایل `.c` متناظر)
- `$@` = نام هدف (فایل `.o`)

## اشتباهات رایج

1. **فاصله به‌جای Tab در recipe** — معروف‌ترین خطای make: `*** missing separator`.
2. **فراموش کردن وابستگی هدرها** — اگر `utils.h` عوض شود ولی `main.o` بازسازی نشود، باگ عجیب می‌گیرید.
3. **نداشتن `clean`** — فایل‌های `.o` قدیمی با تنظیمات قدیمی می‌مانند.
4. **فراموش کردن `.PHONY` برای `clean`/`run`** — اگر فایلی به همین نام وجود داشته باشد، make اجرا نمی‌کندش.
5. **`-g` نبودن در CFLAGS** — برای دیباگ با gdb (جلسهٔ ۴۶) لازم است.

## بهترین شیوه‌ها

- همیشه از `-Wall -Wextra` استفاده کنید.
- در توسعه، `-g` اضافه کنید تا gdb و valgrind مفید باشند.
- `.PHONY: all clean run debug` را بنویسید.
- `clean` همیشه فایل‌های میانی و خروجی را حذف کند.

## خلاصهٔ جلسه

- make فقط فایل‌های قدیمی را بازسازی می‌کند.
- سه بخش هر قانون: هدف، وابستگی، recipe (با Tab).
- متغیرها و pattern rules کد را تمیز نگه می‌دارند.

## تمرین‌ها

### تمرین ۱ (ساده)
یک Makefile برای یک فایل سادهٔ C بنویسید با هدف‌های `all`، `clean` و `run`.

### تمرین ۲ (متوسط)
برای یک پروژهٔ دو فایلی (main.c + utils.c + utils.h) Makefile بنویسید و `-Wall -Wextra -g` را از طریق متغیر `CFLAGS` تنظیم کنید.
