# جلسهٔ ۴۶ — دیباگ با gdb

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- برنامه را با پرچم `-g` کامپایل کنید تا gdb اطلاعات خط داشته باشد
- با دستورهای `run`، `break`، `next`، `step` و `print` دیباگ کنید
- از `backtrace` برای پیدا کردن محل crash استفاده کنید
- مقدار متغیرها و پشتهٔ فراخوانی (call stack) را بررسی کنید

---

## چرا gdb؟

با `printf` دیباگ کردن، کند و ناقص است (باید برنامه را تغییر دهید، دوباره کامپایل کنید). **gdb** به شما اجازه می‌دهد برنامه را قدم‌به‌قدم اجرا کنید، در خط دلخواه متوقف شوید و مقدار هر متغیر را همان لحظه ببینید.

## آماده‌سازی: پرچم -g

```bash
gcc -Wall -Wextra -g -o program program.c
```

پرچم `-g` اطلاعات دیباگ (نام متغیرها، شمارهٔ خطوط) را به خروجی اضافه می‌کند. بدون آن، gdb فقط آدرس‌های بی‌معنی نشان می‌دهد.

## شروع کار

```bash
gdb ./program
```

بعد از ورود به gdb، این دستورهای پایه را یاد بگیرید:

| دستور | کار |
|---|---|
| `run` یا `r` | اجرای برنامه |
| `break main` یا `b main` | توقف در تابع main |
| `break 12` | توقف در خط ۱۲ |
| `next` یا `n` | قدم به جلو (وارد تابع نمی‌شود) |
| `step` یا `s` | قدم به جلو (وارد تابع می‌شود) |
| `print var` یا `p var` | چاپ مقدار متغیر |
| `bt` | backtrace — پشتهٔ فراخوانی |
| `list` یا `l` | نمایش کد اطراف خط فعلی |
| `continue` یا `c` | ادامه تا breakpoint بعدی |
| `quit` یا `q` | خروج |

## مثال کاربردی

برنامهٔ نمونهٔ جلسه:

```c
int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

جلسهٔ دیباگ:

```text
(gdb) break main
(gdb) run
(gdb) next
(gdb) print n
(gdb) step          <- وارد factorial می‌شود
(gdb) print i
(gdb) continue
```

## پیدا کردن crash با backtrace

اگر برنامه segfault داد، داخل gdb `run` کنید و بعد `bt` بزنید — gdb دقیقاً نشان می‌دهد کدام تابع و کدام خط باعث crash شده است. این مهم‌ترین ابزار برای پیدا کردن خطای اشاره‌گرهاست (جلسهٔ ۱۵ به بعد).

## اشتباهات رایج

1. **فراموش کردن `-g`** — gdb نصب است اما اطلاعاتی از خطوط ندارد.
2. **`next` به‌جای `step`** — اگر بخواهید وارد تابع شوید باید `step` بزنید.
3. **دیباگ نسخهٔ قدیمی** — بعد از تغییر کد، دوباره کامپایل نکردن.
4. **کامپایل بدون `-Wall -Wextra`** — خیلی از باگ‌ها را کامپایلر زودتر لو می‌دهد.
5. **دیباگ برنامهٔ بهینه‌شده (`-O2`)** — متغیرها ممکن است بهینه شده باشند؛ در دیباگ از `-O0` یا بدون optimization استفاده کنید.

## بهترین شیوه‌ها

- همیشه با `-g` و بدون optimization دیباگ کنید.
- اول `break` روی خط مشکوک، بعد `print` متغیرها.
- برای باگ‌های منطقی، از `watch` هم می‌توانید استفاده کنید تا تغییر یک متغیر را بگیرید.
- اگر crash است، اول `bt` بزنید تا محل دقیق را پیدا کنید.

## خلاصهٔ جلسه

- `-g` شرط اول دیباگ با gdb است.
- `break`/`run`/`next`/`step`/`print`/`bt` شش دستور اصلی‌اند.
- `bt` بعد از crash، سریع‌ترین راه پیدا کردن محل خطاست.
