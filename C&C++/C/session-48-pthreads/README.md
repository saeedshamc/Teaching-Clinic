# جلسهٔ ۴۸ — برنامه‌نویسی چندنخی (pthreads)

## اهداف یادگیری

در پایان این جلسه می‌توانید:

- نخ (thread) بسازید و با `pthread_join` منتظر پایانش بمانید
- داده را با آرگومان به نخ بفرستید
- رقابت (race condition) را بشناسید و با `pthread_mutex` حل کنید
- برنامه را با فلگ `-pthread` کامپایل کنید

---

## نخ چیست؟

یک برنامه می‌تواند چند «نخ» اجرا کند که همزمان در یک فرایند می‌دوند و حافظهٔ مشترک دارند. مثلاً یک وب‌سرور برای هر کلاینت یک نخ می‌سازد، یا یک برنامهٔ محاسباتی کار را بین چند هستهٔ CPU پخش می‌کند.

مزیت نخ‌ها نسبت به فرایند (fork): **حافظهٔ مشترک** — همهٔ نخ‌ها متغیرهای سراسری یکسانی می‌بینند.

## ساخت نخ

```c
#include <pthread.h>
#include <stdio.h>

void *worker(void *arg) {
    int id = *(int *)arg;
    printf("نخ %d اجرا شد\n", id);
    return NULL;
}

int main(void) {
    pthread_t thread;
    int id = 1;

    pthread_create(&thread, NULL, worker, &id);
    pthread_join(thread, NULL);   /* منتظر پایان نخ بمان */

    return 0;
}
```

- `pthread_create(&thread, NULL, تابع, آرگومان)` — نخ را می‌سازد و تابع را در آن اجرا می‌کند.
- تابع نخ باید `void *worker(void *arg)` باشد.
- `pthread_join(thread, NULL)` — منتظر می‌ماند تا نخ تمام شود (مثل `wait` برای فرایند).

## کامپایل

```bash
gcc -Wall -Wextra -pthread -o program program.c
```

فلگ `-pthread` الزامی است — بدون آن، خطای لینک `undefined reference to 'pthread_create'` می‌گیرید.

## رقابت (Race Condition)

اگر چند نخ متغیر مشترکی را بدون هماهنگی تغییر دهند، نتیجه نامشخص می‌شود:

```c
int counter = 0;   /* مشترک بین همهٔ نخ‌ها */

void *increment(void *arg) {
    for (int i = 0; i < 1000000; i++) {
        counter++;          /* RACE! */
    }
    return NULL;
}
```

دو نخ که همزمان `counter++` می‌کنند، ممکن است یکدیگر را «بازنویسی» کنند و نتیجه از ۲,۰۰۰,۰۰۰ کمتر شود.

## قفل (Mutex)

`pthread_mutex` تضمین می‌کند فقط یک نخ در یک لحظه به بخش بحرانی (critical section) وارد شود:

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

void *increment(void *arg) {
    for (int i = 0; i < 1000000; i++) {
        pthread_mutex_lock(&lock);      /* قفل */
        counter++;                       /* بخش بحرانی */
        pthread_mutex_unlock(&lock);    /* باز کردن قفل */
    }
    return NULL;
}
```

نتیجه حالا همیشه دقیقاً ۲,۰۰۰,۰۰۰ است.

## اشتباهات رایج

1. **فراموش کردن `-pthread`** — خطای لینک.
2. **پاس دادن آدرس متغیر محلی به نخ** — اگر متغیر محلی تابع main بعد از create عوض شود، نخ مقدار اشتباه می‌خواند.
3. **فراموش کردن `pthread_join`** — برنامه ممکن است قبل از تمام شدن نخ‌ها خارج شود.
4. **رقابت بدون قفل** — نتیجهٔ نامشخص.
5. **قفل و بازکردن ناهماهنگ** — اگر یک مسیر return را فراموش کنید، deadlock می‌گیرید.

## بهترین شیوه‌ها

- همیشه `pthread_join` کنید (مخصوصاً برای نخ‌های با حافظهٔ تخصیصی).
- آرگومان را به‌صورت کپی یا در ساختاری که طول عمر تضمینی دارد بفرستید.
- بخش بحرانی را کوتاه نگه دارید.
- خروجی را با یک شمارندهٔ قفل‌شده تست کنید تا مطمئن شوید race ندارید.

## خلاصهٔ جلسه

- `pthread_create` + `pthread_join` برای ساخت و انتظار نخ‌ها.
- نخ‌ها حافظهٔ مشترک دارند → رقابت ممکن است.
- `pthread_mutex_lock/unlock` رقابت را حل می‌کند.
