# جلسه ۱۶: مسیر پایانی — ماژول Note تایپ‌شده (۱۲۰ دقیقه)

**محیط فرض:** TypeScript 5.x · اجرای مثال‌ها با tsx

## پیش‌نیازها
جلسات ۰۸–۱۲ و ۱۴.

## اهداف قابل‌اندازه‌گیری
1. مدل `Note` و عملیات خالص (`add`/`toggle`/`remove`) را تایپ کنید
2. ماژول‌ها را جدا نگه دارید (types / notes / main)
3. با `tsc --noEmit` کل مسیر را سبز کنید
4. مسیر بعدی به [`Reactjs/`](../../Reactjs/) را بدانید

## چرا مهم است؟
جمع‌بندی دوره: داده + جنریک ذهنی + ماژول + strict بدون UI فریم‌ورک.

## مفهوم عمیق
منبع حقیقت: آرایهٔ `Note[]`. توابع جدید آرایه برمی‌گردانند (immutable)، مشابه الگوی جلسه JS ۲۴.

```ts
export type Note = { id: string; text: string; done: boolean };
```

## اشتباه‌های رایج
1. mutate مستقیم آرایهٔ ورودی.
2. `id` از نوع `any`.
3. قاطی کردن parse ورودی کاربر با منطق دامنه.

## مثال گام‌به‌گام
```bash
npx tsc --noEmit
npx tsx session-16-capstone-notes/examples/main.ts
```

## الگوی بهتر
UI (بعداً در React) فقط این توابع را صدا می‌زند؛ نوع‌ها از همین ماژول export می‌شوند.

## تمرین‌ها
### آسان
یک note اضافه و چاپ کنید.
### چالشی
`filterOpen(notes)` فقط `done === false`.

## راهنمای حل
`notes.filter((n) => !n.done)`

## خودآزمایی
1. چرا توابع خالص آرایهٔ جدید برمی‌گردانند؟
2. جداسازی فایل types چه کمکی می‌کند؟
3. چطور کل دوره را typecheck می‌کنید؟
4. قدم بعدی یادگیری چیست؟
5. آیا باید React-project را تغییر دهید؟

## جمع‌بندی و پل
TypeScript را تا سطح قابل‌اتکا برای ورود به React+TS آوردید. پروژهٔ Vite شخصی بسازید؛ مواد [`Reactjs/`](../../Reactjs/) را بخوانید؛ اپ آمادهٔ ریپو را دست نزنید.

SQL / Git / Docker عمداً خارج از این دورهٔ TypeScriptاند.
