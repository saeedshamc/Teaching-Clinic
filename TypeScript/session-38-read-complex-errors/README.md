# جلسه 38: خواندن خطاهای پیچیده — جنریک و conditional (۱۲۰ دقیقه)

**محیط فرض:** Node.js LTS · TypeScript 5.x · `npx tsc --noEmit` · `npx tsx`

## پیش‌نیازها
جلسات ۸، ۲۴، ۲۵.

## اهداف قابل‌اندازه‌گیری
در پایان می‌توانید:

1. خطای چندخطی را از بیرون به درون بخوانید
2. Related information را جدی بگیرید
3. نوع دو طرف را استخراج کنید
4. استراتژی ساده‌سازی نوع را به کار ببرید
5. از any برای خاموشی پرهیز کنید

## چرا مهم است؟
خطاهای mapped/conditional چندلایه ترسناک به نظر می‌رسند؛ با روش خواندن قابل‌هضم می‌شوند.

## مفهوم عمیق

### 1. الگوریتم خواندن

۱ فایل/خط ۲ کد TS ۳ جمله ۴ نوع چپ/راست ۵ Related.

### 2. نام مستعار

نوع‌های میانی نام‌دار برای دیدن hover.

### 3. ساده‌سازی

موقتاً جنریک را با نوع مشخص جایگزین کنید تا بفهمید کجا می‌شکند.

### 4. Excess property

خطاهای object literal جداگانه بشناسید.

### 5. Variance ذهنی

گاهی ناسازگاری تابع از جهت‌گیری نوع است.

### 6. ابزار

ادیتور hover + tsc --pretty.

### 7. دام

اولین as any.

### 8. ثبت

خطاهای پرتکرار تیم را در نوت بگذارید.
