# جلسه 46: عملکرد نوع — پیچیدگی و ضدالگوی هیولا (۱۲۰ دقیقه)

**محیط فرض:** Node.js LTS · TypeScript 5.x · `npx tsc --noEmit` · `npx tsx`

## پیش‌نیازها
جلسات ۲۴–۲۶.

## اهداف قابل‌اندازه‌گیری
در پایان می‌توانید:

1. نشانه‌های نوع هیولایی را بشناسید
2. نوع را به نام‌های میانی بشکنید
3. بگویید سادگی قرارداد بهتر از جادو است
4. چک‌لیست ضد over-engineering بدهید
5. با حذف یک لایه نوع، خوانایی را بالا ببرید

## چرا مهم است؟
نوع‌های بیش‌ازحد هوشمند ادیتور را کند و خطا را غیرقابل‌خواندن می‌کنند.

## برنامه زمانی (۱۲۰ دقیقه)

| زمان | موضوع |
|------|--------|
| ۰–۲۰ | انگیزه و مسئله |
| ۲۰–۴۵ | مفاهیم پایه |
| ۴۵–۷۵ | مفاهیم میانی + مثال |
| ۷۵–۱۰۰ | دام‌ها و الگو |
| ۱۰۰–۱۲۰ | تمرین و خودآزمایی |

---

## مفهوم عمیق

### 1. نشانه‌ها

hover چندصفحه‌ای، tsc کند، پیام خطای غول.

### 2. علل

conditional تو در تو، intersect بزرگ، recursion عمیق.

### 3. راه

نام میانی، ساده‌سازی API، کمتر جادو.

### 4. اندازه API

جنریک کمتر روی مرز عمومی.

### 5. ابزار

گاهی جدا کردن پروژه typecheck.

### 6. دام

بهینه‌سازی زودرس نوع.

### 7. تعادل

ایمنی در برابر پیچیدگی.

### 8. بازبینی

اگر هم‌تیمی نفهمید، پیچیده است.

---

## اشتباه‌های رایج

1. **یک type صدخطی.**
2. **جنریک چهار پارامتری بی‌دلیل.**
3. **recursion عمیق آموزشی در prod.**
4. **نادیده کندی IDE.**
5. **افتخار به پیچیدگی.**
