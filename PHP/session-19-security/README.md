# جلسه ۱۹: امنیت وب — XSS، CSRF، SQLi، آپلود (۱۲۰ دقیقه)

**محیط فرض:** PHP 8.2+

## پیش‌نیازها
جلسات ۱۰، ۱۵، ۱۶.

## اهداف قابل‌اندازه‌گیری
می‌توانید XSS، CSRF، SQL Injection و آپلود ناامن را توضیح دهید؛ ضدالگوی هر کدام را بشناسید؛ و الگوی دفاعی درست را بنویسید (بدون آموزش بهره‌برداری مخرب).

## چرا مهم است؟
بیشتر حوادث اپ‌های PHP از همین چهار خانواده می‌آید. دفاع باید پیش‌فرض باشد نه وصلهٔ بعدی.

## مفهوم عمیق
| تهدید | دفاع آموزشی |
|--------|-------------|
| XSS | `htmlspecialchars` در خروجی HTML |
| SQLi | PDO prepare — هرگز الحاق ورودی در SQL |
| CSRF | توکن در session + فیلد مخفی فرم؛ SameSite |
| آپلود | سفید‌لیست پسوند/MIME، نام تصادفی، خارج از root اجرایی |

رمز عبور: فقط با `password_hash` / `password_verify` (جلسه auth).

## اشتباه‌های رایج
1. blacklist برای آپلود (`evil.php.jpg`).
2. غیرفعال کردن escape «چون داده خودمان است».
3. توکن CSRF ثابت سراسری بدون چرخش.

## مثال گام‌به‌گام
```bash
php session-19-security/examples/01-security.php
```

## الگوی بهتر
دفاع لایه‌ای: validate ورودی، parameterized query، escape خروجی، CSRF روی state-changing POST، آپلود در ذخیرهٔ غیرقابل‌اجرا.

## تمرین‌ها
### آسان
تابع `e(string $s): string` برای escape بنویسید و استفاده کنید.

### چالشی
طرح یک فرم POST با تولید و بررسی توکن CSRF (کد کامل در examples).

## راهنمای حل
`$_SESSION['csrf'] = bin2hex(random_bytes(16));` و مقایسهٔ hash_equals.

## خودآزمایی
1. XSS یعنی چه؟
2. CSRF چه فرقی با XSS دارد؟
3. چرا blacklist آپلود ضعیف است؟
4. hash_equals چرا؟
5. escape کجا لازم است؟
6. SQLi را چطور می‌بندیم؟

## جمع‌بندی و پل جلسهٔ بعد
ذهن امنیتی آماده است. جلسهٔ بعد مینی‌اپ تمرینی جمع‌بندی داخل خود دوره.
