# جلسه ۰۱: Git چیست و سه ناحیه (۹۰ دقیقه)

**محیط فرض:** Git 2.40+ · جزئیات در [SETUP.md](../SETUP.md)

## پیش‌نیازها
ترمینال/PowerShell پایه.

## اهداف قابل‌اندازه‌گیری
1. بگویید Git برای چه چیزی است (تاریخچهٔ تغییرات، نه فقط «آپلود فایل»)
2. سه ناحیه را نام ببرید: working tree، staging (index)، repository (commits)
3. `git --version` را اجرا و خروجی را بخوانید
4. تفاوت snapshot با کپی پوشه‌ای را در یک جمله بگویید

## چرا مهم است؟
بدون مدل سه ناحیه، `add` و `commit` جادو به نظر می‌رسند و اشتباهات بعدی تکراری می‌شوند.

## مفهوم عمیق
```
[ فایل‌های در حال ویرایش ]  = working tree
        | git add
[ آماده‌ی ثبت ]            = staging / index
        | git commit
[ تاریخچهٔ ثبت‌شده ]       = commits در .git
```

هر commit یک snapshot از پروژه در آن لحظه است (با اشاره به والدین).

## اشتباه‌های رایج
1. فکر کردن که Git فقط برای GitHub است.
2. قاطی کردن «ذخیره در ادیتور» با commit.
3. تمرین روی ریپوی واقعی Clinic به‌جای sandbox.

## مثال گام‌به‌گام
```powershell
powershell -File Git/session-01-intro/examples/01-three-areas.ps1
```

## الگوی بهتر
قبل از هر دستور مخرب‌نما بپرسید: «آیا داخل sandbox هستم؟»

## تمرین‌ها
### آسان
`git --version` را اجرا کنید.
### چالشی
سه ناحیه را روی کاغذ برای یک تغییر تک‌فایلی بکشید.

## راهنمای حل
ویرایش → working؛ `add` → staging؛ `commit` → تاریخچه.

## خودآزمایی
1. Git چیست؟
2. staging چه نقشی دارد؟
3. آیا ذخیرهٔ ادیتور همان commit است؟
4. چرا sandbox؟
5. خروجی `git --version` چه می‌گوید؟

## جمع‌بندی و پل جلسهٔ بعد
مدل ذهنی. جلسه بعد: init و اولین commit.
