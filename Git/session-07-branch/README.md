# جلسه ۰۷: شاخه و switch (۹۰ دقیقه)

**محیط فرض:** Git · sandbox

## پیش‌نیازها
جلسات ۰۲–۰۳.

## اهداف قابل‌اندازه‌گیری
1. شاخه بسازید و با `switch` جابه‌جا شوید
2. بگویید شاخه فقط یک اشاره‌گر به commit است
3. کار موازی روی دو شاخه را نشان دهید
4. `branch` را لیست کنید

## چرا مهم است؟
بدون شاخه، هر آزمایش روی `main` خطر خراب کردن خط اصلی را دارد.

## مفهوم عمیق
```powershell
git switch -c feature/login
# کار و commit
git switch main
```

`checkout -b` معادل قدیمی‌تر ساخت+جابه‌جایی است؛ در این دوره `switch` ترجیح داده می‌شود.

## اشتباه‌های رایج
1. commit روی main اشتراکی برای هر آزمایش.
2. فراموش کردن switch قبل از شروع کار.
3. نام شاخهٔ بی‌معنا (`tmp123`).

## مثال گام‌به‌گام
```powershell
powershell -File Git/session-07-branch/examples/01-branch.ps1
```

## الگوی بهتر
نام: `feature/...`، `fix/...`؛ یک موضوع در هر شاخه.

## تمرین‌ها
### آسان
شاخه `feature/hello` بسازید و یک commit بزنید.
### چالشی
روی main یک commit دیگر بزنید و ببینید تاریخچه‌ها جدا می‌مانند.

## راهنمای حل
بعد از commit روی feature، `switch main` و commit جدا؛ `log --oneline --all --graph`.

## خودآزمایی
1. شاخه چیست؟
2. `switch -c` چه می‌کند؟
3. چرا روی main آزمایش نکنیم؟
4. چگونه لیست شاخه‌ها؟
5. آیا فایل‌های uncommitted با switch جابه‌جا می‌شوند؟

## جمع‌بندی و پل جلسهٔ بعد
شاخه. جلسه بعد: merge.
