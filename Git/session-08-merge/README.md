# جلسه ۰۸: merge و تعارض ساده (۹۰ دقیقه)

**محیط فرض:** Git · sandbox

## پیش‌نیازها
جلسه ۰۷.

## اهداف قابل‌اندازه‌گیری
1. `git merge` یک feature روی main را اجرا کنید
2. fast-forward را از merge commit تشخیص دهید
3. یک تعارض ساده را در فایل ببینید و حل کنید
4. بعد از حل، `add` + تکمیل merge را انجام دهید

## چرا مهم است؟
ادغام شاخه‌ها کار روزمرهٔ تیمی است؛ ترس از conflict با تمرین کم می‌شود.

## مفهوم عمیق
```powershell
git switch main
git merge feature/hello
```

تعارض: Git نشانه‌های `<<<<<<<` می‌گذارد؛ شما نسخهٔ درست را نگه می‌دارید، stage می‌کنید، merge را تمام می‌کنید.

## اشتباه‌های رایج
1. رها کردن merge نیمه‌کاره.
2. commit کردن فایل با نشانه‌های conflict.
3. merge بدون دیدن `log --graph`.

## مثال گام‌به‌گام
```powershell
powershell -File Git/session-08-merge/examples/01-merge-conflict.ps1
```

## الگوی بهتر
شاخه‌های کوتاه‌عمر؛ pull/merge مکرر از main برای کم کردن تعارض بزرگ.

## تمرین‌ها
### آسان
feature بدون تعارض را merge کنید.
### چالشی
تعارض را دستی حل و merge را تمام کنید.

## راهنمای حل
نشانه‌ها را پاک کنید، محتوای نهایی را بنویسید، `git add`، سپس `git commit` (اگر merge commit لازم بود).

## خودآزمایی
1. fast-forward یعنی چه؟
2. نشانه‌های تعارض کدام‌اند؟
3. بعد از حل چه می‌کنید؟
4. چگونه merge را abort کنیم؟
5. چرا شاخهٔ کوتاه بهتر است؟

## جمع‌بندی و پل جلسهٔ بعد
merge. جلسه بعد: rebase محلی.
