# جلسه ۱۳: GitHub مفهومی — PR و همکاری (۹۰ دقیقه)

**محیط فرض:** خواندنی · بدون push اجباری به GitHub یا Clinic

## پیش‌نیازها
جلسات ۱۱–۱۲ · آشنایی با [`Bash/session-25-ci-cd-basics`](../../Bash/session-25-ci-cd-basics/) مفید است ولی اجباری نیست.

## اهداف قابل‌اندازه‌گیری
1. Pull Request (PR) را توضیح دهید
2. نقش review و CI سبز قبل از merge را بگویید
3. تفاوت branch روی remote میزبان با bare محلی را بدانید
4. بگویید این جلسه نیاز به تغییر `origin` ریپوی Clinic ندارد

## چرا مهم است؟
بیشتر همکاری واقعی روی GitHub/GitLab با PR اتفاق می‌افتد؛ Git خام همان زیرساخت است.

## مفهوم عمیق
```
1) از main شاخه بساز
2) push به fork/remote شخصی
3) PR باز کن: هدف = main
4) review + CI
5) merge (با دکمه یا محلی)
```

Issue برای بحث/باگ؛ PR برای پیشنهاد کد.

## اشتباه‌های رایج
1. PR بدون توضیح.
2. merge با CI قرمز بدون دلیل.
3. push --force به main بعد از review.

## مثال گام‌به‌گام
فایل `examples/01-pr-checklist.md` را بخوانید. اسکریپت اجرایی لازم نیست.

## الگوی بهتر
عنوان PR واضح؛ توصیف کوتاه؛ لینک به Issue اگر هست.

## تمرین‌ها
### آسان
چک‌لیست PR را برای یک تغییر فرضی پر کنید.
### چالشی
در ریپوی عمومی دلخواه (نه اجباری Clinic) یک PR باز را فقط بخوانید و بخش‌هایش را نام ببرید.

## راهنمای حل
عنوان، توضیحات، فایل‌های تغییر، چک‌ها، مکالمهٔ review.

## خودآزمایی
1. PR چیست؟
2. CI چه نقشی دارد؟
3. چرا force به main بد است؟
4. Issue چه فرقی با PR دارد؟
5. آیا باید origin کلینیک را عوض کنید؟

## جمع‌بندی و پل جلسهٔ بعد
همکاری میزبان. جلسه بعد: دستورات خطرناک در sandbox.
