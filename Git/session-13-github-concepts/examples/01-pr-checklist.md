# چک‌لیست مفهومی Pull Request

## قبل از باز کردن
- [ ] از main به‌روز شاخه ساختم
- [ ] commitها موضوع واحد دارند
- [ ] `status` تمیز است (یا فقط تغییرات عمدی)
- [ ] تست/typecheck محلی اگر پروژه دارد

## متن PR
- [ ] عنوان کوتاه و دقیق
- [ ] خلاصهٔ ۱–۳ خط: چرا این تغییر
- [ ] نحوهٔ تست دستی

## بعد از باز شدن
- [ ] CI سبز (اگر تعریف شده)
- [ ] حداقل یک review وقتی تیم دارد
- [ ] بدون `push --force` به main

## یادآوری Teaching Clinic
روی ریپوی Clinic برای آموزش این جلسه لازم نیست چیزی push کنید.
مدل شاخه را در sandbox جلسات ۱۱–۱۲ تمرین کردید.
