# جلسه ۱۲: Auth مفهومی (الگوها، نه قفل به یک Vendor) (۹۰ دقیقه)

## پیش‌نیاز
جلسات ۰۵، ۱۰، ۱۱

## اهداف یادگیری
1. الگوهای session cookie، JWT، و provider خارجی را مقایسه کنید.
2. بگویید چرا Auth فقط کلاینتی کافی نیست.
3. محل چک: middleware + server guard + DB.

## چرا مهم است
انتخاب Auth بدون مدل تهدید = حس امنیت کاذب.

## مفهوم اصلی
- **Session سمت سرور:** کنترل ابطال آسان‌تر
- **JWT:** مقیاس‌پذیرتر ولی ابطال سخت‌تر
- **Provider (Auth.js، Clerk، Cognito، ...):** سرعت راه‌اندازی در برابر وابستگی vendor

این جلسه پیاده‌سازی قفل‌شده به یک فروشنده ندارد؛ الگو را بفهمید، بعد ابزار را انتخاب کنید.

## اشتباهات رایج
1. فقط مخفی کردن لینک در UI.
2. نگه داشتن نقش کاربر فقط در localStorage.
3. اعتماد به middleware به‌تنهایی بدون بررسی سرور.

## تمرین
### آسان
جدول مقایسهٔ سه الگو (۵ سطر).
### چالش
برای اپ آموزشگاه، انتخاب الگو را با ۲ استدلال بنویسید.

## خودآزمایی
- [ ] سه الگو را بلدم
- [ ] UI ≠ امنیت
- [ ] vendor lock را می‌فهمم
- [ ] cookie HttpOnly را شنیده‌ام
- [ ] دفاع لایه‌ای بلدم

## جمع‌بندی + پل
ذهنیت auth. جلسهٔ بعد deploy.
