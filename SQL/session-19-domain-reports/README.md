# جلسه ۱۹: گزارش‌گیری روی دامنه (۹۰ دقیقه)

**محیط فرض:** SQLite 3 · ادامهٔ دامنه کتابخانه

## پیش‌نیازها
جلسات ۰۸–۰۹ و ۱۸.

## اهداف قابل‌اندازه‌گیری
1. امانت‌های باز را با JOIN لیست کنید
2. تعداد امانت هر عضو را تجمیع کنید
3. کتاب‌های هرگز امانت‌داده‌نشده را با LEFT JOIN پیدا کنید
4. یک گزارش تاریخ‌محور ساده بنویسید

## چرا مهم است؟
اسکیما بدون گزارش ارزش عملی کمی دارد.

## مفهوم عمیق
همان جداول جلسه ۱۸؛ تمرکز روی SELECTهای معنادار.

## اشتباه‌های رایج
1. فیلتر `returned_at = ''` به‌جای `IS NULL`.
2. تجمیع بدون GROUP BY درست.
3. فراموش ساخت دوبارهٔ seed قبل از گزارش.

## مثال گام‌به‌گام
```bash
sqlite3 library.db < session-18-domain-schema/examples/01-schema-seed.sql
sqlite3 library.db < session-19-domain-reports/examples/01-reports.sql
```

## الگوی بهتر
هر گزارش یک فایل؛ نام واضح.

## تمرین‌ها
### آسان
لیست امانت باز با نام عضو و عنوان کتاب.
### چالشی
عضوی با بیشترین تعداد امانت (باز یا بسته).

## راهنمای حل
`GROUP BY member_id ORDER BY COUNT(*) DESC LIMIT 1`

## خودآزمایی
1. امانت باز یعنی چه؟
2. کتاب بدون امانت چگونه؟
3. چرا seed را تکرار می‌کنیم؟
4. HAVING کجا در گزارش؟
5. تاریخ را چطور مقایسه کنیم؟
