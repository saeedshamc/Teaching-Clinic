# جلسه ۱۵: تراکنش‌ها (۹۰ دقیقه)

**محیط فرض:** SQLite 3

## پیش‌نیازها
جلسه ۰۶.

## اهداف قابل‌اندازه‌گیری
1. `BEGIN` / `COMMIT` / `ROLLBACK` را اجرا کنید
2. بگویید تراکنش چه اتمی‌تی می‌دهد
3. یک سناریوی انتقال وجه آموزشی را با rollback نشان دهید
4. خطر تغییر نیمه‌کاره بدون تراکنش را توضیح دهید

## چرا مهم است؟
چند نوشتن وابسته باید همه با هم موفق یا همه لغو شوند.

## مفهوم عمیق
```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
-- یا ROLLBACK;
```

## اشتباه‌های رایج
1. فراموش COMMIT و قفل ماندن.
2. فرض اینکه هر دستور جدا خودکار برای چند جدول کافی است.
3. ROLLBACK بعد از COMMIT.

## مثال گام‌به‌گام
```bash
sqlite3 clinic.db < session-15-transactions/examples/01-transactions.sql
```

## الگوی بهتر
در اپ، تراکنش دور واحد کار کسب‌وکار (نه دور هر INSERT کوچک بی‌ربط).

## تمرین‌ها
### آسان
دو UPDATE داخل تراکنش و COMMIT.
### چالشی
عمداً قبل از COMMIT یک ROLLBACK بزنید و نتیجه را ببینید.

## راهنمای حل
بعد از ROLLBACK موجودی باید به حالت اول برگردد.

## خودآزمایی
1. اتمی بودن یعنی چه؟
2. BEGIN چه می‌کند؟
3. تفاوت COMMIT و ROLLBACK؟
4. اگر برنامه وسط کار کرش کند؟
5. تراکنش خواندنی صرف کی لازم است؟

## جمع‌بندی و پل جلسهٔ بعد
تراکنش. جلسه بعد: قیود و FK واقعی.
