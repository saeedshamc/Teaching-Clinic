# جلسه ۱۴: ایندکس و EXPLAIN QUERY PLAN (۹۰ دقیقه)

**محیط فرض:** SQLite 3

## پیش‌نیازها
جلسات ۰۵ و ۰۷.

## اهداف قابل‌اندازه‌گیری
1. بگویید ایندکس چیست و روی چه ستون‌هایی معمولاً می‌گذاریم
2. `CREATE INDEX` بنویسید
3. خروجی ابتدایی `EXPLAIN QUERY PLAN` را بخوانید
4. بگویید ایندکس رایگان نیست (هزینهٔ نوشتن/فضا)

## چرا مهم است؟
جدول بزرگ بدون ایندکس روی فیلترهای پرتکرار کند می‌شود.

## مفهوم عمیق
```sql
CREATE INDEX idx_orders_user_id ON orders(user_id);
EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE user_id = 1;
```

ایندکس روی PK معمولاً خودکار است.

## اشتباه‌های رایج
1. ایندکس روی هر ستون.
2. ایندکس نکردن FKهای پرتکرار در join.
3. انتظار معجزه روی جدول خیلی کوچک (تفاوت محسوس نیست).

## مثال گام‌به‌گام
```bash
sqlite3 clinic.db < session-14-indexes/examples/01-indexes.sql
```

## الگوی بهتر
ایندکس بر اساس WHERE/JOIN واقعی؛ بعد از دیدن plan تصمیم بگیرید.

## تمرین‌ها
### آسان
ایندکس روی `orders(user_id)`.
### چالشی
دو EXPLAIN قبل/بعد ایندکس را مقایسه و یک جمله بنویسید.

## راهنمای حل
به‌دنبال SCAN در برابر SEARCH/USING INDEX در خروجی باشید.

## خودآزمایی
1. ایندکس چه کمکی می‌کند؟
2. هزینهٔ ایندکس چیست؟
3. روی PK لازم است دستی بسازیم؟
4. EXPLAIN QUERY PLAN برای چیست؟
5. ایندکس ترکیبی کی؟

## جمع‌بندی و پل جلسهٔ بعد
ایندکس. جلسه بعد: تراکنش.
