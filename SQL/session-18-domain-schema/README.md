# جلسه ۱۸: اسکیمای دامنهٔ آموزشی — کتابخانه (۹۰ دقیقه)

**محیط فرض:** SQLite 3 · دامنه: امانت کتاب

## پیش‌نیازها
جلسات ۱۳ و ۱۶.

## اهداف قابل‌اندازه‌گیری
1. جداول members، books، loans را طراحی و بسازید
2. FK و قیود لازم را بگذارید
3. دادهٔ seed اولیه وارد کنید
4. بگویید چرا loan جدول جداست (رابطهٔ چندبه چند زمانی)

## چرا مهم است؟
تمرین طراحی واقعی قبل از گزارش و capstone.

## مفهوم عمیق
- عضو کتاب امانت می‌گیرد.
- هر امانت: یک عضو + یک کتاب + تاریخ.
- کتاب نباید همزمان دو امانت باز داشته باشد (در capstone ساده‌سازی می‌کنیم؛ اینجا اسکیما پایه).

## اشتباه‌های رایج
1. نگه داشتن همه چیز در یک جدول.
2. تاریخ را عدد بی‌معنا کردن بدون قرارداد ISO.
3. خاموش بودن foreign_keys.

## مثال گام‌به‌گام
```bash
sqlite3 library.db < session-18-domain-schema/examples/01-schema-seed.sql
sqlite3 library.db ".tables"
```

## الگوی بهتر
نام جداول جمع معنادار؛ کلیدها پایدار؛ PRAGMA روشن.

## تمرین‌ها
### آسان
یک عضو و دو کتاب اضافه کنید.
### چالشی
یک loan با تاریخ `returned_at` خالی (هنوز برنگشته).

## راهنمای حل
`returned_at TEXT NULL` برای امانت باز.

## خودآزمایی
1. چرا جدول loans لازم است؟
2. FKها کدام‌اند؟
3. seed چیست؟
4. امانت باز را چطور مدل می‌کنید؟
5. PRAGMA کجا؟

## جمع‌بندی و پل جلسهٔ بعد
اسکیما. جلسه بعد: گزارش‌ها.
