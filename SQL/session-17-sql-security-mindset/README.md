# جلسه ۱۷: ذهنیت امن SQL (۹۰ دقیقه)

**محیط فرض:** مفهومی + نمونهٔ متنی · بدون آموزش بهره‌برداری مخرب

## پیش‌نیازها
جلسات ۰۵–۰۶ · آشنایی ذهنی با لایهٔ اپ.

## اهداف قابل‌اندازه‌گیری
1. بگویید الحاق ورودی کاربر داخل رشتهٔ SQL چرا خطرناک است
2. الگوی parameterization / prepared statement را توضیح دهید
3. اصل حداقل دسترسی و عدم نمایش جزئیات خطای داخلی به کاربر را بشناسید
4. مسیر بعدی را به [`PHP/session-16-pdo-basics`](../../PHP/session-16-pdo-basics/) وصل کنید

## چرا مهم است؟
SQL Injection هنوز از رایج‌ترین آسیب‌هاست. دفاع باید پیش‌فرض باشد.

## مفهوم عمیق
ضدالگوی مفهومی (انجام ندهید):

```text
"SELECT * FROM users WHERE email = '" + userInput + "'"
```

الگوی درست در اپ:

```text
prepare: SELECT * FROM users WHERE email = ?
execute with bound value: userInput
```

در این دورهٔ SQL خام، شما مقدارها را خودتان در اسکریپت می‌نویسید؛ خطر وقتی است که **ورودی بیرونی** به رشتهٔ SQL بچسبد.

## اشتباه‌های رایج
1. اعتماد به «validate کردم پس الحاق امن است».
2. نمایش stack/SQL خام به کاربر نهایی.
3. اتصال دیتابیس با دسترسی ادمین برای اپ وب.

## مثال گام‌به‌گام
فایل `examples/01-safe-patterns.md` را بخوانید. این جلسه فایل `.sql` مخرب برای حمله ندارد.

## الگوی بهتر
همیشه placeholder در لایهٔ اپ؛ نقش DB محدود؛ لاگ امن.

## تمرین‌ها
### آسان
یک جمله بنویسید که تفاوت الحاق و bind را بگوید.
### چالشی
در README جلسهٔ PHP مربوطه، محل `prepare` را پیدا و نقل‌قول کنید.

## راهنمای حل
در PHP: `$pdo->prepare('... ? ...'); $stmt->execute([$value]);`

## خودآزمایی
1. الحاق رشته چرا بد است؟
2. prepared statement چیست؟
3. آیا escape دستی به‌جای prepare کافی است؟
4. حداقل دسترسی یعنی چه؟
5. قدم بعدی در این ریپو کدام جلسه PHP است؟
