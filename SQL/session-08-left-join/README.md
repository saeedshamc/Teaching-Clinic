# جلسه ۰۸: LEFT JOIN و NULL (۹۰ دقیقه)

**محیط فرض:** SQLite 3

## پیش‌نیازها
جلسه ۰۷.

## اهداف قابل‌اندازه‌گیری
1. LEFT JOIN بنویسید
2. بگویید چرا کاربر بدون سفارش در INNER غایب و در LEFT حاضر است
3. فیلتر `WHERE o.id IS NULL` را برای «بدون سفارش» به کار ببرید
4. تفاوت معنایی LEFT با INNER را در یک جمله بگویید

## چرا مهم است؟
گزارش «کاربران بدون خرید» بدون LEFT سخت است.

## مفهوم عمیق
```sql
SELECT u.name, o.total
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;
```

طرف چپ حفظ می‌شود؛ اگر راست نباشد، ستون‌های راست NULL می‌شوند.

## اشتباه‌های رایج
1. گذاشتن شرط روی جدول راست در WHERE به‌جای ON و تبدیل ناخواسته به INNER.
2. فرض اینکه LEFT همیشه سریع‌تر است.
3. فراموش IS NULL برای یافتن بی‌تطبیق.

## مثال گام‌به‌گام
```bash
sqlite3 clinic.db < session-08-left-join/examples/01-left-join.sql
```

## الگوی بهتر
شرط رابطه در ON؛ فیلتر کسب‌وکار روی نتیجهٔ نهایی با آگاهی از NULL.

## تمرین‌ها
### آسان
لیست همهٔ کاربران با total (یا NULL).
### چالشی
فقط کاربرانی که هیچ سفارشی ندارند.

## راهنمای حل
`LEFT JOIN ... WHERE o.id IS NULL`

## خودآزمایی
1. LEFT چه چیزی را حفظ می‌کند؟
2. چرا شرط راست در WHERE خطرناک است؟
3. یافتن بدون‌تطبیق چگونه است؟
4. RIGHT JOIN در SQLite؟ (پشتیبانی محدود/معمولاً با جابه‌جایی چپ شبیه‌سازی)
5. یک کاربرد گزارش بگویید.

## جمع‌بندی و پل جلسهٔ بعد
LEFT. جلسه بعد: تجمیع و GROUP BY.
