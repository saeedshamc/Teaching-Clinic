# جلسه ۱۳: نرمال‌سازی مفهومی تا 3NF (۹۰ دقیقه)

**محیط فرض:** SQLite 3 · تمرکز طراحی نه formal proof

## پیش‌نیازها
جلسات ۰۷–۰۸.

## اهداف قابل‌اندازه‌گیری
1. مشکل تکرار داده را با مثال نشان دهید
2. 1NF/2NF/3NF را در یک جملهٔ کاربردی بگویید
3. جدول تکراری را به جداول مرتبط بشکنید
4. بگویید نرمال‌سازی بیش‌ازحد هم هزینه دارد

## چرا مهم است؟
اسکیمای بد یعنی آنومالی به‌روزرسانی و گزارش غلط.

## مفهوم عمیق
- **1NF:** مقادیر اتمی؛ نه لیست داخل سلول.
- **2NF:** وابستگی کامل به کلید (برای کلید مرکب).
- **3NF:** بدون وابستگی گذراندنی بین غیرکلیدها (مثل city → province داخل جدول کاربر اگر province فقط به city وابسته است).

مثال بد: ستون `products` در سفارش به‌صورت `'A,B,C'`.

## اشتباه‌های رایج
1. ذخیرهٔ چند مقدار با ویرگول در یک TEXT.
2. کپی نام و قیمت کالا داخل هر سطر سفارش بدون جدول product (حداقل id لازم است؛ snapshot قیمت گاهی عمدی است).
3. نرمال کردن تا جایی که هر گزارش ۱۰ join لازم داشته باشد بدون نیاز.

## مثال گام‌به‌گام
```bash
sqlite3 clinic.db < session-13-normalization/examples/01-normalize.sql
```

## الگوی بهتر
دامنه را جدا کنید؛ برای تاریخچهٔ قیمت، تصمیم صریح بگیرید (snapshot در سفارش).

## تمرین‌ها
### آسان
یک جدول بد با لیست ویرگولی را به دو جدول بشکنید.
### چالشی
توضیح دهید چرا نگه داشتن `unit_price` روی order_items گاهی درست است.

## راهنمای حل
قیمت کالا بعداً عوض می‌شود؛ فاکتور باید قیمت زمان خرید را نگه دارد.

## خودآزمایی
1. 1NF یعنی چه؟
2. آنومالی به‌روزرسانی چیست؟
3. کی denormalize می‌کنیم؟
4. کلید مرکب کجا دیده می‌شود؟
5. رابطهٔ چند به چند چگونه حل می‌شود؟

## جمع‌بندی و پل جلسهٔ بعد
طراحی. جلسه بعد: ایندکس.
