# جلسه ۰۴: INSERT (۹۰ دقیقه)

**محیط فرض:** SQLite 3

## پیش‌نیازها
جلسه ۰۳.

## اهداف قابل‌اندازه‌گیری
1. یک‌ردیفی و چندردیفی INSERT بنویسید
2. ترتیب ستون‌ها را با لیست صریح کنترل کنید
3. خطای UNIQUE/NOT NULL را تفسیر کنید
4. بگویید چرا INSERT بدون لیست ستون شکننده است

## چرا مهم است؟
ورود دادهٔ اولیه و seed تست از INSERT می‌آید.

## مفهوم عمیق
```sql
INSERT INTO users (email, name) VALUES ('a@ex.com', 'علی');
INSERT INTO users (email, name) VALUES
  ('b@ex.com', 'سارا'),
  ('c@ex.com', 'رضا');
```

اگر `id` را ندهید، SQLite معمولاً مقدار بعدی کلید را می‌سازد.

## اشتباه‌های رایج
1. `INSERT INTO users VALUES (...)` بدون نام ستون پس از تغییر اسکیما.
2. کوتیشن اشتباه دور رشته.
3. درج تکراری email و تعجب از خطا.

## مثال گام‌به‌گام
```bash
sqlite3 clinic.db < session-04-insert/examples/01-insert-users.sql
```

## الگوی بهتر
همیشه ستون‌ها را نام ببرید. برای seed، یک فایل جدا (`seed.sql`).

## تمرین‌ها
### آسان
سه کاربر با ایمیل یکتا درج کنید.
### چالشی
عمداً email تکراری بدهید و پیام خطا را بخوانید.

## راهنمای حل
پیام شبیه `UNIQUE constraint failed: users.email`.

## خودآزمایی
1. چندردیفی چگونه است؟
2. چرا نام ستون مهم است؟
3. اگر id ندهیم چه می‌شود؟
4. خطای NOT NULL کی رخ می‌دهد؟
5. seed یعنی چه؟

## جمع‌بندی و پل جلسهٔ بعد
داده وارد شد. جلسه بعد: SELECT و WHERE.
