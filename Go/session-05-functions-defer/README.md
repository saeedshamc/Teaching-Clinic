# جلسه ۰۵: توابع، چند مقدار برگشتی و defer (۹۰ دقیقه)

**محیط فرض:** Go 1.22+

## پیش‌نیاز
- جلسات ۰۱ تا ۰۴

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. تابع با پارامتر و چند مقدار برگشتی بنویسید
2. الگوی رایج `(value, error)` را به‌کار ببرید
3. با **named result** در حد خوانایی آشنا شوید
4. `defer` را برای آزادسازی منبع درست زمان‌بندی کنید

## چرا این مطلب مهم است
در Go استثنا (exception) رایج نیست؛ خطا مقدار برگشتی است. `defer` هم برای بستن فایل/قفل حیاتی است — اگر ترتیب defer را نفهمید، منبع نشت می‌کند یا زود بسته می‌شود.

## مفهوم اصلی

### چند مقدار برگشتی
```go
func Div(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("division by zero")
	}
	return a / b, nil
}
```

### defer
`defer f()` اجرای `f` را تا خروج از تابع جاری عقب می‌اندازد. چند `defer` به‌صورت LIFO اجرا می‌شوند. آرگومان‌های defer همان لحظهٔ ثبت evaluate می‌شوند.

```go
f, err := os.Open("a.txt")
if err != nil { return err }
defer f.Close()
```

## اشتباهات رایج
1. **نادیده گرفتن خطا با `_` همه‌جا** — باگ‌ها خاموش می‌شوند.
2. **فراخوانی `Close` بدون defer و return میانی** — مسیر خطا فایل را باز می‌گذارد.
3. **فرض اینکه defer آرگومان را دیر evaluate می‌کند** — مقدارها همان موقع کپی می‌شوند؛ برای دیدن اثر جانبی دقیق، با متغیر اشاره‌گر یا بستن روی متغیر نهایی تمرین کنید.

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-05-functions-defer/examples
go run .
```

```go
package main

import "fmt"

func Div(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("division by zero")
	}
	return a / b, nil
}

func main() {
	defer fmt.Println("پایان main")
	q, err := Div(10, 2)
	if err != nil {
		fmt.Println("خطا:", err)
		return
	}
	fmt.Println("خارج‌قسمت:", q)
}
```

## نسخهٔ بهتر / الگوی درست
خطا را همان لایه مدیریت یا با context بپیچید (جلسهٔ errors). `defer Close` را بلافاصله بعد از Open موفق بگذارید.

## تمرین عملی

### آسان
تابع `Swap(a, b int) (int, int)` بنویسید که دو مقدار را جابه‌جا برگرداند.

### چالش
تابعی شبیه‌سازی کنید که سه `defer fmt.Println` با پیام‌های ۱،۲،۳ ثبت کند و ترتیب چاپ را پیش‌بینی و تأیید کنید.

## راهنمای راه‌حل (چالش)
خروجی باید ۳ سپس ۲ سپس ۱ باشد (LIFO)، بعد بقیهٔ بدنه اگر چیزی مانده باشد طبق ترتیب اجرا.
