# جلسه ۱۷: ساخت HTTP API آموزشی کوچک (۱۲۰ دقیقه)

**محیط فرض:** Go 1.22+ · پورت آزاد 8080

## پیش‌نیاز
- جلسه ۱۶ (net/http) و ۱۵ (json)

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. یک API حافظه‌ای برای «یادداشت‌ها» با لیست و ایجاد بسازید
2. کد وضعیت درست (200/201/400/404) برگردانید
3. state را با mutex در برابر race محافظت کنید
4. ساختار handler / store را جدا کنید

## چرا این مطلب مهم است
تمرین نزدیک به واقعیت بدون دیتابیس: قرارداد HTTP، اعتبارسنجی، و همگام‌سازی حافظه.

## مفهوم اصلی
لایهٔ `Store` داده را نگه می‌دارد؛ handler فقط HTTP را ترجمه می‌کند. برای آموزش in-memory کافی است؛ بعداً می‌توان Store را با DB عوض کرد (مثل interface جلسه ۸).

## اشتباهات رایج
1. **map بدون mutex در سرور همزمان**
2. **همیشه 200 برگرداندن حتی برای ورودی بد**
3. **قاطی کردن منطق دامنه داخل handler شلوغ**

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-17-http-api/examples
go run .
```

سپس:
```bash
curl -s http://127.0.0.1:8080/notes
curl -s -X POST http://127.0.0.1:8080/notes -H "Content-Type: application/json" -d "{\"title\":\"اولین\"}"
```

## نسخهٔ بهتر / الگوی درست
ID را سمت سرور بسازید؛ ورودی را validate کنید؛ خطاها را یکدست JSON برگردانید.

## تمرین عملی

### آسان
endpoint گرفتن یک یادداشت با `GET /notes/{id}` اضافه کنید (در Go 1.22 از الگوی مسیر استفاده کنید یا query `?id=`).

### چالش
`DELETE /notes/{id}` با 204 یا 404.

## راهنمای راه‌حل (چالش)
در Store متد Delete؛ اگر نبود false؛ handler بر اساس آن وضعیت بدهد.

## خودآزمایی
- [ ] جداسازی store/handler بلدم
- [ ] mutex برای map بلدم
- [ ] 201 برای ایجاد بلدم
- [ ] JSON خطا یکدست می‌نویسم
- [ ] validate عنوان خالی بلدم
- [ ] می‌دانم in-memory فقط آموزشی است

## جمع‌بندی + پل به جلسه بعد
API کوچک کار می‌کند. جلسهٔ بعد ساختار پروژه واقعی: `cmd` / `internal` / `pkg`.
