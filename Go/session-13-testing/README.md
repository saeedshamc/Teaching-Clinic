# جلسه ۱۳: تست table-driven و benchmark مقدماتی (۱۲۰ دقیقه)

**محیط فرض:** Go 1.22+

## پیش‌نیاز
- جلسات ۰۱ تا ۱۲ · آشنایی با `go test` از جلسه ۰۲

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. تست **table-driven** با اسلایس کیس‌ها بنویسید
2. از `t.Run` برای زیر‌تست نام‌دار استفاده کنید
3. با `t.Helper` و `t.Fatalf` خوانایی را بهتر کنید
4. یک `BenchmarkXxx` ساده بنویسید و با `go test -bench` اجرا کنید

## چرا این مطلب مهم است
تست‌های تکراری با کپی‌پیست می‌شکنند. جدول کیس‌ها رفتار مرزی را ارزان پوشش می‌دهد؛ benchmark از بهینه‌سازی خیالی جلوگیری می‌کند.

## مفهوم اصلی

```go
func TestAbs(t *testing.T) {
	cases := []struct {
		name string
		in   int
		want int
	}{
		{"pos", 2, 2},
		{"neg", -2, 2},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			if got := Abs(tc.in); got != tc.want {
				t.Fatalf("got %d want %d", got, tc.want)
			}
		})
	}
}
```

Benchmark:
```go
func BenchmarkAbs(b *testing.B) {
	for i := 0; i < b.N; i++ {
		_ = Abs(-1)
	}
}
```

## اشتباهات رایج
1. **اشتراک state بین ساب‌تست‌ها بدون ایزوله**
2. **فراموش `t.Run` و خواندن سخت لاگ fail**
3. **بهینه‌سازی زودهنگام بدون benchmark**

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-13-testing/examples
go test .
go test -bench=. -benchmem .
```

فایل‌های `abs.go` و `abs_test.go` در examples.

## نسخهٔ بهتر / الگوی درست
نام کیس‌ها توصیفی؛ برای خطا از مقایسهٔ `errors.Is`؛ برای خروجی بزرگ از `cmp` یا تست طلایی در مراحل بعد.

## تمرین عملی

### آسان
برای تابع `Max(a,b int) int` سه کیس table-driven بنویسید.

### چالش
Benchmark برای `Max` بنویسید و یک‌بار با `-bench` اجرا کنید؛ عدد `ns/op` را تفسیر کنید (کمتر = سریع‌تر در این معیار خام).

## راهنمای راه‌حل (چالش)
حلقه روی `b.N`؛ از بهینه شدن دور نزنید با ذخیره در متغیر سراسری یا `_ =`.
