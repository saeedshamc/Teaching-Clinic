# جلسه ۱۹: gofmt، go vet و lint مفهومی (۶۰ دقیقه)

**محیط فرض:** Go 1.22+

## پیش‌نیاز
- جلسات ۰۱ تا ۱۸

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. کد را با `gofmt` / `go fmt` یکدست کنید
2. با `go vet` مشکلات مشکوک را ببینید
3. نقش linterهای خارجی (مثل staticcheck) را مفهومی بگویید
4. فرمت را به عادت قبل از commit تبدیل کنید

## چرا این مطلب مهم است
در Go بحث استایل تا حد زیادی با `gofmt` تمام شده؛ PRها کمتر روی فاصله و براکت می‌جنگند و بیشتر روی طراحی.

## مفهوم اصلی

```bash
gofmt -w .
go vet ./...
```

`vet` تحلیل ایستا سبک خودِ toolchain است (مثلاً printf اشتباه). Linterهای خارجی قوانین بیشتری دارند ولی باید نسخه و CI را ثابت کنید.

## اشتباهات رایج
1. **فرمت نکردن قبل از review**
2. **نادیده گرفتن vet در CI**
3. **فعال کردن ۲۰ linter ناسازگار بدون اجماع تیم**

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-19-tooling/examples
gofmt -w .
go vet .
go run .
```

## نسخهٔ بهتر / الگوی درست
در ادیتور format-on-save با gofmt/goimports؛ در CI همان ابزارها.

## تمرین عملی

### آسان
یک فایل عمداً بدفرمت کنید و با `gofmt -w` درستش کنید.

### چالش
عمداً `fmt.Printf("%s", 12)` بنویسید و ببینید `go vet` چه می‌گوید؛ بعد درستش کنید.

## راهنمای راه‌حل (چالش)
