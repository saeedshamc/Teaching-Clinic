# جلسه ۰۲: اولین برنامه، package و go run/build/test (۹۰ دقیقه)

**محیط فرض:** Go 1.22+ · ماژول فعال (جلسه ۰۱)

## پیش‌نیاز
- جلسه ۰۱ (نصب Go و مفهوم Module)

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. یک پکیج `main` با تابع `main` بنویسید و اجرا کنید
2. تفاوت **package** نام‌دار با `package main` را توضیح دهید
3. `go run`، `go build` و `go test` را به‌جا استفاده کنید
4. یک تست خیلی ساده با `TestXxx` بنویسید و سبز کنید

## چرا این مطلب مهم است
در Go مرز کامپایل و تحویل، **پکیج** است نه «یک فایل جادویی». اگر `main` و تست و build را قاطی کنید، یا باینری نمی‌سازید یا تست‌ها اصلاً اجرا نمی‌شوند.

## مفهوم اصلی

### package و entry point
هر فایل `.go` با `package نام` شروع می‌شود. برنامهٔ اجرایی باید `package main` و تابع `func main()` داشته باشد. پکیج‌های دیگر کتابخانه‌اند و `main` ندارند.

### سه فرمان روزمره

| فرمان | کار |
|--------|-----|
| `go run .` | کامپایل موقت + اجرا (مناسب یادگیری) |
| `go build -o app.exe .` | ساخت باینری پایدار |
| `go test .` | اجرای تست‌های `_test.go` در پکیج جاری |

نام فایل تست باید به `_test.go` ختم شود و توابع تست به شکل `func TestSomething(t *testing.T)`.

## اشتباهات رایج
1. **نوشتن `package main` در کتابخانهٔ قابل import** — مصرف‌کننده نمی‌تواند آن را import کند.
2. **اجرای `go test` روی فایلی که `main` و تست را قاطی کرده بدون درک پکیج** — تست و باینری قوانین متفاوتی دارند؛ برای تمرین، مثال و تست را در یک پکیج `main` ساده نگه می‌داریم.
3. **فراموش کردن `import "testing"` در فایل تست** — کامپایل تست fail می‌شود.

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-02-first-program/examples
go run .
go test .
go build -o hello.exe .
```

`main.go`:

```go
package main

import "fmt"

func Greet(name string) string {
	return "سلام، " + name
}

func main() {
	fmt.Println(Greet("Go"))
}
```

`main_test.go`:

```go
package main

import "testing"

func TestGreet(t *testing.T) {
	got := Greet("Sara")
	want := "سلام، Sara"
	if got != want {
		t.Fatalf("got %q want %q", got, want)
	}
}
```

## نسخهٔ بهتر / الگوی درست
منطق قابل تست (`Greet`) را از `main` جدا کنید تا `go test` بدون اجرای برنامه، رفتار را قفل کند. `main` فقط wiring باشد.

## تمرین عملی

### آسان
تابع `Add(a, b int) int` بنویسید و در `main` چاپ کنید؛ یک `TestAdd` برای `2+3=5` بنویسید.

### چالش
تابع `Greet` را طوری تغییر دهید که اگر `name` خالی بود `"سلام، مهمان"` برگرداند و تست جدا برای هر دو حالت بنویسید.

## راهنمای راه‌حل (چالش)
1. در ابتدای `Greet` با `if name == ""` شاخه بزنید.
2. دو تست: `TestGreetNamed` و `TestGreetEmpty` (یا table-driven ساده).
3. `go test .` باید بدون fail تمام شود.

## خودآزمایی
- [ ] می‌دانم چرا برنامه به `package main` نیاز دارد
- [ ] تفاوت `go run` و `go build` را می‌گویم
- [ ] می‌توانم یک `TestXxx` بنویسم
- [ ] نام فایل تست را رعایت می‌کنم
- [ ] منطق را از `main` جدا می‌کنم تا قابل تست باشد
- [ ] اگر تست fail شود پیام `t.Fatalf` را می‌خوانم

## جمع‌بندی + پل به جلسه بعد
الان چرخهٔ نوشتن → اجرا → تست را دارید. جلسهٔ بعد انواع پایه، متغیر، ثابت و تبدیل نوع را دقیق می‌کنیم.
