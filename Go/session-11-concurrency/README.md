# جلسه ۱۱: goroutine، channel، select و خطر race (۱۲۰ دقیقه)

**محیط فرض:** Go 1.22+ · برای تشخیص رقابت: `go run -race .`

## پیش‌نیاز
- جلسات ۰۱ تا ۱۰

## اهداف یادگیری
پس از این جلسه می‌توانید:
1. با `go f()` یک **goroutine** سبک راه بیندازید
2. با channel بدون بافر / با بافر داده رد و بدل کنید
3. با `select` بین چند کانال انتخاب کنید
4. خطر **data race** روی متغیر مشترک را بشناسید و با کانال یا mutex درست کنید

## چرا این مطلب مهم است
قدرت Go در concurrency است؛ اما race باگ‌هایی می‌سازد که فقط گاه‌گاه می‌ترکند. بدون `-race` و مدل ذهنی مالکیت داده، سرویس شکننده می‌شود.

## مفهوم اصلی

```go
ch := make(chan int)
go func() { ch <- 1 }()
v := <-ch

select {
case v := <-ch:
    _ = v
case <-time.After(time.Second):
    // timeout
}
```

قانون طلایی: «حافظه را با ارتباط به اشتراک بگذارید، نه ارتباط را با حافظهٔ بی‌قفل.»

## اشتباهات رایج
1. **نوشتن همزمان در map/slice از چند goroutine بدون همگام‌سازی**
2. **فراموش کردن close یا گیر کردن روی ارسال به کانال بدون شنونده**
3. **راه‌اندازی هزار goroutine بدون محدودیت و لغو (context در جلسه بعد)**

## مثال آموزشی قدم‌به‌قدم

```bash
cd session-11-concurrency/examples
go run .
go run -race .
```

```go
package main

import "fmt"

func main() {
	ch := make(chan string, 1)
	go func() {
		ch <- "آماده"
	}()
	fmt.Println(<-ch)
}
```

## نسخهٔ بهتر / الگوی درست
مالکیت داده را به یک goroutine بدهید؛ بقیه پیام بفرستند. برای شمارندهٔ مشترک ساده، `sync/atomic` یا کانال نتایج.

## تمرین عملی

### آسان
دو goroutine هر کدام یک پیام به کانال بفرستند؛ main دو پیام را بخواند و چاپ کند.

### چالش
عمداً یک race روی متغیر `int` بسازید، با `-race` ببینید، بعد با کانال یا `mutex` درستش کنید.

## راهنمای راه‌حل (چالش)
نسخهٔ خراب: دو goroutine `n++` روی یک متغیر. نسخهٔ درست: هر کدام نتیجه را به کانال بفرستند و main جمع کند.

## خودآزمایی
- [ ] `go` را بلدم
- [ ] تفاوت کانال بافر دار و بدون بافر را می‌گویم
- [ ] `select` را در حد timeout بلدم
- [ ] `-race` را اجرا می‌کنم
- [ ] map مشترک بدون قفل نمی‌نویسم
- [ ] می‌دانم deadlock یعنی چه

## جمع‌بندی + پل به جلسه بعد
concurrency بدون لغو کامل نیست. جلسهٔ بعد **context** برای deadline، cancel و حمل مقدار درخواست.
