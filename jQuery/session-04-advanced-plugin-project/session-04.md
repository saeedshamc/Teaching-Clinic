# جلسه ۴ — پلاگین‌نویسی، بهینه‌سازی عملکرد، معماری و پروژه نهایی

## بخش اول: نوشتن پلاگین jQuery

### ۱.۱ چرا پلاگین؟

وقتی یک قطعه رفتار (مثلاً یک Tooltip، یک Tab، یک Slider ساده) را بارها در پروژه‌های مختلف نیاز دارید، منطقی است آن را به‌شکل یک متد قابل استفاده مجدد روی `$.fn` (پروتوتایپ jQuery) اضافه کنید تا مثل متدهای داخلی (`.fadeIn()`, `.addClass()`) صدا زده شود.

### ۱.۲ الگوی رسمی پلاگین (IIFE + Closure)

```javascript
(function ($) {
  'use strict';

  $.fn.highlightText = function (options) {
    // تنظیمات پیش‌فرض که با ورودی کاربر ترکیب می‌شوند
    var settings = $.extend({
      color: 'yellow',
      duration: 500
    }, options);

    // این حلقه به pluginها اجازه می‌دهد روی چندین المان انتخاب‌شده کار کنند
    // و chain-پذیر بمانند (بسیار مهم!)
    return this.each(function () {
      var $el = $(this);
      var original = $el.css('background-color');
      $el.css('background-color', settings.color);
      setTimeout(function () {
        $el.css('background-color', original);
      }, settings.duration);
    });
  };

})(jQuery);

// استفاده:
$('.important-text').highlightText({ color: '#ffef99', duration: 800 });
```

نکات کلیدی این الگو:

1. **IIFE** — `(function($){ ... })(jQuery)` تضمین می‌کند که داخل پلاگین شما، `$` همیشه دقیقاً به `jQuery` اشاره دارد، حتی اگر بیرون از این تابع کتابخانه دیگری `$` را بازتعریف کرده باشد (سازگاری با `noConflict`).
2. **`return this.each(...)`** — تضمین می‌کند پلاگین شما هم روی چند المان هم‌زمان کار کند و هم قابلیت Chaining حفظ شود (چون `each` خودِ `this` — یعنی شیء jQuery — را برمی‌گرداند).
3. **`$.extend(defaults, options)`** — الگوی استاندارد برای تنظیمات پیش‌فرض قابل بازنویسی توسط کاربر پلاگین.

### ۱.۳ `$.extend` در برابر `$.fn.extend`

```javascript
// $.extend: ادغام آبجکت‌ها (یا افزودن متد سراسری/utility به خودِ $)
var merged = $.extend({}, defaults, userOptions); // آبجکت جدید، defaults تغییر نمی‌کند
$.extend($, { myUtilFunction: function () { ... } }); // اضافه‌کردن تابع utility سراسری: $.myUtilFunction()

// $.fn.extend: افزودن یک یا چند متد جدید به همه اشیاء jQuery (روی المان‌ها)
$.fn.extend({
  myMethod1: function () { return this.each(function () { ... }); },
  myMethod2: function () { return this.each(function () { ... }); }
});
```

### ۱.۴ رویدادهای سفارشی (Custom Events)

پلاگین‌های حرفه‌ای معمولاً رویداد سفارشی هم "پرتاب" می‌کنند تا کد بیرونی بتواند به اتفاقات پلاگین واکنش نشان دهد، بدون اینکه پلاگین را دستکاری کند:

```javascript
$.fn.myCarousel = function () {
  return this.each(function () {
    var $el = $(this);
    // ... منطق کاروسل ...

    // وقتی اسلاید عوض شد، یک رویداد سفارشی پرتاب کن:
    $el.trigger('slideChanged', [currentIndex]);
  });
};

// کد مصرف‌کننده پلاگین می‌تواند گوش بدهد:
$('#myCarousel').on('slideChanged', function (event, index) {
  console.log('اسلاید فعلی: ' + index);
});
```

`.trigger(name, extraData)` رویداد را شبیه‌سازی می‌کند؛ `extraData` آرایه‌ای از پارامترهای اضافه است که بعد از `event` به هندلر پاس داده می‌شود.

## بخش دوم: بهینه‌سازی عملکرد (Performance)

### ۲.۱ کش‌کردن سلکتور (یادآوری و تعمیق)

```javascript
// ❌
for (var i = 0; i < 100; i++) {
  $('#list').append('<li>' + i + '</li>'); // ۱۰۰ بار reflow/repaint احتمالی
}

// ✅ ساخت رشته HTML یکجا و افزودن یک‌باره (خیلی سریع‌تر)
var html = '';
for (var i = 0; i < 100; i++) {
  html += '<li>' + i + '</li>';
}
$('#list').append(html); // فقط یک بار DOM دستکاری می‌شود
```

### ۲.۲ استفاده از `detach()` هنگام دستکاری سنگین

اگر می‌خواهید تغییرات زیادی روی یک بخش از DOM بدهید، بهتر است ابتدا آن را از صفحه جدا کنید (که دیگر باعث reflow نشود)، تغییرات را اعمال کنید، سپس دوباره بچسبانید:

```javascript
var $list = $('#bigList');
var $parent = $list.parent();
$list.detach(); // خارج از DOM => تغییرات رویش دیگر باعث reflow صفحه نمی‌شود

// ... خیلی تغییر و append و... روی $list ...

$parent.append($list); // یک‌بار برگرداندن به DOM
```

### ۲.۳ Event Delegation برای کاهش تعداد Listener ها

به‌جای وصل‌کردن رویداد به ۱۰۰۰ ردیف جدول، یک رویداد روی خودِ جدول وصل کنید (جلسه ۲) — هم برای المان‌های پویا لازم است، هم مصرف حافظه را به‌شدت کاهش می‌دهد.

### ۲.۴ سلکتورهای سریع‌تر

```javascript
$('#id')          // سریع‌ترین — مرورگر مستقیم getElementById صدا می‌زند
$('.class')          // سریع
$('tag')                // نسبتاً سریع
$('[data-attr=x]')          // کندتر — باید کل DOM پیمایش شود
$('div:contains("x")')        // کندترین دسته — سلکتورهای اختصاصی jQuery
```

قاعده: سلکتورهای پیچیده را از راست به چپ بخوانید — مرورگر ابتدا آخرین بخش سلکتور را پیدا می‌کند و سپس فیلتر می‌کند، پس سلکتورهای بلند و مبهم (`div ul li a span`) کندتر از سلکتورهای مشخص (`#specific-id`) هستند.

### ۲.۵ Debounce برای رویدادهای پرتکرار

رویدادهایی مثل `scroll`, `resize`, `input` می‌توانند صدها بار در ثانیه اجرا شوند. برای جلوگیری از افت عملکرد:

```javascript
function debounce(fn, delay) {
  var timer = null;
  return function () {
    var context = this, args = arguments;
    clearTimeout(timer);
    timer = setTimeout(function () {
      fn.apply(context, args);
    }, delay);
  };
}

$(window).on('resize', debounce(function () {
  console.log('حالا واقعاً کاربر تغییر اندازه را تمام کرده: ' + $(window).width());
}, 300));
```

jQuery خودش تابع debounce ندارد؛ این یک الگوی جاوااسکریپت خالص است که بسیار در کنار jQuery استفاده می‌شود.

## بخش سوم: jQuery در دنیای مدرن

### ۳.۱ مقایسه با Vanilla JS امروزی

بسیاری از قابلیت‌هایی که روزی فقط jQuery داشت، امروز مستقیم در جاوااسکریپت استاندارد وجود دارد:

| نیاز | jQuery | Vanilla JS مدرن |
|---|---|---|
| انتخاب المان | `$('.x')` | `document.querySelectorAll('.x')` |
| رویداد | `.on('click', fn)` | `.addEventListener('click', fn)` |
| Ajax | `$.ajax()` | `fetch()` |
| افزودن کلاس | `.addClass()` | `.classList.add()` |
| انیمیشن | `.animate()` | CSS Transitions/Animations یا Web Animations API |

**نتیجه‌گیری واقع‌بینانه**: برای پروژه‌های جدید و کوچک، اغلب Vanilla JS کافی و حتی سریع‌تر است (چون نیازی به دانلود کتابخانه ندارد). jQuery همچنان در نگهداری پروژه‌های legacy، پلاگین‌های WordPress، و مواقعی که سرعت توسعه بر بهینگی نهایی اولویت دارد، بسیار کاربردی است.

### ۳.۲ jQuery و فریم‌ورک‌های مدرن (React/Vue/Angular)

اصولاً **نباید** jQuery را مستقیماً داخل کامپوننت‌های React/Vue استفاده کرد، چون این فریم‌ورک‌ها خودشان DOM را مدیریت می‌کنند (Virtual DOM) و دستکاری مستقیم DOM توسط jQuery باعث ناهماهنگی (Out-of-sync state) می‌شود. اگر پروژه‌ای React است، معادل‌های خودِ اکوسیستم React (state, refs, کتابخانه‌های انیمیشن React) باید استفاده شوند.

## بخش چهارم: پروژه نهایی — To-Do List با شبیه‌سازی Ajax

در فایل `code/index.html` این جلسه، یک پروژه کوچک جمع‌بندی پیاده‌سازی شده که همه مفاهیم چهار جلسه را ترکیب می‌کند:

- **جلسه ۱**: سلکتورها، `.val()`, `.text()`, `.addClass()`
- **جلسه ۲**: Event Delegation برای آیتم‌های پویا، افکت‌های `fadeIn`/`slideUp`
- **جلسه ۳**: ساخت/حذف/پیمایش المان، `closest()`، Ajax شبیه‌سازی‌شده با `$.Deferred` برای «ذخیره در سرور»
- **جلسه ۴**: یک پلاگین کوچک سفارشی (`$.fn.toastNotify`) برای نمایش پیام موفقیت، و debounce روی جستجوی زنده لیست

ساختار پروژه:

1. کاربر یک کار جدید تایپ و اضافه می‌کند → با انیمیشن `slideDown` وارد لیست می‌شود.
2. کلیک روی هر آیتم آن را «انجام‌شده» علامت می‌زند (با Event Delegation).
3. دکمه حذف هر آیتم (با `closest`) آن آیتم را با `fadeOut` حذف می‌کند.
4. یک دکمه «ذخیره در سرور» یک Ajax شبیه‌سازی‌شده صدا می‌زند که بعد از تاخیر مصنوعی موفق/ناموفق می‌شود.
5. یک باکس جستجو با debounce، لیست را زنده فیلتر می‌کند.
6. با موفقیت هر عملیات، پلاگین سفارشی `toastNotify` یک پیام کوچک گوشه صفحه نشان می‌دهد.

## ۵. تله‌های رایج در پلاگین‌نویسی و بهینه‌سازی

1. **فراموش‌کردن `return this.each(...)`** در پلاگین → Chaining شکسته می‌شود و پلاگین فقط روی اولین المان کار می‌کند.
2. **تغییر مستقیم آبجکت `defaults`** به‌جای استفاده از `$.extend({}, defaults, options)` → تنظیمات پیش‌فرض پلاگین بین چند بار استفاده «آلوده» می‌شود.
3. **append کردن در حلقه** به‌جای ساخت رشته HTML و append یکجا → کندی محسوس در لیست‌های بزرگ.
4. **استفاده مستقیم jQuery داخل کامپوننت React/Vue** → تداخل با Virtual DOM و باگ‌های عجیب.
5. **گوش‌ندادن به رویداد resize/scroll با debounce** → افت شدید FPS و لگ محسوس صفحه.

## ۶. تمرین‌های پیشنهادی نهایی

1. پلاگین `highlightText` بالا را طوری تغییر دهید که یک رویداد سفارشی `highlighted` هم پرتاب کند و کد بیرونی بتواند آن را بشنود.
2. در پروژه To-Do، یک فیلتر «فقط انجام‌نشده‌ها / فقط انجام‌شده‌ها / همه» اضافه کنید.
3. تابع debounce را به throttle تبدیل کنید (throttle حداکثر یک‌بار در هر بازه زمانی اجرا می‌شود، برخلاف debounce که صبر می‌کند فعالیت متوقف شود) و تفاوت رفتاری‌شان را روی رویداد `scroll` مشاهده کنید.
4. با `console.time()`/`console.timeEnd()` سرعت append در حلقه را در برابر append یکجا با رشته HTML روی ۱۰۰۰ آیتم مقایسه کنید.

با پایان این ۴ جلسه، شما اکنون:

- مبانی سلکتورها و DOM را عمیقاً می‌دانید (جلسه ۱)
- مدل رویداد، Delegation و انیمیشن‌ها را حرفه‌ای مدیریت می‌کنید (جلسه ۲)
- پیمایش پیشرفته DOM و Ajax واقعی (همراه با Deferred/Promise) را بلدید (جلسه ۳)
- توانایی نوشتن پلاگین‌های قابل استفاده مجدد و بهینه‌سازی عملکرد پروژه‌های واقعی را دارید (جلسه ۴)
