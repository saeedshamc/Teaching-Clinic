# جلسه ۰۴: Volume و bind mount (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · [SETUP.md](../SETUP.md)

## پیش‌نیازها
جلسات ۰۱–۰۳.

## اهداف قابل‌اندازه‌گیری
1. بگویید چرا فایل داخل container با `rm` کانتینر معمولاً از بین می‌رود
2. volume نام‌دار بسازید و به مسیر داخل کانتینر وصل کنید
3. تفاوت volume و bind mount را توضیح دهید
4. خطر overwrite مسیر میزبان با bind را بشناسید

## چرا مهم است؟
دیتابیس و آپلود کاربر بدون volume دوام نمی‌آورند.

## مفهوم عمیق
- **لایهٔ writable کانتینر:** موقتی؛ با حذف کانتینر می‌رود (مگر volume).
- **named volume:** توسط Docker مدیریت می‌شود؛ مناسب دادهٔ پایدار.
- **bind mount:** پوشهٔ واقعی میزبان را سوار می‌کند؛ مناسب کد در حال توسعه.
- روی ویندوز مسیر bind معمولاً از طریق Desktop/WSL ترجمه می‌شود.

## اشتباه‌های رایج
1. انتظار ماندگاری داده بدون volume.
2. bind روی مسیر اشتباه میزبان و پاک شدن ناخواستهٔ فایل‌ها.
3. قاطی کردن `-v name:/data` با `-v C:\path:/data`.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-04-volumes/examples/01-named-volume.ps1
```

## الگوی بهتر
دادهٔ مهم → named volume؛ کد در حال توسعه → bind mount آگاهانه.

## تمرین‌ها
### آسان
یک named volume بسازید و `docker volume ls` را ببینید.
### چالشی
دو بار container جدا با همان volume اجرا کنید و ثابت کنید فایل باقی مانده است.

## راهنمای حل
اسکریپت فایلی در volume می‌نویسد، کانتینر را حذف می‌کند، کانتینر جدید همان فایل را می‌خواند.

## خودآزمایی
1. چرا بدون volume داده از بین می‌رود؟
2. named volume چیست؟
3. bind mount چیست؟
4. یک خطر bind را نام ببرید.
5. `docker volume ls` چه می‌کند؟

## جمع‌بندی و پل جلسهٔ بعد
ماندگاری. جلسه بعد: شبکهٔ bridge و نام سرویس.
