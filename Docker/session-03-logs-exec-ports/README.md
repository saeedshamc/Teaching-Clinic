# جلسه ۰۳: لاگ، exec و پورت (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · [SETUP.md](../SETUP.md)

## پیش‌نیازها
جلسات ۰۱–۰۲.

## اهداف قابل‌اندازه‌گیری
1. لاگ یک container را با `docker logs` بخوانید
2. با `docker exec` داخل container دستور بزنید
3. معنی `-it` را بگویید
4. با `-p` یک پورت را به میزبان map کنید

## چرا مهم است؟
بدون لاگ و exec، دیباگ سرویس‌های کانتینری کور است.

## مفهوم عمیق
- **stdout/stderr کانتینر** → `docker logs`
- **exec:** پروسهٔ جدید داخل همان namespace کانتینر در حال اجرا
- **`-p HOST:CONTAINER`:** ترافیک میزبان به پورت داخل کانتینر
- **`-it`:** ترمینال تعاملی (برای shell)

## اشتباه‌های رایج
1. `exec` روی container متوقف.
2. قاطی کردن پورت میزبان و پورت داخلی.
3. باز کردن `-p 80:80` وقتی پورت 80 میزبان اشغال است.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-03-logs-exec-ports/examples/01-nginx-port.ps1
```

سپس در مرورگر: `http://localhost:8080`

## الگوی بهتر
برای دموی محلی از پورت‌های بالا مثل `8080` استفاده کنید تا با سرویس‌های سیستم برخورد نکند.

## تمرین‌ها
### آسان
لاگ container دمو را با `docker logs` ببینید.
### چالشی
با `exec` داخل nginx یک `ls /usr/share/nginx/html` بزنید.

## راهنمای حل
اسکریپت nginx:alpine را روی 8080 بالا می‌آورد، لاگ می‌گیرد، exec می‌زند و پاک می‌کند.

## خودآزمایی
1. `logs` چه چیزی را نشان می‌دهد؟
2. `exec` با `run` چه فرقی دارد؟
3. `-p 8080:80` یعنی چه؟
4. چرا `-it` برای shell لازم است؟
5. اگر پورت اشغال باشد چه کنید؟
