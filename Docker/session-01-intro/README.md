# جلسه ۰۱: کانتینر در برابر VM و نصب (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · جزئیات در [SETUP.md](../SETUP.md)

## پیش‌نیازها
ترمینال/PowerShell پایه.

## اهداف قابل‌اندازه‌گیری
1. تفاوت کانتینر و ماشین مجازی را در یک جمله بگویید
2. `docker version` و `docker info` را اجرا و بخوانید
3. نقش daemon را توضیح دهید
4. بگویید چرا این دوره اپ‌های Clinic را دست نمی‌زند

## چرا مهم است؟
بدون مدل ذهنی درست، Docker فقط چند دستور حفظی می‌شود و عیب‌یابی غیرممکن است.

## مفهوم عمیق
- **VM:** سیستم‌عامل مهمان کامل + هایپروایزر (سنگین‌تر).
- **کانتینر:** پروسهٔ ایزوله‌شده روی کرنل میزبان؛ سریع‌تر و سبک‌تر.
- **Image:** قالب فقط‌خواندنی.
- **Container:** نمونهٔ در حال اجرا (یا متوقف) از image.

CLI با **daemon** حرف می‌زند؛ اگر Desktop خاموش باشد، دستورات شکست می‌خورند.

## اشتباه‌های رایج
1. فکر کردن که کانتینر = VM کامل.
2. نصب Docker بدون روشن کردن Desktop/daemon.
3. تمرین مخرب روی اپ production یا ریپوی Clinic.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-01-intro/examples/01-check-docker.ps1
```

## الگوی بهتر
قبل از هر دستور سنگین: `docker info` تا مطمئن شوید daemon زنده است.

## تمرین‌ها
### آسان
`docker version` را اجرا کنید.
### چالشی
سه تفاوت کانتینر و VM را بنویسید.

## راهنمای حل
کانتینر کرنل را share می‌کند؛ VM سیستم‌عامل جدا دارد. اسکریپت نسخه و وضعیت daemon را چاپ می‌کند.

## خودآزمایی
1. کانتینر چیست؟
2. image چیست؟
3. daemon چه نقشی دارد؟
4. چرا `docker info` مهم است؟
5. قانون دست‌نزدن به اپ Clinic چیست؟
6. `docker compose` با فاصله یعنی چه؟

## جمع‌بندی و پل جلسهٔ بعد
مدل ذهنی و نصب. جلسه بعد: چرخهٔ image/container با `pull` و `run`.
