# جلسه ۱۲: چند سرویس — وب + API آموزشی (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · [SETUP.md](../SETUP.md)

## پیش‌نیازها
جلسه ۱۱.

## اهداف قابل‌اندازه‌گیری
1. دو سرویس در Compose تعریف کنید (مثلاً `web` و `api`)
2. از یک سرویس سرویس دیگر را با **نام سرویس** صدا بزنید
3. فقط پورت لازم را به میزبان publish کنید
4. بگویید ارتباط داخلی روی شبکهٔ Compose است نه لزوماً localhost میزبان

## چرا مهم است؟
اپ واقعی چند پروسه دارد؛ الگوی نام‌محور پایهٔ همهٔ استک‌هاست.

## مفهوم عمیق
Compose برای پروژه یک شبکه می‌سازد. سرویس `api` از داخل `web` با host نام `api` قابل resolve است.

این مثال: nginx استاتیک + یک API خیلی کوچک با `node:alpine` که JSON برمی‌گرداند.

## اشتباه‌های رایج
1. صدا زدن `localhost` از داخل کانتینر برای رسیدن به سرویس دیگر.
2. publish کردن همهٔ پورت‌های داخلی به میزبان.
3. وابستگی سخت به IP به‌جای نام سرویس.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-12-compose-multiservice/examples/01-web-api.ps1
```

## الگوی بهتر
فقط edge (مثلاً وب روی 8080) را publish کنید؛ API داخلی بماند مگر برای دیباگ.

## تمرین‌ها
### آسان
`curl` به صفحهٔ وب روی میزبان.
### چالشی
از داخل کانتینر `web` به `http://api:3000` درخواست بزنید.

## راهنمای حل
اسکریپت up می‌کند، از میزبان و از داخل شبکه چک می‌کند، down می‌کند.

## خودآزمایی
1. چرا `localhost` داخل کانتینر غلط است؟
2. نام سرویس چه نقشی دارد؟
3. چه پورتی publish شود؟
4. دو سرویس حداقل برای چه سناریویی؟
5. `build` جدا برای هر سرویس؟

## جمع‌بندی و پل جلسهٔ بعد
چندسرویسی. جلسه بعد: depends_on، restart، volume در Compose.
