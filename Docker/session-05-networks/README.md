# جلسه ۰۵: شبکهٔ bridge پایه (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · [SETUP.md](../SETUP.md)

## پیش‌نیازها
جلسات ۰۱–۰۴.

## اهداف قابل‌اندازه‌گیری
1. یک شبکهٔ bridge بسازید
2. دو کانتینر را به همان شبکه وصل کنید
3. از یک کانتینر با **نام** کانتینر دیگر ping/ارتباط بگیرید
4. بگویید Swarm در این دوره نیست

## چرا مهم است؟
در Compose سرویس‌ها با نام همدیگر را پیدا می‌کنند؛ پایه همان شبکهٔ bridge است.

## مفهوم عمیق
- شبکهٔ پیش‌فرض `bridge` برای دمو کافی است؛ شبکهٔ user-defined DNS داخلی به نام کانتینر می‌دهد.
- کانتینر روی شبکهٔ جدا به نام هم دسترسی ندارد مگر متصل باشند.
- `-p` برای دسترسی از **میزبان** است؛ بین کانتینرها معمولاً پورت داخلی کافی است.

## اشتباه‌های رایج
1. انتظار resolve نام روی bridge پیش‌فرض قدیمی بدون شبکهٔ سفارشی.
2. باز کردن همهٔ پورت‌ها به میزبان برای ارتباط داخلی.
3. ورود به Swarm/Kubernetes قبل از تسلط بر bridge.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-05-networks/examples/01-bridge-dns.ps1
```

## الگوی بهتر
برای چند کانتینر مرتبط همیشه `docker network create` و `--network` یکسان.

## تمرین‌ها
### آسان
`docker network ls` را ببینید.
### چالشی
سومین کانتینر را به همان شبکه اضافه و با نام صدا بزنید.

## راهنمای حل
اسکریپت شبکه می‌سازد، دو alpine وصل می‌کند و با `ping` نام‌محور چک می‌کند.

## خودآزمایی
1. چرا شبکهٔ user-defined بهتر است؟
2. DNS نام کانتینر چه می‌کند؟
3. `-p` برای ارتباط داخلی لازم است؟
4. Swarm در این دوره؟
5. `docker network rm` چه پیش‌نیازی دارد؟

## جمع‌بندی و پل جلسهٔ بعد
شبکه. جلسه بعد: نوشتن Dockerfile.
