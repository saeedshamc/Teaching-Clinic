# جلسه ۱۱: Docker Compose پایه (۹۰ دقیقه)

**محیط فرض:** Docker Desktop / Engine · `docker compose` · [SETUP.md](../SETUP.md)

## پیش‌نیازها
جلسات ۰۱–۱۰.

## اهداف قابل‌اندازه‌گیری
1. یک `compose.yml` با یک سرویس `build` بنویسید
2. `docker compose up -d` و `down` را اجرا کنید
3. تفاوت Compose plugin با باینری قدیمی `docker-compose` را بگویید
4. وضعیت سرویس را با `docker compose ps` ببینید

## چرا مهم است؟
چند کانتینر + شبکه + volume با یک فایل توصیف می‌شود؛ استاندارد کار تیمی محلی.

## مفهوم عمیق
```yaml
services:
  web:
    build: ./app
    ports:
      - "8080:80"
```

Compose یک پروژه (نام پوشه) می‌سازد، شبکه پیش‌فرض می‌دهد و lifecycle را یکجا مدیریت می‌کند.

## اشتباه‌های رایج
1. استفاده از `version:` اجباری قدیمی بدون نیاز.
2. اجرای `up` از پوشهٔ اشتباه.
3. فراموش کردن `down` و گیر کردن پورت.

## مثال گام‌به‌گام
```powershell
powershell -File Docker/session-11-compose-basics/examples/01-compose-up.ps1
```

## الگوی بهتر
همیشه از ریشهٔ همان پوشهٔ `compose.yml` دستور بزنید؛ یا `-f` صریح.

## تمرین‌ها
### آسان
`compose ps` و `compose logs` را ببینید.
### چالشی
پورت را به `8081` عوض کنید و دوباره up کنید.

## راهنمای حل
یک سرویس nginx آموزشی با build محلی.

## خودآزمایی
1. `up -d` چیست؟
2. `down` چه پاک می‌کند؟
3. `build:` در برابر `image:`؟
4. نام پروژه از کجا می‌آید؟
5. چرا plugin مدرن ترجیح است؟

## جمع‌بندی و پل جلسهٔ بعد
Compose تک‌سرویسی. جلسه بعد: چند سرویس با هم.
