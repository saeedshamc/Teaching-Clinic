# جلسه 49: مقدمه Sass / SCSS (2 ساعت)

## اهداف یادگیری
- فهم نقش پیش‌پردازنده در کنار CSS
- نصب و اجرای Dart Sass
- تفاوت `.scss` و `.sass`
- گردش کار: نوشتن SCSS → کامپایل → `style.css`

---

## 1. چرا Sass؟

CSS خام تکرار، متغیر محدود (قبلاً)، و نبود ساختار ماژولار داشت. Sass امکان می‌دهد:

- متغیر و نقشه (map)
- تودرتویی خوانا
- mixin و function
- تقسیم فایل با `@use` / `@forward`

خروجی نهایی همان CSS است که مرورگر می‌فهمد.

---

## 2. نصب

با Node LTS:

```bash
npm install -D sass
npx sass main.scss style.css
npx sass --watch main.scss:style.css
```

یا سراسری: `npm install -g sass`

جزئیات محیط: [SETUP.md](../SETUP.md)

---

## 3. SCSS در برابر indented Sass

| | SCSS | Sass قدیمی |
|---|------|------------|
| پسوند | `.scss` | `.sass` |
| آکولاد/نقطه‌ویرگول | دارد (شبیه CSS) | ندارد |
| پیشنهاد این دوره | **SCSS** | فقط آشنایی |

---

## 4. اولین فایل

`main.scss`:

```scss
$brand: #c2410c;

.btn {
  background: $brand;
  color: #fff;
}
```

کامپایل → `style.css` که صفحه به آن لینک شده است.

---

## اشتباهات رایج
- ویرایش فقط `style.css` و از دست رفتن تغییرات بعد از کامپایل مجدد
- باز کردن پروژه Sass با `file://` وقتی بعداً ابزار بیلد دارید (برای این جلسه ساده، لینک مستقیم CSS خروجی کافی است)

---

## تمرین‌ها
### آسان
`$brand` را عوض کنید، دوباره کامپایل کنید، رنگ دکمه را ببینید.
### متوسط
یک متغیر `$radius` اضافه و روی دکمه اعمال کنید.
### چالش
`--watch` را روشن بگذارید و بدون کامپایل دستی تغییر را ببینید.

## خلاصه
Sass ابزار نویسنده است؛ مرورگر CSS کامپایل‌شده را اجرا می‌کند.
