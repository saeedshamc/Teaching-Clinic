# جلسه 43: ITCSS و لایه‌بندی فایل‌ها (2 ساعت)

## اهداف یادگیری
- فهم فلسفهٔ ITCSS (Inverted Triangle CSS)
- چیدن فایل‌ها از کم‌خصوصیت به زیاد
- کاهش جنگ specificity در پروژه‌های بزرگ

---

## 1. مثلث وارونه چیست؟

در ITCSS، لایه‌های پایین‌تر (عمومی) کم‌خصوصیت‌اند و لایه‌های بالاتر (مشخص) خصوصیت بیشتری دارند. استایل‌ها را از کلی به جزئی می‌نویسید تا بعداً مجبور به `!important` نشوید.

---

## 2. لایه‌های رایج

| لایه | نقش | مثال |
|------|-----|------|
| Settings | متغیرها / توکن‌ها | رنگ، فاصله |
| Tools | ابزار (معمولاً در Sass) | mixin |
| Generic | reset / normalize | `box-sizing` |
| Elements | تگ‌های خام | `h1`, `a` |
| Objects | اسکلت بی‌ظاهر | `.o-media` |
| Components | UI واقعی | `.card` |
| Utilities | کمک‌کننده‌های قوی | `.u-hidden` |

ترتیب import/لینک مهم است: اول Generic، آخر Utilities.

---

## 3. نمونهٔ ساختار پوشه

```
styles/
  settings/_tokens.css
  generic/_reset.css
  elements/_typography.css
  components/_card.css
  utilities/_helpers.css
  main.css   /* فقط @import یا لینک‌ها */
```

در CSS خالص می‌توانید چند فایل را به ترتیب در HTML لینک کنید؛ در Sass بعداً با `@use` مرتب‌تر می‌شود.

---

## اشتباهات رایج
- نوشتن کامپوننت قبل از base و بعد جنگیدن با margin پیش‌فرض
- utilityهای خیلی قوی در وسط پروژه که همه چیز را override می‌کنند بدون قرارداد
- یک فایل هزارخطی بدون لایه

---

## تمرین‌ها
### آسان
برای پروژه جلسه ۴۰، نام ۶ فایل لایه را روی کاغذ بنویسید.
### متوسط
`reset` و `card` را در دو فایل جدا فرض کنید و ترتیب لینک را مشخص کنید.
### چالش
یک کلاس utility مثل `.u-text-center` بسازید و فقط در لایه utilities نگه دارید.

## خلاصه
ITCSS نظم می‌دهد: از عمومی به خاص، با specificity کنترل‌شده.
